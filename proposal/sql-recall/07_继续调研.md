## 对选题的直接后果

「第一篇把自然语言编成商品硬过滤，再拿去检索」已经有人做过。还能写的句子更窄：

在公开商品库上，模型写出可执行 SQL，数据库返回候选，用留出交互或可核验属性打 Recall / NDCG，并单独报告约束满足、空结果和放松代价。全库协议下，这一格还没有被一篇已打开的论文占住。

不能写成的句子也更具体：

- 不能写「还没有人把自然语言商品请求编译成结构化过滤」。CIKM 2024 的过滤接口、HyST 的元数据过滤、MACS 的槽位到 SQL，都已经在做这件事。
- 不能写「还没有人让模型写出带向量占位符的 SQL，并用 Hit@1 打分」。ProRetrieval 在自建的 3,000 件商品集上做了。它打的是构造出来的单篇金文档，不是留出购买。
- 不能把 HyST 在 76 条查询、3,335 件商品上的 Precision@1 0.9211，当成打过 STaRK 官方全库 BM25（Hit@1 44.94，Recall@20 53.77）。池子和查询都换过。
- 不能写 LLM 生成的 SQL 召回已经是 SOTA，也不能把任何一篇的线上 A/B 挪成这篇的线上收益。

## 新核验

读过的范围写在每条后面。数字只引用打开文本里印出来的格子或作者自己的句子。

### 已经贴近「自然语言 → 可执行过滤 / SQL → 商品候选」

#### HyST

Jiyoon Myung、Jihyeon Park、Joohyung Han。arXiv:2508.18048，2025-08-25。打开的 arXiv 页没有会议名。读了方法、数据构造、表 2、表 3 和局限。

LLM 把自然语言拆成元数据过滤和剩下的语义查询。过滤是向量库的 JSON 条件（`$eq`、`$in`、`$lt`），然后在过滤后的候选上做向量检索。实验把 STaRK-Amazon 压成一张表，结构化列只用 brand 和 category，文本是 title、description、reviews 拼在一起。作者手选 76 条同时要结构和语义的查询，丢掉 `also_bought` / `also_viewed`，池子从一百万级收成 3,335 件。

表 2：HyST 的 Precision@1 / Precision@5 / Precision@10 / Recall@20 / MRR 是 0.9211 / 0.8349 / 0.8022 / 0.8063 / 0.9265。同表 BM25 是 0.8026 / 0.6053 / 0.5105 / 0.6960 / 0.8564，线性化语义检索是 0.8947 / 0.6947 / 0.5974 / 0.8019 / 0.9232。表 3：去掉查询精炼后，Precision@1 仍是 0.9211，Precision@5 升到 0.8586。作者写精炼有时会丢掉标题里已经出现的品牌。局限写明：颜色问句太少所以没评；数值范围、嵌套条件和「超过 100 条评论」都没测；76 条里见到 1 次幻觉属性 `DATA_TIMELINE`。他们把 Recall@20 的理由写成沿用 STaRK「相关答案都不超过 20」。这句在他们手选的 76 条上没有另作统计。仓库里对全量 9,100 条的核对是 2,720 条答案多于 20，不要把 HyST 的协议句当成全量文件的事实。

对这篇的用处：STaRK 上「先结构化过滤、再向量排序」已经有一篇预印本，而且作者自己把纯 SQL 路线写成盖不住评论语气。它没有占住官方全库、关系边和价格区间。主实验若仍用 STaRK，必须把 HyST 列为最近的公开对照，并写明池子是 3,335 而不是约 90 万。

#### ProRetrieval

Chengsong You 等。打开的是 arXiv HTML `2608.27017`，首页没有会议名，代码链接是匿名的。读了摘要、方法、第 4 节表 2 和表 3、局限。

模型生成一份混合程序：SQL 负责结构化字段上的与、或、非和嵌套，文本和图像检索以占位符插进 SQL（`id IN <text_0>`）。电商集由 Amazon ESCI 和 Amazon Reviews 拼成，3,000 件商品，字段有 brand、category、price、rating，外加标题、描述、评论和图像。20,000 条训练查询、3,000 条测试查询，按叶子数分成 L1–L3。金文档是构造流程先选定的一篇，奖励里的结果项是 rank-1 命中。报告指标是 Hit@1、Hit@3、MRR 和 NDCG@3；相关集是这一篇金文档，所以 NDCG 不是留出购买上的排序。

表 2 是 Qwen3-4B 的动作空间消融，电商，N=3,000：只 SQL 的 Hit@1 0.650、MRR 0.664、执行成功率 99.7%；SQL+文本 0.752；全 DSL 的 SFT 0.680；全 DSL 的 GRPO 0.809。摘要把 4B 相对 GPT-5.5 收成 0.81 对 0.69。正文另写 8B SFT 的电商 Hit@1 是 0.820，并且 8B 上继续跑 GRPO / DAPO 没有超过这格。表 3：SQL-R1 在结构化查询上 Hit@1 0.866，图像查询 0.048。局限写明：schema 预先给定，逻辑深度最多两层，语料是 3,000 件商品，单轮，没有用户序列。

对这篇的用处：这是目前打开过的文本里，最接近「模型写 SQL、执行器返回商品、用 Hit 打分」的一篇。金标准是模板构造的单篇文档，所以集合召回会受构造过程抬高，这和总览里对 STaRK 合成标签的警告是同一类。它自己的表说明只执行 SQL 低于 SQL 加文本。这篇不证明 SQL 召回打赢全部向量召回，也不证明留出购买上的收益。

#### MACS

Juli Huang、Hannah Clay、Thomas Sarda、Sajjad Beygi、Negin Golrezaei、Amin Saberi。打开的是 arXiv HTML `2608.14068`，首页没有会议名。读了摘要、问题定义和第 4–5 节。第 6 节的结果表没有逐格复核，下面的通过率沿用摘要里作者写的数字。

购物代理用 LLM 做改写、路由和槽位抽取。商户代理把槽位映射成 SQL `WHERE`，在固定目录上执行。目录是作者自己的 21,000 多件商品，其中 1,490 多台笔记本有 12 个规格字段：CPU、RAM、GPU、存储类型、屏幕、续航、重量、操作系统、价格、品牌、评论数、评分。相似和兼容走 Cypher。结果少于 3 条时按重要度丢掉可选规格；价格上限和品牌排除不放松；放松必须在回复里写明。摘要：140 条单轮上通过率 87.1%，品牌合规 1.000；10 个多轮场景的宏平均 Pass@5 是 72%，对照写的是 GPT+Catalog 56% 和 Gemini+Catalog 52%。质量分用 G-Eval，摘要写均值 0.751 对 0.736。没有公开全库 Recall 或 NDCG，也没有行为留出。

对这篇的用处：硬约束执行、品牌排除和按优先级放松，已经有一个对话电商系统。LLM 写的是槽位，SQL 是确定性映射，不是自由生成的多表 SQL。评测是小规模自建通过率。公开基准上的 Recall，以及「放松哪一条才算最小」，这篇没有占住。

#### CIKM 2024，自然语言到商品过滤接口

Vijit Malik、Vinayak Puranik、Anirban Majumder、Vivek Sembium。CIKM 2024，DOI [10.1145/3627673.3680070](https://doi.org/10.1145/3627673.3680070)。读了摘要、任务定义和实验设置。表里的内部测试集多以相对涨幅印出，绝对 Exact Match 没有从版面里抽成可引用的一格，这里不补。

任务是把商品搜索句变成过滤 API，例子是 “HP laptop 4g or more, under 1k” 对应品牌、内存和价格。LLM 用来造训练数据，上线模型是在伪标签上微调的多任务 schema 生成器。公开对照用 Amazon ESCI 里他们筛出的 268 条查询做人工过滤标注，平均每条 1.2 个过滤。文中写出的 ESCI Exact Match：FLAN-T5 端到端 56.34%。指标是过滤 schema 的 Exact Match 和 Micro-F1，以及延迟。没有候选召回，也没有 SQL。

对这篇的用处：电商搜索里「自然语言落到品牌、内存、价格」在 2024 年的档案会议上已经是过滤生成任务。主指标若改成 Exact Match，就是在跟这篇比。召回论文要另报执行后的候选集。

#### Pandey，领域自适应稠密检索

Mritunjay Pandey。预印本，打开的 PDF 首页日期是 2026-02-03，arXiv:2602.00899。没有会议页眉。读了摘要、主结果和局限第 6.2 节。

Amazon Reviews 2023 的 Fashion 子集，评论当查询、标题当文档，目录 826,402。微调双塔的 Recall@10 0.66、MRR@10 0.59，同图 BM25 的 Recall@10 是 0.26、零样本 0.42。INT8 的 p50 延迟 6.1 ms。局限节写了三句，都是作者自己的失败模式，不是另做的实验臂：semantic drift；entity confusion，例子是 “Nike running shoes” 召回 Adidas；attribute hallucination，例子是 “V-neck with gold buttons” 只保住 V-neck。补救写成混合打分，或检索后硬过滤，例子是 `Brand == 'Nike'`。文中没有这条过滤臂的 Recall。

对这篇的用处：背景里引用的 entity confusion 和 attribute hallucination，在这份预印本的局限节里确实有。它是单作者预印本，硬过滤没有测。可以把它当作稠密检索自己写出的失败类型，不能把它的 0.66 写成「稠密检索已经解决时尚召回」，也不能把未测的品牌过滤写成已知涨幅。

#### BEATS

Yung-Yu Shih、Shang-Yu Su、Tzu-I Ho、Dongzhe Wang、Yun-Nung Chen。SIGIR 2026。论文里的 ACM 引用行是 2026-07-20 至 24 日，墨尔本，DOI [10.1145/3805712.3808520](https://doi.org/10.1145/3805712.3808520)。读了任务定义和第 4.3 节的表。

乐天台湾的目录原来缺少属性模式。LLM 加人工校对生成属性，再把属性拼进商品文本，训练双塔。表：基线 Recall@10 / Recall@100 / NDCG@10 / MRR@10 是 66.6 / 83.8 / 49.2 / 44.5，加属性后是 70.4 / 86.8 / 52.0 / 46.9。作者写检索结构没变，涨幅来自文本里多了属性。

对这篇的用处：属性信息也可以写进稠密检索的文档，而不经过 SQL。SQL 臂要对照的失败，应是「列上有值、稠密检索仍违反该列」，不是「目录里根本没有这一列」。

#### RecoAtlas

Imad Aouali、Flavian Vasile、Clijo Jose、Otmane Sakhi、Alexandre Gilotte、Benjamin Heymann，Criteo。打开的是 arXiv HTML `2605.18805`，首页没有会议名。读了摘要、第 1–3 节和实验设置。主表数字没有逐格抄。

代理在大目录上搜，交回固定大小的商品集合加短解释。工具是相关性、互补和去重，各有语义版和行为对齐版，嵌入是 Qwen3-Embedding-0.6B。数据是 Amazon Reviews（Hou 等，2024）和 H&M 购买；Amazon 把至少四星当正例。用户按 70/15/15 切开。查询是生成的，金标准是行为参考集。指标把 SetHit@K 和 LLM 判断分开。作者写语义上说得通的报告，不一定对应行为上的集合效用；线上 A/B 仍是金标准，但不适合作为开放基准。相关工作点名 AgentRecBench 的 SQL 式历史工具，RecoAtlas 改用推荐工具，不提供候选短名单。四个环境的留出查询数是 1,960、339、771、1,960，合计 5,030。

对这篇的用处：Amazon 加 H&M、大目录、工具调用、集合级效用，已经有一个 2026 预印本基准。它的工具不是 SQL。若新基准仍用生成查询加行为参考集，要说明和 RecoAtlas 的差在硬约束执行，而不是「第一份购物代理基准」。

#### SQLForge

Yu Guo、Dong Jin、Shenghao Ye、Shuangwu Chen、Jian Yang、Xiaobin Tan。ACL 2025 Findings，页 8441–8452。打开了 Anthology PDF 的题录、摘要和相关工作中对 DAIL-SQL、DIN-SQL 的定位。

用合法 SQL 抽模板，换领域造库，再把 SQL 回译成问句，微调开放模型。摘要：SQLForge-LM 在 Spider 开发集执行准确率 85.7%，BIRD 开发集 59.8%。评测是 Spider、BIRD 和稳健性集。没有商品目录，没有 Recall。

对这篇的用处：它可以当商品 SQL 的合成配方。执行准确率仍不是主指标，这一条总览已经写过。Spider / BIRD 的库没有价格、库存和空结果放松。

#### 约束放松的概念前身

Dietmar Jannach、Johannes Liegl。打开的是作者主页上的 PDF，文件名是 `Conference_IEA_2006.pdf`。抽取文本的前两页没有再印年份和会议全称，所以年份只记到这个文件名。

推荐问题的过滤规则使结果为空时，合法放松是删掉一部分规则后至少剩一件商品。最小放松是：不存在更小的规则子集，删掉后仍然非空。算法把这件事写成基于模型的诊断，用 QuickXplain 找最小冲突，再用 hitting set。例子是相机表上的接口、价格、分辨率和品牌。文中没有 LLM，也没有把 SQL 执行结果当 top-K。

MACS 的放松是另一套：结果少于 3 条就按重要度丢可选规格，价格和品牌排除不动。两篇不要写成同一个算法。Jannach 与 Liegl 给的是「最小」的定义；MACS 给的是「有些约束不许放松」的产品规则。新方法若声称最小放松，要写出优化的是约束条数、优先级，还是被放开的商品集合有多大。

Amazon Reviews 2023 是目前最接近「行为日志 + 价格 + 品牌细节」的公开表。请求和金 SQL 仍然要构造。构造时不要让金候选等于 SQL 模板的逆运算，否则纯 SQL 的集合召回会被抬高。STaRK 合成集和 ProRetrieval 都是这个构造。

### 评测：会改协议的两篇

Teresa Zhang。RecSys 2026 短文，DOI [10.1145/3773078.3831829](https://doi.org/10.1145/3773078.3831829)，出版日期 2026-09-27。这次只打开了 ACM 摘要页，没有全文，作者数字下面都按摘要引用。

固定候选和各自召回会选出不同的第一名：十个基准实例里八个不一致。OTTO、Dressipi、Diginetica 在两种 K=20 锚点下仍不一致。作者写这是机制存在性，不是生产里的普遍率，并建议比较整条流水线时报告 own-candidate utility。

这和总览「不要用固定候选掩盖第一阶段」同向。摘要没有讨论 SQL。它不提供新的主指标，只加强必须报各自候选上的效用。

Balázs Hidasi、Ádám Tibor Czapp。RecSys 2023，DOI [10.1145/3604915.3608839](https://doi.org/10.1145/3604915.3608839)。读了 ACM HTML 的问题界定。四类缺陷是：数据与任务不配、在重度预处理的数据上作一般结论、时间泄漏、负采样。

对 SQL 召回多出来的约束是：候选若来自全表执行，排序指标就要在这个候选集上算；换成 1 个正例加随机负例，测的是另一件事。InteRecAgent 的排序表就是后一种。时间切分仍按 RelBench 那条：特征不能看到种子时间之后。

背景里的 *Offline evaluation options for recommender systems* 本轮没有重新打开，不追加结论。

## 只读到摘要或题录，不能当强实验结论

- K-RagRec。Shijie Wang、Wenqi Fan、Yue Feng、Shanru Lin、Xinyu Ma、Shuaiqiang Wang、Dawei Yin。arXiv:2501.02226，2025-01-04，v2 为 2025-05-28。读了摘要和贡献列表。检索的是商品知识图谱子图，再对齐进 LLM。摘要写做了实验，没有在本次摘抄里给出 Recall 或 NDCG。它是 KG-RAG 对照，不是 SQL 召回。实验表未逐格核对。
- *Joint Modeling and Optimization of Search and Recommendation*。Hamed Zamani、W. Bruce Croft。arXiv:1807.05631。读了摘要。联合损失同时训检索和推荐，摘要写商品数据上的初步结果。没有硬约束执行，没有 SQL。打开的 arXiv 页没有会议名。
- *Faceted search and retrieval based on semantically annotated product family ontology*。Soon Chong Johnson Lim、Ying Liu、Wing Bun Lee。DOI [10.1145/1506250.1506254](https://doi.org/10.1145/1506250.1506254)，页面出版日期 2009-02-09。只读了摘要。对象是产品族设计里的相机文档，用语义标注做分面检索。它说明分面和本体早于 LLM。摘要没有电商日志，也没有推荐指标。背景里把它放进「结构化产品检索」是范围上的前身，不是购物召回实验。
- GenFacet。Zhouwei Zhai、Min Yang、Jin Li，JD.com。打开的 HTML 自称 SIGIR 2026，但 DOI 和 ISBN 仍是占位符。只把它当未核验会议身份的文本。摘要写分面生成加查询改写，线上分面 CTR 相对 +42.0%，UCVR 相对 +2.0%。这是他们的线上数字，不是 SQL 候选生成，也不能写成这篇的线上收益。
- 背景名单中的法律文档 LLM-as-a-judge 论文，本轮没有打开。不升格，也不把它的法官一致性写成已核对。

## 新颖性：哪一格仍开着

[创新点总表](deep/06_创新点总表.md) 里「模型写出 SQL、数据库执行、再用留出的 Hit / Recall / NDCG 打分，STaRK 上还没有只执行 SQL 就打过 BM25」这句，今天要加三个旁注，格子本身还留着。

1. HyST 在 STaRK 的 76 条、3,335 件子集上做了过滤后向量检索，过滤语言是 JSON，关系边被删掉。官方全库的只执行 SQL 一臂仍没有。
2. ProRetrieval 在 3,000 件自建商品集上做了模型写 SQL，Hit@1 有数，金标准是单篇构造文档。留出交互上的推荐 Recall 仍没有。
3. MACS 和 CIKM 2024 占住的是槽位或过滤 schema。自由 SQL、多表连接和空结果的最小放松，在公开全库上仍没有 Recall 表。

因此 ACL 2027 的题目若保留「硬约束推荐召回的自然语言到 SQL 基准」，贡献句要写成协议和缺口，而不是「第一次做结构化商品过滤」。必须点名的近邻是 HyST、ProRetrieval、MACS、Malik 等 CIKM 2024，以及仓库里已有的 InteRecAgent、TalkPlay-Tools、SUQL。主表仍是各自候选上的召回，外加约束满足、空结果率和放松代价。稠密检索、KG 子图和购物代理是对照，不是等待被全面替换的对象。

离线协议证明的是可控数据上的候选质量和约束满足。它不证明线上长期收益。
