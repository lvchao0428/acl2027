>
> 「重稿」在本文分成两层，不混用。第一层是撞车：若按某个创新点再投一篇，审稿人会把它当成已有工作的重复，原因是哪一句已经被占住。第二层是投稿风险：这个方向若投 ACL 2027 主会，哪些句子会因为像已中稿工作的重写而被拒。笔记没有写某篇被某会议拒稿的，本文不写成拒稿。workshop、短文、Findings、未下到的档案版，只按笔记里的场合名称记录。

## 1. 结论

这个主体周围、笔记已经打开并写明场合的文章，进入下面第 2 节统计的有 90 篇。主会口径 27 篇：机器学习主会 8、NLP 主会 7、检索与数据库主会 10、推荐主会全文 2。非主会 15 篇：Findings 3、Datasets and Benchmarks 5、workshop 4、短文 3。由本仓库 PDF 页眉核对到的 position 是 0 篇。名单外的已写明场合 10 篇，期刊 3 篇。仅预印本 35 篇，不算中稿。另有 9 行笔记点了名，但会议未核验、全文未下，或只有算法名和榜名，不进入这 90。

ACL 主会长文在这 90 篇里是 3 篇：QUEST（ACL 2023，文件名 `acl-long`）、HybGRAG（ACL 2025 长文）、BLaIR / Amazon-C4（ACL 2026 长文）。三篇都没有占住下面这句。NAACL 主会长文是 BookSQL、H-STAR、FLEX，外加笔记未写成 Findings 或短文的 FollowIR。EMNLP 主会长文在这批笔记里没有；EComAgentBench 写的是 EMNLP 2026 Industry。

ACL 2027 主会还空着的是这一句，出处是 [继续调研](../07_继续调研.md) 的「对选题的直接后果」和「新颖性」，并与总览、五步网格、[window-05](reanalysis/window-05.md) 的选题对齐：在公开商品全库上，模型写出可执行 SQL，数据库返回候选，用留出交互或可核验属性打 Recall / NDCG，并单独报告约束满足、空结果和放松代价。落到主实验上，就是 STaRK-Amazon：模型只把已经落到关系上的片段写成 SQL，数据库返回关系超集，BM25 或小编码器在商品文档上排序，关系片段和整句分开报。五步网格写明，没有任何一篇是「只执行 Cypher 或 SQL、不再做向量或 BM25」并且在 STaRK-Amazon 上打过表 6 的 BM25。继续调研加了三个旁注，格子本身还留着：HyST 用的是 76 条、3,335 件上的 JSON 过滤；ProRetrieval 用的是 3,000 件自建集上、构造出来的单篇金文档；MACS 和 CIKM 2024 占住的是槽位或过滤 schema，不是公开全库上的自由 SQL 加 Recall 表。

再写就会被当成重稿的，主要是三块已经挤满的贡献，加上两块看起来空、一写成新系统就撞车的格子。

1. 只换领域、模板填槽、再报一个域内执行准确率，或者把拒答和可靠性分写成主创新。垂直领域那一路的全文检索不到 Recall、NDCG 或 Hit。OMOP 的 LoRA 已经把合成模板上的测试执行准确率做到 93.55。
2. 「还没有人把自然语言商品请求编译成结构化过滤」，以及「还没有人让模型写出带向量占位符的 SQL，并用 Hit@1 打分」。前一句撞 CIKM 2024 的过滤接口、HyST 和 MACS；后一句撞 ProRetrieval。
3. 无约束的下一个物品上，把自连接或语义 ID 再写成一篇召回论文。审稿人会把自连接叫成 SQL 版 ItemKNN。TIGER 一路占住的是生成下一个物品的 ID；Xu 等占住的是同一份 Beauty 上全量交叉熵 SASRec 的 NDCG@10 0.0597。这张「SQL 自连接对全量交叉熵 SASRec 或 EASE」的表，笔记写明这批 PDF 里没有，所以也不能写成已经输了。

手写的 H&M 共现是另一句容易写重的话：它是漏掉的经典基线，可以进实验节，不能进贡献列表。window-05 写，审稿人会把它叫成 SQL 版近邻。

## 3. 按创新点看重稿

格子用四档：已有；空着且值得做；空着但是假空；不该做。已有格写再投一篇会撞上谁、撞在哪一句。空着且值得做的格写它为什么还不算重稿，以及审稿人仍可能用哪句话把它打成增量。假空和不该做写明那就是重稿，或是投错了会议。

两张网格不一致的地方先钉住，后面每格只采用五步网格的档，并保留总表的原句。

- 硬属性过滤、工程师写死的 SQL。总表写已有：InteRecAgent 的工具限制和 TalkPlay 的布尔 SQL。五步网格写空着但是假空：STaRK 合成标签落在关系候选里，只执行关系模板是构造的逆运算，没有排序就没有第一名。两句都保留。再做一个通用的属性 WHERE 工具，撞的是 InteRecAgent。在 STaRK 合成集上只报模板 SQL 的集合召回，是假空，不是新实验。
- 带文本的半结构化检索、LLM 写 SQL 且数据库执行。总表写空着且值得做：STaRK 上没有只执行 SQL 或 Cypher 打过 BM25。五步网格把这一格标成已有 SUQL，紧接着写：STaRK 上「只把已经落到边上的片段写成 SQL，数据库返回关系超集，BM25 或小编码器在商品文档上排序」跨了两格，不被任何一个「已有」单独占住。继续调研没有把这格划掉，只禁止写成「第一次做结构化商品过滤」。
- 物品到物品共现、工程师写死的 SQL。总表写空着但可能是假空：写成 SQL 不构成新系统。五步网格写空着且值得做，身份是漏掉的基线。window-05 把两句收成实验节可以写、贡献列表不能写。
- 关系库上的未来窗口 top-K、工程师写死的 SQL。总表写历史访问和全局流行已有，共现自连接没人跑但不是新系统。五步网格把共现这一格标成空着且值得做，并限定为健全性检查。
- 约束满足、工程师写死的 SQL。总表写 TrustSQL 和 EHRSQL 已有。五步网格写空着但是假空：拒答主创新已经挤满，PCN-Rec 的校验也不是 SQL。

**无约束下一物品上的 SQL 自连接，无论工程师写还是模型写。** 自连接只等于 ItemKNN 或 Swing，写不出 EASE 和吃序列顺序的 SASRec。InteRecAgent 禁止用 SQL 找相似物品。这格不能当主表。再投 ACL，审稿人会叫它 SQL ItemKNN；再投推荐主会，Ferrari、Benigni 和 Xu 会要求打过调好的近邻和全量交叉熵，而这张表还不存在，不能把缺席写成已经分出胜负。

**用户近邻写成 LLM 查询、语义 ID 或凭记忆生成标题。** 用户近邻不是文档查询。TIGER 的用户 token 是生成下一物品时的输入。没有「生成用户标题再当近邻」的公开协议。

**再报一个域内执行准确率，或把主指标写成作者看约束满不满足。** 这是垂直领域 22 篇的重复，也是投错任务。ACL 主会读者若看到 Spider 或 BIRD 下跌表、RS(c)、或 OMOP 式的 93.55，会对上 BookSQL、SM3、FLEX、TrustSQL、Arctic、SQLForge，而不会把它读成商品检索。

## 4. 热度趋势

年份只用笔记里出现的 2023–2026。今天是 2026-11-11，所以 2026 年的会议和预印本都算已经出现。没有年份的论文不放进任何一条线。不画引用曲线，只写哪一年开始出现、哪一年句子已经拥挤。2019 的 RecSys 复现、2021 的 TOIS、2022 的 EHRSQL 只作为前史：近邻基线和不可回答题在 2023 之前就有，不把它们画成这四条线的起点。

**领域 Text-to-SQL 的执行准确率与拒答。** 2023 年 Binder（ICLR）把模型调用嵌进 SQL 或 Python，ScienceBenchmark（PVLDB）和 DIN-SQL（NeurIPS）都在报执行准确率。2024 年这一句已经拥挤：BookSQL（NAACL 长文）是会计模板，SM3（NeurIPS D&B）是医学模板，SUQL（NAACL Findings）是返回集合的人工精度，Wretblad（ACL 短文）在查 BIRD 噪声，TrustSQL 的预印本把拒答定义成可靠性分。2025 年仍在加长文和榜，H-STAR、FLEX（NAACL）、Spider 2.0（ICLR）、SQLForge（ACL Findings）、OmniSQL 预印本，拥挤的是同一类分数。2026 年 Arctic（ACL Findings）继续用执行对错训练，OMOP 在 ClinicalNLP @ LREC 上把合成模板做到执行准确率 93.55，BiomedSQL 的页眉是 COLM。线没有停，贡献类型在 2024 年就已经挤满。这路到 2026 年仍没有一篇把 SQL 的执行结果当成推荐候选。

**自然语言商品过滤。** 档案会议上的起点是 2024 年 Malik 等的 CIKM：商品搜索句变成过滤接口，指标是 Exact Match 和 Micro-F1，没有候选召回。InteRecAgent 的 arXiv 号是 2308，2023 年就已经把硬条件交给 SQL，但那是预印本，而且禁止用 SQL 找相似物品。2025 年 HyST 在 STaRK 的小子集上做了 JSON 过滤再向量检索。2026 年句子变挤：ProRetrieval、MACS、RecoAtlas 都是无会议页眉的预印本，BEATS 在 SIGIR 上把属性写进双塔文档，RecBench+ 的页眉是 WSDM，EComAgentBench 是 EMNLP Industry，BLaIR 是 ACL 长文但测的是嵌入 NDCG，没有 SQL 行。「第一次做结构化商品过滤」到 2026 年不能再写。还没有挤满的是公开全库上的可执行 SQL 加留出 Recall。

**无约束下一物品与生成式检索。** 2023 年 TIGER（NeurIPS）把语义 ID 的生成式检索做成一篇主会论文，LC-Rec 和 GPT4Rec 的预印本号也在 2023。2024 年这一串已经拥挤：LETTER（CIKM）、EAGER（KDD）、IDGenRec（SIGIR），外加 Xu 等的预印本指出这些表里的 SASRec 是 BPR 或 BCE 的弱行，同一份 Beauty 上全量交叉熵的 NDCG@10 是 0.0597。2025 年 LLM2Rec（KDD）和 LEARN 仍在做向量，OneRec-Think 的预印本继续相对弱 SASRec 报涨幅。2026 年 Benigni 等的 TORS 说明，SIGIR 2023–2024 的扩散推荐在清洗后的 Amazon-Books 上没有稳定打过 ItemKNN。无约束下一物品从 2024 年起拥挤。SQL 自连接没有进入这条线的主表。

**关系库上的 GNN 推荐。** 2023 年的预印本是 Fey 等，笔记写会议版把它引成 ICML 2024 position，打开的 PDF 无页眉。2024 年会议形态出现：RelBench v1 是 NeurIPS Datasets and Benchmarks，推荐任务没有自然语言；ContextGNN 的预印本给出 H&M 的 2.93 和局部性。2026 年继续加，但加的不是语言：v2 是 ICLR DATA-FM workshop，RelAgent 是 NeurIPS 2026 的特征 SQL 加树模型，ReFuGe 是 WWW 2026 短文，两者的 H&M 数字都是流失分类的 AUROC。手写共现到 2026-11-11 仍没有出现在这七篇里。把这条线写成「GNN 已经打败 SQL」会跨过 window-05 明确杀掉的句子。

**「SQL 的执行结果就是推荐或检索候选」。** 2023 到 2026 都没有一篇已打开的论文占住公开全库上的这一格。靠近它的句子按年贴上来：2023 年 InteRecAgent 的属性 SQL，2024 年 SUQL 的小集合人工精度和 CIKM 的过滤接口，2024 年 STaRK 提供了全库基准但没有 SQL 臂，2025 年 HyST 在缩小的池子上做过滤后检索，2026 年 ProRetrieval 在 3,000 件上用构造单文档的 Hit@1。线的附近一年比一年挤，格子本身到笔记写完的这一天仍空着。空着不等于可以写成「第一次做商品 SQL」。可以写的是协议和缺口：全库、关系边、留出或可核验的候选、约束满足、空结果和放松代价。

## 5. 多维度

每一维都回到这篇的选题：STaRK-Amazon 上关系片段 SQL 加 BM25 或小编码器；RelBench 手写共现只做健全性检查。

### 会议社群和 ACL 主会读者是否重叠

ACL、NAACL、EMNLP 主会读者重叠最高的，是垂直领域 Text-to-SQL 和表问答：BookSQL、H-STAR、FLEX、Binder 的问答设置、SUQL 的 Findings、Arctic 的 Findings。他们熟悉执行准确率、Spider 和 BIRD。这篇能写的是一句划界：那 22 篇没有 Recall、NDCG 或 Hit，OMOP 的 93.55 说明域内执行高分已经出现。这篇不能写的是再交一张域内执行准确率，或把拒答分当成主贡献。那样投的是他们已经在审的会，句子是重写。

SIGIR、KDD、CIKM、WWW、PVLDB 的读者重叠在检索和过滤，不在 ACL 的语言贡献。Malik 等、BEATS、SIEVE、Lim、TIGER 一串、LLM2Rec 在那边。这篇能向 ACL 读者解释分工：列上的谓词交给数据库，文本仍交给 BM25。这篇不能把 PVLDB 的近邻 recall 或 CIKM 的 Exact Match 写成自己的主指标，也不能把论文写成过滤索引或生成式检索的下一篇。RecSys 2019 和 RecSys 2023 的读者会要调好的 ItemKNN 和评测协议；那两篇支持「近邻是强基线」和「各自候选上算效用」，不支持把 RelBench 写成语言实验。

NeurIPS、ICLR 主会在这批里更多是生成式检索、推理型检索和 Spider 2.0，加上 RelAgent 这种关系学习。Datasets and Benchmarks 里的 STaRK 和 RelBench v1 是这篇实际对着打的基准，档次低于主会，不因此降低表 6 和表 5 的约束力。COLM、CIDR、WSDM、SIGMOD、AAAI、ClinicalNLP、EMNLP Industry 按笔记保留，不用来声称「ACL 主会还没有任何邻近工作」或「这些会低于 ACL」。

大量最近的商品 SQL 近邻是仅预印本：HyST、ProRetrieval、MACS、InteRecAgent、KAR、MoR、SPARK。没有会议页眉不等于句子不存在。投稿风险来自句子，不来自对方是否已经进主会。

### 贡献是方法、数据、测量，还是缺失基线

这篇能写的贡献类型是测量加一个缺失对照，方法创新要等先导过关再谈。总览的停点写明：11 月 25 日如果生成 SQL 的下游指标达不到手写 SQL 的八成，先写测量文，不设计新的生成算法。测量用现成指标：Hit、Recall、MRR、NDCG、条件匹配率、温度 0 的字符串一致、结果集 Jaccard、执行审计。审计只说明展示的行是不是这条 SQL 的执行结果。

不能写成新方法的有：手写共现，它是缺失基线；只把 ItemKNN 写成 SQL；再造一个可解释性指数；把「SQL 是忠实解释」写成贡献，审稿人会要用户研究。不能写成新数据的有：给 RelBench 的 14 个任务各套一句模板；把 STaRK 合成标签的逆运算当成新标注。STaRK、RecBench+、Amazon-C4、RelBench 的数据贡献分别属于 D&B、名单外的 WSDM、ACL 长文和 D&B，这篇是在这些数据上换执行器和指标，不是再发一个基准，除非题目按继续调研收成「协议和缺口」，并且点名 HyST、ProRetrieval、MACS、Malik 等、InteRecAgent、TalkPlay-Tools、SUQL。

RelAgent 和 ReFuGe 的方法是「LLM 搜索 SQL 特征，树模型出分类分」。那是方法论文的形状，任务不是购买 top-K。这篇不能把健全性检查写成同类方法。

### 指标是执行准确率，还是 Recall、NDCG、Hit

执行准确率这条线从 2023 年接到 2026 年，主会、Findings 和名单外都有。它回答的是金 SQL 是否执行到同一结果。FLEX 和 Jin 等说明这个判断会把错查询判对、把对查询判错，金标噪声还会改名次。TrustSQL 和 OMOP 说明高执行分可以和很差的可靠性分同时出现。这篇的主表不能使用执行准确率，也不能把作者判定的约束满足或 RS(c) 写成 Recall。

这篇能报的是检索和推荐指标，而且不能横比。STaRK 合成集打表 6 的 BM25：Hit@1 44.94，Hit@5 67.42，Recall@20 53.77，MRR 55.30。人工 81 条另表。Recall@20 同时报截断前后。RecBench+ 若做，相关集是知识图谱上满足条件的全部物品，历史子集的 Precision 另报，0.308 和 0.714 不进主表。Amazon-C4 的负对照是 NDCG@100 0.1856。RelBench 的健全性检查是 MAP，百分数刻度下的历史访问是 0.89，和 Recall 不是同一个数。Beauty 上的 NDCG@10 0.0597 只说明序列基线要用全量交叉熵这一档，不能横比到 STaRK。

mFAR 自己的 BM25 是 0.483 / 0.584 / 0.589，不是表 6。HyST 的 Precision@1 0.9211 不是表 6。ProRetrieval 的 Hit@1 不是留出购买。InteRecAgent 的 Recall@5 是百分数，排序 NDCG 是 1 个正例加 19 个随机负例。这些格子都不能填进主表当已经打过的基线。

### 语言是否真正进入任务

语言进入任务，在这篇里指用户问句里同时有关系片段和自由文本，模型只把关系片段写成 SQL，文本留在 SQL 外面。STaRK 的合成查询和 81 条人工查询满足这一点。81 条不是四个模板填出来的，不少句子仍然点了图里有的品牌、颜色、品类或另一件商品，同时夹着图里没有的价格和尺寸。价格和尺寸不在图里，就不能写成关系 SQL 已经覆盖整句。

语言没有进入任务的，是 RelBench 全部推荐任务、Wydmuch 的固定段落、RelAgent 和 ReFuGe 的特征搜索、历史访问和全局流行、ItemKNN 和 EASE、TIGER 的 ID 生成、SIEVE 和 Lim 的索引负载。这些可以当对照或健全性检查。把它们写成语言主实验，会在 ACL 主会上被看成投错了任务。MACS 的语言进入的是槽位，SQL 是确定性映射，不是自由生成的多表 SQL。CIKM 2024 的语言进入的是过滤 schema，没有执行后的候选集。SUQL 的语言进入的是餐馆表上的模型谓词，分数不是全库排序。三篇都说明「问句里出现了属性词」这句已经有人写过，不说明 STaRK 全库那一臂已经有人测过。

## 6. 对 ACL 2027 的直接建议

主实验写 STaRK-Amazon：模型只把品牌、颜色、品类、also_bought 这类已经落到关系上的片段写成 SQL，DuckDB 执行，BM25 或小编码器在超集里排序，关系片段和整句分开报，要打的全库数字是表 6 的 BM25，人工 81 条另表，另一种过滤顺序单独报。

RelBench 只留 H&M 购买上的一条手写共现，先复现历史访问 0.89，再看 MAP 有没有超出重复购买名单；它进实验节，不进贡献列表，主实验不挪到没有问句的任务上，也不写「GNN 打败 SQL」。

贡献句写成公开全库上的协议和缺口，点名 HyST、ProRetrieval、MACS、Malik 等 CIKM 2024、InteRecAgent、TalkPlay-Tools 和 SUQL，不写「第一次把自然语言商品请求编译成结构化过滤」，也不写「SQL 替换向量召回」或「只发 SQL 已经打过 BM25」。

主表用 Hit、Recall、MRR、NDCG、条件匹配率、温度 0 的字符串一致和结果集 Jaccard，外加一条执行审计；不报域内执行准确率，不把 Arctic 的 BIRD 开发集 68.9 或 OMOP 的 93.55 当成这篇的分数，无约束的 SASRec 和 EASE 放附录。

生成器仍用 Arctic-Text2SQL-R1-7B 或 OmniSQL-7B，外加一次当时的前沿模型；先导若过不了总览里的两个停点，就停在测量，不把未测的胜负写成结论。
