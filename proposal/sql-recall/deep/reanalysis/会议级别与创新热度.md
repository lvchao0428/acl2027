## 1. 一句话结论

这条线里，已发表论文散在主会长文、NeurIPS D&B、Findings、领域会和研讨会；95 篇里主会长文 20 篇，未见会议录用 41 篇。主会长文堆在域内执行准确率、语义 ID、检索基准这三类。公开全库上「模型写出可执行 SQL、数据库返回候选、用 Hit / Recall / NDCG 打分」没有被一篇主会长文占住。对 ACL 2027 主会（总览记载的 ARR 截止是 2027-01-04），能写的是这一格的协议和缺口；再报一个域内执行准确率，或把拒答写成主创新，会和已经中稿的主会、D&B 论文撞车。

## 3. 按创新点看重稿

四档以五步之后的网格为准。06 总表有三处不同，不另开一套格子：

- 硬过滤 × 工程师写死的 SQL：06 写成已有；五步之后改成假空。理由是 STaRK 合成标签落在关系候选里，只执行关系模板是构造的逆运算。
- 物品共现 × LLM 写 SQL：06 写成不该做；五步之后改成空着且值得做。前提是问句里同时有硬谓词。InteRecAgent 明文不许用 SQL 找相似物品。
- 半结构化 × LLM 写 SQL：06 把「STaRK 上没有只执行 SQL 打过 BM25」写成这一格空着；五步之后把 SUQL 填进「已有」，并把「只写关系片段、超集上再排序」放到格子外面。07 说格子外面这一步还留着。

### 3.1 还没有被一格占住的做法

五路都没有杀掉、07 加了旁注仍留着的，是跨在两格上的这一句：模型只把已经落到边上的片段写成 SQL，数据库返回关系超集，BM25 或小编码器在商品文档上排序。关系片段和整句分开报。数据是 STaRK-Amazon 全库。分数是表 6 的 Hit@1、Hit@5、Recall@20、MRR。

这一条还没有被已发表论文按同一协议占住。SUQL 占住的是餐馆表、最多返回 3 家、作者判定的集合精度，档位是 NAACL 2024 Findings。KAR 和 MoR 占住的是检索器不变、或文本臂仍是 BM25，两篇都是预印本。STaRK 官方系统列表里没有 SQL，也没有 Cypher。

07 把旁边三步写明了，全库协议仍空着：

- HyST（2025，未见录用）在 76 条、3,335 件上做了 JSON 过滤后再向量检索，丢掉 `also_bought` / `also_viewed`。官方全库、关系边和价格区间它没占住。
- ProRetrieval（2026，未见录用）在 3,000 件自建商品上让模型写 SQL，Hit@1 有数。金标准是构造出来的单篇文档，留出购买上的推荐 Recall 它没占住。
- MACS（2026，未见录用）和 Malik 等（CIKM 2024）占住的是槽位或过滤 schema。自由 SQL、多表连接、空结果的最小放松，在公开全库上没有 Recall 表。

| 审稿人会拿的论文 | 档位 | 它实际做到的一步 |
|---|---|---|
| SUQL | NAACL 2024 Findings | 餐馆集合的人工精度，上限 3 家。纯 SQL 不够，文本靠 `ANSWER` |
| Malik 等 | CIKM 2024 | 商品搜索句到过滤 API。公开对照是 ESCI 上 268 条的 Exact Match。没有候选召回，没有 SQL |

### 3.2 标成「已有」的格

每一格写：谁占住、什么档、做到哪一步、哪一步没做所以旁边还空着。

**硬属性过滤 × LLM 写 SQL 且数据库执行。** 占住的是 InteRecAgent（2023，未见录用）和 TalkPlay-Tools 的单表布尔 SQL（2026，未见录用）。InteRecAgent 让模型写 SQL，只许一张物品信息表，不许 `LIMIT`，标题不能当条件，并禁止用 SQL 找相似物品；协同走 ItemCF。它的 Hit@5 来自事先知道目标的模拟器，排序表是 1 个正例加 19 个随机负例。TalkPlay 的 SQL 在单表 `tracks` 上做布尔过滤，另有 BM25，不替换 STaRK-Amazon。再做一遍「LLM 写 WHERE、数据库执行硬条件」会被看成重复。它们没做的是：公开全库、留出交互或可核验属性上的 Recall / NDCG、多表连接。所以全库协议还空着，工具形状已经不空。

**硬属性过滤 × 向量或过滤近似搜索。** 占住的是 SIEVE（PVLDB 2025）和 Lim 等（PVLDB 2026）。两篇的 recall 是找回真正的 top-k 向量近邻。SIEVE 在低选择率上可以到 0.99 以上，ACORN-γ 大约 0.95。Lim 的 “often below 0.2” 绑在高难度、选择率大约 0.1% 或更低，数据是 SIFT、GIST 一类。再写一篇过滤 ANN 的近邻 recall，会和这两篇 PVLDB 重复。它们没做推荐 NDCG，也没做「这个品牌、这个价格、排除已买」。近邻 recall 不能写成推荐涨幅。

**硬属性过滤 × LLM 凭记忆生成标题。** 占住的是 RecBench+ 显式条件（WSDM 2026）。测试提示词没有影片目录。表 2 的 0.308 和 0.714 是生成式分数。再报一组没看目录的生成 Precision / CMR，会和这篇领域会论文重复。它没做全目录检索。式 (7) 的相关集是图谱上属性包含 \(C_{shared}\) 的全部物品；历史子集 Precision 会罚掉「把满足条件的电影都返回」。

**物品到物品共现 × 向量。** 占住的是 InteRecAgent 的 ItemCF（2023，未见录用）和 STAR 的语义加共现（2024，未见录用）。STAR 的共现是事先算好再填进提示，模型没有写这条查询。再把共现塞进向量或提示，会和这两篇预印本重复。它们没做的是数据库里的自连接，也没有调过收缩的 ItemKNN 对照表。档位停在预印本，重稿风险来自做法已经写出来，不来自主会已经收过同一篇。

**带文本的半结构化检索 × LLM 写 SQL 且数据库执行。** 占住的是 SUQL（NAACL 2024 Findings）。文本谓词靠 `ANSWER`，作者写纯 SQL 不够。指标是返回集合的人工精度，上限 3 家。再做「SQL 里调用模型、作者判定约束满不满足」，会和 Findings 这篇重复。它没做 STaRK 全库检索，也没做交互表上的留出推荐分。Findings 低于主会长文；重复贡献的判断看格子，不看它有没有进 ACL 长文。

**带文本的半结构化检索 × LLM 写查询、引擎是 BM25 或搜索。** 占住的是 TalkPlay 的 BM25 工具（2026，未见录用）和 KAR（2024，未见录用）。KAR 扩展查询之后引擎仍是 BM25。再做「模型改写、BM25 照旧」会和这两篇预印本重复。它们没把 STaRK 的官方全库换成只执行 SQL。

**带文本的半结构化检索 × 向量。** 占住的是 STaRK 表 6 的 ada-002 与 ColBERTv2（NeurIPS 2024 D&B）。这是本网格里半结构化检索上的 D&B 论文。再报一个同协议的稠密检索基线，会和基准论文里的这一行重复。表 6 没有 SQL。后面的 HybGRAG（ACL 2025 长文）没有 Amazon 分割；AvaTaR、KAR、MoR、SPARK 在自己的表上打检索分，文本臂或回退里仍有 BM25 或向量。

**无约束的下一个物品 × LLM 写查询、引擎是 BM25。** 占住的是 GPT4Rec（2023，未见录用，页眉是占位会议名）。多查询加 BM25，查询是标题。再做「模型写标题式查询、BM25 取下一物品」会和这篇重复。它没有 SASRec，也没有协同自连接。Q′ 的两份稿是研讨会，查询是网页，引擎是 Bing，不占这一格的商品下一物品。

**无约束的下一个物品 × 向量。** 占住的是 LLM2Rec（KDD 2025）和 LEARN（AAAI 2025）。产出是向量，召回仍是内积或序列模型。再做一篇「LLM 当编码器、内积召回下一物品」，会和 KDD 2025 这篇主会论文撞上。它们写不出可执行连接。Xu 等的全量交叉熵 SASRec（2024，未见录用）在同一用户数、同一物品数的 Beauty 上 NDCG@10 是 0.0597，高于 TIGER 0.0384、EAGER 0.0525、IDGenRec 0.0541、OneRec-Think 0.0471。这张表说明序列基线要用这一档，它自己没有 ItemKNN，也没有 SQL。

**无约束的下一个物品 × 语义 ID。** 占住的是 TIGER（NeurIPS 2023）和 LC-Rec（2023，未见录用）。同方向的主会和领域会还有 EAGER（KDD 2024）、IDGenRec（SIGIR 2024）、LETTER（CIKM 2024）。再做「LLM 生成离散码或文本 ID」，会和这些已发表论文重复。不能把「LLM 生成 ID」写成「LLM 写 SQL」。生成式检索主表里的 SASRec 是 S3-Rec 公开结果那一档，不能写成超过调好的序列模型。

**无约束的下一个物品 × LLM 凭记忆生成标题。** 占住的是 InteRecAgent 里不调工具的 GPT-4（2023，未见录用）。02 写 Beauty 上通用 LLM 幻觉严重，优势有一部分来自模型不认识这些标题。再报「不看目录、直接生成下一件的标题」会和这一基线重复。它没有全库检索协议。

**关系库上的未来窗口 top-K × 向量。** 占住的是会议版 v1 的 GraphSAGE 与 ID-GNN（NeurIPS 2024 D&B），以及 ContextGNN 的成对模型（2024，未见录用）。评测是目标实体嵌入上的 top-k。H&M 购买测试：历史访问 0.89，两层 GraphSAGE 0.80，ID-GNN 2.81，ContextGNN 2.93。再交一个关系库上的 GNN 推荐器，会和 D&B 基准加这篇预印本重复。它们没跑手写共现，也没有用户问句。

**约束满足或拒答 × LLM 写 SQL。** 占住的是 TrustSQL（2024，未见录用）和 OMOP（ClinicalNLP 2026）。同一条线的已发表高档是 EHRSQL（NeurIPS 2022 D&B）和 EHRSQL 2024 共享任务（ClinicalNLP）。高执行分和很差的可靠性分可以同时出现：共享任务第一名 RS(0) 88.17、RS(N) −711.83；OMOP 的 ExecAcc 93.55 与 RS(10) 0.373 同时出现。再把「何时不写 SQL」写成主创新，这一格已经满了。它们的分数是执行准确率或可靠性分，没有推荐 Recall。

**约束满足或拒答 × LLM 凭记忆生成标题。** 占住的是 RecBench+ 的错误信息条件（WSDM 2026）。FTR 被解释成识破假话，系统仍是没看目录的生成。再做一组不看目录的「识破假条件」，会和这篇重复。它不提供目录上的检索召回。

### 3.3 标成「假空」的格

这些格里没有同名系统。投出去仍会被说成重稿，或实验不成立。

**硬属性过滤 × 工程师写死的 SQL。** 看起来像空位，因为没有一篇把「手写 SQL 系统」当成 STaRK 上的检索器发表。投出去不成立：合成标签是关系候选再经文本筛选的子集，只执行抽样时那条关系模板，取回的是标签的超集，测的是构造的逆运算。SQL 没有 `ORDER BY` 就没有 Hit@1。STaRK 是 NeurIPS 2024 D&B。审稿人会说分数是基准构造的逆运算。

**物品共现 × LLM 写查询、引擎是 BM25 或搜索。** 看起来像「模型写查询、另一个引擎执行」还没人做成协同。GPT4Rec（2023，占位页眉）的查询是标题；WebReco 与 EARL（2024，两份研讨会）的查询是网页，引擎是 Bing。02 写明查询是标题或网页。再投会被说成 GPT4Rec 或 Q′ 的重复，共现计数对不上。

**物品共现 × 语义 ID。** 看起来像「用生成式检索做协同」还没写成 SQL，所以格子空着。TIGER（NeurIPS 2023）这一路的协同在参数里。冷启动的 Semantic_KNN 是嵌入近邻，不能代替调过收缩的 ItemKNN。审稿人会直接拿这篇主会论文。假空的原因是：主会已经做了生成式协同，做法是在参数里生成离散码。

**用户到用户近邻 × 工程师写死的 SQL。** 看起来像没人把 UserKNN 写成 SQL。Ferrari 的 UserKNN 在 RecSys 2019，STAR 的 top-10 UserKNN 在 2024 预印本，Hits@10 是 0.007 / 0.007 / 0.002。02 要补的 SQL 是物品侧 ItemKNN。0.007 不能当成用户近邻值得用 LLM 重写的证据。写成 SQL 会被叫成老基线的改写。

**用户到用户近邻 × 向量。** 调过的 UserKNN（Ferrari，RecSys 2019）和 top-10 UserKNN（STAR，预印本）已经在 02。只是没有写成向量索引论文。再做一篇用户近邻向量检索，会被说成这些基线的改写。

**半结构化检索 × 语义 ID。** 这一路留下的是关系片段加上文档排序。TalkPlay 的 Semantic ID 成功率高，是因为上下文里已经有码，而且 TalkPlay 不替换 STaRK。再做一个语义 ID，会被拿去和 TIGER 一系的主会论文比，也补不上 STaRK 的全库标签。

**关系库未来窗口 × LLM 写查询、引擎是 BM25 或搜索。** 任务输入是实体和种子时间。05 写这组不能当语言实验，没有可供模型改写的用户问句。格子空着，是因为任务本身没有问句。投一个「BM25 改写 RelBench 问句」不成立。

**约束满足 × 工程师写死的 SQL。** 确定性校验出现在 PCN-Rec（2026，未见录用）。候选来自 MF/CF 窗口，一次生成的 PassRate 笔记写 0.000，不能写成大模型在约束推荐上的普遍通过率。01 写拒答主创新已经挤满。再交一个手写规则校验器，要么撞上 PCN-Rec 的设置，要么被收成 EHRSQL 那条拒答线。

### 3.4 空着且值得做

这三格没有被已发表论文按同一做法占住。审稿人仍会拿近邻论文来比。三格都不适合单独当成 ACL 主会的语言贡献。

**物品共现 × 工程师写死的 SQL。** 手写共现没出现。自连接写得出调过收缩的 ItemKNN，这张对照表在这批 PDF 里不存在。它是漏掉的基线。网格把它写成经典基线，不写成新系统。审稿人会拿 Ferrari Dacrema 等（RecSys 2019；期刊扩展 TOIS 2021）和 Benigni 等（TORS，2026 年 3 月）：近邻和线性模型经常赢过当时的神经方法，EASE 在 64 GB 内存不够时整行是空的。最近的已发表档位是领域会（2019）和期刊（2021、2026），没有 ACL 主会长文把这条自连接测完。用 Benigni 证明「SQL 版 ItemKNN 没前途」方向反了：自连接写得出这个 ItemKNN，写不出 EASE。

**物品共现 × LLM 写 SQL 且数据库执行。** 02 写没有一篇是模型写出协同自连接、数据库执行、再用推荐 Recall 或 NDCG 打分。InteRecAgent（未见录用）禁止用 SQL 找相似物品，所以不能把那篇算成占住了这一格。若问句里同时有硬谓词，这一格仍空着。审稿人最可能拿的已发表论文是 TIGER（NeurIPS 2023）、EAGER（KDD 2024）、IDGenRec（SIGIR 2024）：协同推荐已经在主会上做成生成式检索。它们生成的是 ID。Xu 等（未见录用）会被拿来要求序列臂用全量交叉熵。这张「SQL 自连接对全量交叉熵 SASRec、对 EASE」的全库排序表不存在，不能预先写成谁输谁。

**关系库未来窗口 × 工程师写死的 SQL。** 手写共现没报过。先对照 H&M 历史访问 0.89。超过 0.89 只说明打过自身历史，不接近 ContextGNN 的 2.93。网格把它留成健全性检查。审稿人会拿 RelBench v1（NeurIPS 2024 D&B）和 ContextGNN（2024，未见录用），并把这条 SQL 叫成 SQL 版近邻。D&B 已经定义了任务和历史访问。缺的是自连接那一行。这一行只做健全性检查。

### 3.5 不该做

无约束下一物品上的写死 SQL 或 LLM 写 SQL：02 写不要当主表。用户近邻上的 LLM 写 SQL、BM25、语义 ID、凭记忆生成：五份最终节没有把这些留成空位。半结构化上的纯 SQL：纯 SQL 盖不住自由文本；TAG 的 0.55 是 80 道改写题上的手写问答上界，档位是 CIDR 2025。关系库上的 LLM 写 SQL 再当成购买 top-K：RelAgent（NeurIPS 2026 主会）和 ReFuGe（WWW 2026 短文）的 SQL 出的是分类或回归特征，H&M 列是 churn。购买任务 `user-item-purchase` 不在这两篇的表里。Wydmuch 定义了链接任务的 MAP，实验没有测，不能把缺席写成 LLM 已经匹配推荐。拒答上的 BM25、向量、语义 ID：01 的拒答文献走 SQL 执行或拒答令牌；04 禁止把 NevIR、ExcluIR、LIMIT 的嵌入失败写成约束推荐上的向量拒答。

## 6. 对选题的直接判断

总览把 ACL 2027 的 ARR 截止记为 2027-01-04。主会长文要避开第 3.2 节里已经有主会或 D&B 的格，也要避开第 3.3 节的假空。

最不像重稿的一条，是第 3.1 节那条：在 STaRK-Amazon 全库上，模型只把已经落到关系上的片段写成可执行 SQL，数据库返回超集，BM25 或小编码器在文档上排序，用表 6 那一组 Hit / Recall / MRR 打分，关系片段和整句分开报，并另报约束满足、空结果和放松代价。最近的已发表近邻是 SUQL（NAACL 2024 Findings）和 Malik 等（CIKM 2024）。STaRK 自己是 NeurIPS 2024 D&B，表 6 没有 SQL。HyST、ProRetrieval、InteRecAgent、TalkPlay 更近，四篇都是未见录用，协议停在小池、单篇金文档、模拟器或单表布尔过滤。

共现上的 LLM 写 SQL 也还没有同格的已发表论文。它比上面那条更容易被叫成 SQL 版 ItemKNN。审稿人会拿 NeurIPS 2023 的 TIGER 和 KDD 2024 的 EAGER。网格把它留成带谓词的第二行实验，不替换 STaRK 主实验。手写共现对照 H&M 的 0.89 只做健全性检查。RelBench v1 是 D&B，这组没有自然语言。

即使做出数字，下面这些做法的档位或口径也撑不起 ACL 主会长文：

- 再报一个域内执行准确率。主会已经有 BookSQL（NAACL 2024 长文）、FLEX 与 H-STAR（NAACL 2025 长文）、Spider 2.0 与 Binder（ICLR）、DIN-SQL（NeurIPS 2023）。D&B 有 EHRSQL 和 SM3。OMOP 在 ClinicalNLP 2026 上把域内执行做到 93.55，RS(10) 仍是 0.373。高分本身不构成贡献。Arctic 在 ACL 2026 Findings，奖励只看执行。
- 把拒答或可靠性分写成主创新。占住它的已发表高档是 NeurIPS 2022 D&B，其后是 ClinicalNLP 的共享任务和 2026 研讨会。01 写这一格没有空位。
- 用 RecBench+ 的历史子集 Precision，或表 2 的 0.308 与 0.714，当检索主结果。这篇是 WSDM 2026。目录不在提示里。式 (7) 才是全目录条件表，而且不换到主实验。
- 在无约束下一物品上再报一个语义 ID，或再报一个 LLM 向量召回。主会已经有 NeurIPS 2023、KDD 2024、SIGIR 2024、KDD 2025。
- 把「只执行 SQL、不再做 BM25」写成已经打过表 6。04 写这张结果不存在。合成集上只执行关系模板的集合召回，是假空，不进主表。
