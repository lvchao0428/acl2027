## 1. 结论

这篇要对标的是 **ACL 主会长文**，也就是一档主会。ARR 截止是 2027-01-04。审稿人会拿一档主会和 Findings 里已经占住的句子来读我们。

一档主会上还空着、而且网格第 3 节写成值得做的，是这一句：LLM 只把已经落到边上的片段写成 SQL，数据库返回关系超集，BM25 或小编码器在商品文档上排序。STaRK-Amazon 的官方全库上，这批 PDF 里没有「只执行 SQL 或 Cypher、不再做向量或 BM25」并且打过表 6 BM25 的一臂。表 6 的 BM25 是 Hit@1 44.94、Hit@5 67.42、Recall@20 53.77、MRR 55.30。

已经在一档或 Findings 里挤满的，是四类句子。第一，换一个领域、用模板填槽、再报域内执行准确率。第二，无约束的下一个物品上，用语义 ID 或生成式解码做检索。第三，半结构化问题上仍带着检索器的混合系统：字段混合打分、检索器银行、查询扩展之后引擎仍是 BM25。第四，推理型相关、指令跟随、单向量容量这一类新测量。拒答和可靠性分在 NeurIPS 2022 的 EHRSQL、ClinicalNLP 研讨会和若干无会议页眉的预印本里已经有任务定义，网格把「再把拒答写成主创新」标成没有空位。

热度只在这批清单内部成立。2025–2026 的一档名单里，推理型检索出现了 BRIGHT（ICLR 2025）、FollowIR（NAACL 2025）和 LIMIT（ICLR 2026）。半结构化检索的基准 STaRK 在 2024 年进了 NeurIPS Datasets and Benchmarks，系统论文 HybGRAG 在 2025 年进了 ACL 主会；AvaTaR、KAR、MoR、SAGE / SPARK 在打开的 PDF 里仍没有会议页眉。温度 0 的非确定性和向量 RAG 的可复现，停在 Atil 等的预印本和 ReproRAG 的 Workshop ’25。域内执行准确率从 2023 年一直排到 2026 年的一档、Findings 和领域会，笔记留下的判语是：再报一个域内执行准确率，写不进创新点。无约束生成式检索在 2023–2025 年仍有 NeurIPS、KDD、SIGIR；笔记留下的中稿句是语义 ID 或文本 ID 本身。同一份 Beauty 上，全量交叉熵 SASRec 的 NDCG@10 是 0.0597，高于 TIGER 的 0.0384、EAGER 的 0.0525、IDGenRec 的 0.0541 和 OneRec-Think 的 0.0471。

对我们选题的一句判断：ACL 主会能接受的是这句还没被一档占住的协议——关系片段写成 SQL，超集交给文档排序，官方检索指标和谓词匹配、温度 0 的字符串一致、结果集 Jaccard、执行审计一起报。STaRK 的基准、HybGRAG 的检索器银行、mFAR 的字段混合、SUQL 的自由文本 SQL、BRIGHT / LIMIT 的推理型测量，都不能再写成我们的创新点。

## 3. 按创新点类型看中稿原因

类型用网格里已有的轴。每类先写审稿人能看见、而且笔记判过站得住或明确留下的那一句，再写这一档靠的是新任务、新系统，还是新测量。被批判杀掉的句子不放在这里，集中放在第 8 节。

### 硬属性过滤 / 已经落到列上的谓词交给数据库

代表和级别：

- InteRecAgent，尚未见会议版。站得住的一句是：LLM 做规划，SQL 工具负责硬条件，ItemCF 负责相似，排序器负责打分。附录把 SQL 限制成一张物品信息表上的单行 SELECT，标题不能当条件，不许用 SQL 找相似物品。
- TalkPlay-Tools，尚未见会议版。站得住的一句是：LLM 编排 SQL、BM25、稠密检索和 Semantic ID。SQL 是音乐单表上的布尔过滤。
- ACORN，SIGMOD 2024。站得住的一句是：谓词可以留在向量搜索里面；在 0.9 召回下，谓词无关的混合搜索比先前方法有 2–1,000 倍的 QPS。这是吞吐。
- SIEVE，PVLDB 2025。站得住的一句是：不为每个谓词改遍历，按负载建一堆子索引，对象是过滤向量搜索的近邻 recall。
- Lim 等，PVLDB 2026。站得住的一句是：过滤近似搜索的难度不该用选择率来代表；谓词是 SIFT / GIST 上的合成标签。
- NumConQ，BDMA 2026。站得住的一句是：稠密检索器满足不了文本里的数值约束。Olympics 上 Contriever 对身高、体重、年龄的一致性平均 16.3%，非数值属性平均 73.64%。文档由结构化条目改写而来，原表在检索时已经不在。
- Malik 等，CIKM 2024。笔记留下的一句是：商品搜索句变成过滤 API，公开对照是 Amazon ESCI 上 268 条人工过滤标注，指标是 Exact Match 和 Micro-F1。FLAN-T5 端到端 Exact Match 56.34%。没有候选召回。
- HyST、ProRetrieval、MACS，都是尚未见会议版。HyST 把自然语言拆成 JSON 元数据过滤和剩下的语义查询，池子是 3,335 件、76 条查询。ProRetrieval 让模型写出带文本和图像占位符的 SQL，电商集 3,000 件，金文档是构造流程先选定的一篇。MACS 让商户代理把槽位映射成 SQL `WHERE`。

能进一档的，是新系统或新测量，落在数据库和向量索引上。ACORN 和 SIEVE 是过滤向量搜索的新系统。Lim 等是新测量：用 α-Hardness 控制负载。它们的 recall 是向量近邻 recall。商品属性 WHERE 再拿推荐的 Recall 或 NDCG 打分，在一档名单里没有对应的系统论文。

停在 arXiv 或领域会、缺的那一块：InteRecAgent 缺一份带自然语言查询和全库 Recall@K 的固定测试集，表上的 Hit@5 来自事先知道目标的模拟器。TalkPlay-Tools 缺商品全库，相关曲目也没有在那篇 PDF 里定义。HyST 缺官方全库和关系边，作者自己把纯 SQL 写成盖不住评论语气。ProRetrieval 缺留出交互，它自己的表里只执行 SQL 的 Hit@1 是 0.650，低于 SQL 加文本的 0.752。Malik 等已经在 CIKM 上把「自然语言落到品牌、内存、价格」做成过滤生成；缺的是执行后的候选集。主指标若改成 Exact Match，对上的就是这一篇。

### 半结构化检索（文本仍交检索器，SQL 或 Cypher 只是一段）

代表和级别：

- STaRK，NeurIPS 2024 Datasets and Benchmarks。站得住的一句是：查询同时要关系约束和文本约束，答案是图上的节点；合成 Amazon 上 BM25 接近稠密模型，表 6 为 44.94 / 67.42 / 53.77 / 55.30。
- SUQL，NAACL 2024 Findings。留下的一句是：把自由文本列上的 SUMMARY 和 ANSWER 放进 SQL。单轮 93.8%、对话 90.3% 是返回集合的人工精度，上限 3 家，只在作者自己判分时成立。
- TAG，CIDR 2025。站得住的一句是：能写成关系代数的只是用户问题的一小部分，RAG 又只覆盖点查，TAG 把两者收成一个范式。80 道改写题上 0.55 是手写上界。
- mFAR，ICLR 2025。站得住的一句是：面向任意字段数的半结构化文档，把词法打分和向量打分混在字段上。
- HybGRAG，ACL 2025 主会长文。站得住的一句是：检索器银行加评论模块，评论的反馈会改检索。脚注写明只用 STARK-MAG 和 STARK-PRIME，没有 Amazon。摘要的 Hit@1 平均相对提升 51% 是 MAG 47.4% 和 PRIME 54.9% 的平均。
- KAR、AvaTaR、MoR、SAGE / SPARK，打开的 PDF 都没有会议页眉。KAR 站得住的范围是：用知识图谱里的文档关系做查询扩展，引擎仍是 ada-002 或 BM25。AvaTaR 站得住的一句是：用比较器优化执行器对工具的使用，输出仍按检索指标打分。MoR 在 Amazon 上的文本臂就是 BM25，Hit@1 / R@20 是 52.19 / 59.92，对照 BM25 是 44.94 / 53.77。SPARK 的工具是 HNSW 和 Cypher，空结果回退 BM25 加余弦；合成集 R@20 是 53.95，BM25 是 53.77，multi-ada-002 是 55.12。

能进一档的，STaRK 是新任务（半结构化检索基准），mFAR 和 HybGRAG 是新系统（字段混合打分、检索器银行）。SUQL 进的是 Findings，卖的是一种把自由文本放进 SQL 的形式语言，指标停在人工集合精度。TAG 进的是 CIDR，卖的是范式分工，实验停在 80 道改写题。

停在无会议页眉的四篇，缺的是同一块：在 STaRK-Amazon 官方全库上，只执行 SQL 或 Cypher、不再做向量或 BM25，并且打过表 6 的 BM25。KAR 打过的是扩展之后的查询。MoR 的文本臂是 BM25。AvaTaR 按检索指标打分，PDF 里没有「只执行 SQL」的一臂。SPARK 交替使用 HNSW 和 Cypher。网格把我们的空格写成跨了「硬属性过滤」和「带文本的半结构化检索」两格，不被上面任何一篇单独占住。

### 无约束下一物品 / 语义 ID / 生成式推荐

代表和级别：

- TIGER，NeurIPS 2023。站得住的一句是：用 RQ-VAE 把文本嵌入收成语义 ID，序列模型直接生成下一个物品的 ID。相对表内抄来的 SASRec，Beauty 上的涨幅只在该协议成立。
- EAGER，KDD 2024。留下的一句是：行为码和语义码两条解码流。Beauty 的 NDCG@10 0.0525 仍低于 Xu 的 0.0597。
- IDGenRec，SIGIR 2024。留下的一句是：用文本词当物品 ID。Beauty 的 NDCG@10 0.0541 仍低于 0.0597。文本 ID 是给语言模型生成的。
- LETTER，CIKM 2024。留下的一句是：量化时加协同正则，让语义 ID 对齐 SASRec 的物品向量。对照的 SASRec 仍是弱行。
- LLM2Rec，KDD 2025。留下的一句是：两阶段把 LLM 变成物品编码器。产出是向量，召回仍是内积或序列模型。
- LEARN，AAAI 2025。站得住的一句是：用冻结的 LLM 抽物品文本向量。
- NoteLLM-2，KDD 2025。留下的一句是：端到端多模态表示，只在小红书笔记对的私有协议下有数。
- NoteLLM，WWW 2024 Companion。站得住的一句是：面向笔记到笔记的物品到物品召回，冷启动没有交互边。
- Xu 等，尚未见会议版。站得住的一句是：LLM 推荐器超过传统模型，是因为传统模型用了 BCE 或 BPR；换成全体物品上的交叉熵之后，SASRec 反过来超过 LlamaRec、P5、E4SRec。Beauty 上全量交叉熵 SASRec 的 NDCG@10 是 0.0597。

- Benigni 等，TORS 2026。站得住的一句是：复现的扩散推荐模型至少有一个更简单的基线打平或超过；清洗后的 Amazon-Books 上 ItemKNN 的 Recall@10 是 0.1133。
- GPT4Rec，尚未见会议版。站得住的一句是：用目标标题当查询来微调 GPT-2，再单独调 BM25。查询是标题扩展，没有协同自连接。
- LC-Rec、OneRec-Think、HLLM，尚未见会议版。留下的句子都停在各自的留一协议，并且不能把「LLM 生成 ID」写成「LLM 写 SQL」。

能进一档的，是新系统：语义 ID、文本 ID、两条解码流、用 LLM 做物品编码器。新任务的成分弱，下一物品留一是原有协议。新测量在这一档里表现为 Xu、Ferrari、Benigni 把基线重新标定；其中 Xu 这份 PDF 没有会议页眉，Benigni 在期刊。

这一类在一档里已经挤满到不能再当主创新。网格把无约束的下一个物品标成不该做主表。自连接写得出的是 ItemKNN 或 Swing。EASE 和吃序列顺序的 SASRec 写不出来。这批 PDF 里没有把 SQL 自连接、全量交叉熵 SASRec、EASE 放进同一张全库排序表。

停在 arXiv 的生成式论文，缺的是一份打过 Xu 这一档序列模型的全库表。GPT4Rec 缺的是协同自连接和硬谓词满足率，页眉还是占位会议名。

### 领域 Text-to-SQL 的执行准确率、拒答、可靠性

代表和级别：

- ScienceBenchmark，PVLDB 2023。留下的一句是：这些科学库比 Spider 难；「同一系统从 82% 掉到 25%–60%」没有同配置复现。造数据流程可用。
- SM3-Text-to-Query，NeurIPS 2024 Datasets and Benchmarks。留下的一句是：在他们划定的范围内，这是同时覆盖多种数据模型和查询语言的医学 Text-to-Query 基准。数据是 Synthea。零样本 SQL 最高 47.05% 只在那张提示表里成立，BM25 抽相似例之后可以到 88.55。
- BookSQL，NAACL 2024 长文。留下的一句是：会计单库、专家模板、测试模板不可见。零样本迁移很差站在这个范围内。
- EHRSQL，NeurIPS 2022 Datasets and Benchmarks。留下的一句是：可回答和不可回答放进同一个集。问句来自医院人员，进模型的是去歧义之后的模板实例。
- Spider 2.0，ICLR 2025。留下的一句是：企业工作流上的长上下文、方言和多条 SQL。o1-preview 智能体的 21.3% 是它在这个基准上的分数。
- FLEX，NAACL 2025 长文。站得住的一句是：执行准确率相对专家既会判错查询为对，也会判对查询为错。
- Wretblad 等，ACL 2024 短文。留下的一句是：BIRD 金融开发集 106 对里 52 对有噪声、22 对金 SQL 有错。范围是这个子集。
- H-STAR，NAACL 2025 长文。留下的一句是：按题型在文本推理和符号表操作之间分流。这是表问答路由。
- Binder，ICLR 2023。留下的一句是：在 SQL 或 Python 里嵌模型调用，覆盖纯 SQL 写不出的问题。WikiTQ 上 Codex BINDER 的执行准确率 64.6，相对 Codex SQL 的 61.1。
- Arctic-Text2SQL-R1，ACL 2026 Findings。总表三条里没有整句标成站得住。可以引用的是榜上的执行准确率：32B 的 BIRD 71.83%，以及他们那张多基准平均表上 7B 的 57.2。
- SQLForge，ACL 2025 Findings。07 留下的一句是：用合法 SQL 抽模板、换领域造库、再把 SQL 回译成问句。Spider 开发集执行准确率 85.7%，BIRD 开发集 59.8%。没有商品目录，没有 Recall。
- BiomedSQL，COLM 2026。留下的一句是：问句里不写、SQL 里必须写上的统计阈值，这个现象成立。40 个模板和专家 90.0 没有留下来。
- EHRSQL 2024 共享任务，ClinicalNLP 研讨会。站得住的一句是：用可靠性分 RS(10) 给系统排名。第一名在 RS(N) 下仍是 −711.83。
- OMOP text-to-SQL，ClinicalNLP @ LREC 2026 研讨会。留下的一句是：只输出一条 SQL，否则输出 `<NO_SQL>`。LoRA 的测试执行准确率 93.55 和 RS(10) 0.373 可以同时出现。
- TrustSQL、Query Carefully、FINCH、BlendSQL、Jin 等、OmniSQL、FinSQL，都是尚未见会议版。TrustSQL 站得住的一句是：能答的题写出执行正确的 SQL，不能答的题拒绝，并用惩罚分 RS(c)。Query Carefully 站得住的一句是：在 OncoMX 上建了 80 道不可回答题。FINCH 把「最大金融基准」判成不成立。

能进一档的，主要是新任务：科学库、医学多查询语言、会计库、医院问句、企业工作流。FLEX 和 Wretblad 是新测量：执行准确率会把名次排错，金 SQL 也会改名次。Binder 和 H-STAR 是新系统，分数仍是表问答准确率。Findings 里的 Arctic 和 SQLForge 继续沿执行准确率。01 这一路 22 篇全文检索不到推荐的 Recall、NDCG 或 Hit。

这一类进一档，靠的是「又一个库、又一张执行准确率表」这种新任务。笔记把挤满写成三件事：专家模板加域内执行准确率；不可答、拒答令牌和错答更贵的可靠性分；SQL 当中间表示，分数看答案对不对。OMOP 说明域内 LoRA 已经可以把测试执行准确率做到 93.55，高分本身不构成贡献。

停在 arXiv 的拒答论文，缺的是推荐留出。TrustSQL 的任务定义清楚，会议页眉没有。Query Carefully 的 80 题是作者自选的规模。把拒答再写成主创新，网格写这一格已经满了。

### 指标与诊断（嵌入能力边界、否定、数值、推理型相关、非确定性、忠实性）

代表和级别：

- LIMIT，ICLR 2026。站得住的一句是：固定维的单向量表示不了全部带间隔的 top-k 组合；相关集是 46 篇文档的全部两两组合。小集合上 BM25 的 Recall@2 是 97.8。
- BRIGHT，ICLR 2025。站得住的一句是：相关关系需要推理时，现有检索器都很差。表 2 的 BM25 十二个数据集平均 nDCG@10 是 14.5。查询侧思维链最多提高 12.2 个点，步骤被当作新查询。
- FollowIR，NAACL 2025。站得住的一句是：检索模型把指令当关键词。TREC 叙事指令停在自由文本里。
- QUEST，ACL 2023。留下的一句是：带逻辑算子的实体检索上，T5-Large 双编码器的平均 Recall@100 是 0.476，MRecall@100 是 0.142；0.142 是候选集含全部相关文档的查询比例。双编码器高于 BM25。
- NumConQ，BDMA 2026。见上一类。数值只有在原表还在时才该交给 SQL。作者的补救 NC-Retriever 仍是稠密检索器。
- NevIR，尚未见会议版。站得住的一句是：这种对比否定上，没有一个双编码器的成对准确率超过 12%，多数在 5%–10%，随机是 25%。否定活在自由文本里。
- ExcluIR，尚未见会议版。留下的一句是：排除性自由文本上，BM25 的 RR 是 53.48，作者仍写成远未理想。排除发生在自由文本查询和正负文档之间。
- Atil 等，尚未见会议版。站得住的一句是：温度 0 仍然不稳定。TARr@N 看原始字符串是否全部相同，TARa@N 看解析后的答案。可以出现准确率 100%、TARa 100%、TARr 0。
- ReproRAG，Workshop ’25。站得住的一句是：向量 RAG 的跨次运行要用集合重叠和秩相关来量。固定缓存嵌入、固定种子、CPU 上重建时，表 6 的 Jaccard 可以是 1.00。同一条 SQL、同一个库，结果集的 Jaccard 应当为 1。
- Faithful CoT，IJCNLP-AACL 2023。留下的一句是：忠实等于答案由确定性求解器执行符号链得到。脚注写明翻译阶段不在这个保证里。
- PCN-Rec，LARS @ WWW ’26 Companion。站得住的一句是：LLM 只提议名单和证书，确定性验证器决定接受。候选窗口来自 MF / CF，约束是长尾曝光和类型多样性。
- Text2VectorSQL，尚未见会议版。站得住的一句是：自然语言到同时含 SQL 谓词和向量检索的查询，是一个任务。金标准是预过滤执行结果。唯一一对召回是 ClickHouse 上 UniVectorSQL-7B 从 Non-integration 的 0.6 到 JOIN-integration 的 0.4。数据是 VectorSQLBench。

能进一档的，是新测量，有时同时是新任务。LIMIT 把嵌入的组合容量做成可测数据集。BRIGHT 把推理型相关做成检索基准。FollowIR 把「指令被当成关键词」做成 p-MRR。QUEST 把带交、并、差的实体检索做成数据集。它们进的是 ACL 或 ICLR，卖的是测量本身，查询语言不在贡献里。

停在 arXiv 或研讨会的，缺的是把测量接到 STaRK 的 qrel 上。NevIR 和 ExcluIR 的否定在自由文本里；列已经存在时，数据库谓词才接得住。Atil 提供 TARr 的定义，测的是五个模型和八个任务，SQL 生成器不在其中。ReproRAG 提供 Jaccard 的定义，量的是嵌入索引的漂移。PCN-Rec 的校验对象是治理约束，名单来自 MF / CF 窗口。Faithful CoT 的等式是求解器执行符号链。Text2VectorSQL 的两种顺序还没有在推荐 qrel 上测过。这些定义可以借来做主表的列。借来之后，测量定义仍属于原论文。

### 关系库未来窗口 top-K（RelBench 一路）

代表和级别：

- RelBench v1，NeurIPS 2024 Datasets and Benchmarks。站得住的一句是：给定源实体和种子时间，对目标实体排 top-K，指标是 MAP。库里没有自然语言查询。H&M 购买的历史访问在表里是 0.89，这个格子是百分数。
- ContextGNN，尚未见会议版。站得住的数字是：H&M 和 Amazon 购买的测试格都是 2.93。超过全局流行和自身历史的是 ID-GNN、NBFNet 和 ContextGNN。两层 GraphSAGE 0.80、NGCF 0.75、MultiVAE 0.28 没有超过历史访问 0.89。
- RelBench v2，DATA-FM workshop @ ICLR 2026。站得住的一句是：推荐仍然报 MAP，历史访问和全局流行在重跑后仍是 0.89 和 0.30。H&M 的四层 GraphSAGE 是 0.68±0.06，低于历史访问。
- RelAgent，NeurIPS 2026。站得住的一句是：智能体写 SQL 特征程序，在树模型里选择，推理时不再调用模型。范围是实体分类和回归。
- ReFuGe，WWW 2026 短文。站得住的一句是：三个智能体写出关系特征，接 LightGBM，在实体分类上比 AUROC。H&M 这一列是 user-churn。
- Fey 等、Wydmuch 等，尚未见会议版。Fey 留下的一句是：一层消息传递的函数形式可以写成 JOIN 加 AGGREGATE。Wydmuch 站得住的一句是：预测时间只能使用更早的其他实体；实验表里没有 MAP。

能进一档的，RelBench v1 是新任务：关系库上带种子时间的预测基准。RelAgent 是新系统：用智能体搜索 SQL 特征。ReFuGe 是同一方向的短文系统。它们的 SQL 产出的是特征列或分类分数。没有任何一篇把用户问句解析成 SQL，再把结果集当成购买 top-K。

手写共现 SQL 是这组论文没报过的经典基线，笔记把它留成健全性检查：先对照 H&M 历史访问 0.89。超过历史访问不等于接近 ContextGNN 的 2.93。审稿人会把它叫成 SQL 版近邻，所以它不进语言主实验，也不占「新系统」这句。

停在研讨会或无页眉的，缺的是问句。v2 的输入仍是实体、时间和标签。ContextGNN 这份 PDF 没有会议页眉，系统比较停在嵌入上的 top-k。Wydmuch 定义了链接任务的 MAP，实验没有测。

## 4. 热度趋势

下面只数第 2 节这 94 篇在各年、各档里的出现。样本就是这份本地清单。某一年某一类只有两三篇，写的是这三四篇的场合，不外推成全领域录用率。

### 硬属性过滤

一档里和「谓词 + 检索」直接相关的系统，是 2024 年的 ACORN（SIGMOD，谓词留在向量索引里）和 2025–2026 年的 SIEVE、Lim 等（PVLDB，过滤近似搜索的索引和难度）。商品侧「自然语言落到过滤」在 2024 年进了 CIKM（Malik 等），指标是过滤 schema 的 Exact Match。InteRecAgent（2023 预印本）、TalkPlay-Tools、HyST、ProRetrieval、MACS 在打开的文本里都没有会议页眉。这一类在一档上升温的是向量索引里的谓词执行；商品目录上的可执行 SQL 再加推荐召回，到 2026 年仍停在预印本和 CIKM 的过滤接口。

### 半结构化检索

2024 年，STaRK 以新基准进 NeurIPS Datasets and Benchmarks，SUQL 以形式语言进 NAACL Findings，KAR 和 AvaTaR 的打开版本没有会议页眉。2025 年，HybGRAG 进 ACL 主会，mFAR 进 ICLR，TAG 进 CIDR，MoR 仍无会议页眉。2026 年，SAGE / SPARK 仍无会议页眉。清单里看得到的走向是：任务定义在 2024 年进了一档的数据集轨道，混合检索系统在 2025 年有一篇 ACL 主会和一篇 ICLR，同一方向上仍把文本臂留给 BM25 或 HNSW 的系统，到 2026 年的打开版本还没有会议页眉。篇数少，四篇无页眉不能读成「这一方向被拒」。

### 无约束下一物品 / 语义 ID

2023 年 TIGER 进 NeurIPS。2024 年 EAGER 进 KDD，IDGenRec 进 SIGIR，LETTER 进 CIKM。2025 年 LLM2Rec 和 NoteLLM-2 进 KDD，LEARN 进 AAAI。生成式检索的系统论文在这四年的一档和领域会里连续出现。与此同时，Xu 等（2024 预印本）把全量交叉熵 SASRec 放到 0.0597，高于这批论文用来对照的弱 SASRec 行；Benigni 等（TORS 2026）把调过的 ItemKNN 放回扩散模型的表里。笔记留下的中稿句是语义 ID、文本 ID、LLM 编码器。「打赢微调大模型」和「打赢调好的序列模型」在批判语里留不下来。降成基线的是这句胜负。语义 ID 的系统论文在 2023–2025 年的 NeurIPS、KDD 和 SIGIR 名单里仍然有。

### 领域 Text-to-SQL

2023 年有 ScienceBenchmark（PVLDB）和 Binder（ICLR）。2024 年有 BookSQL（NAACL）、SM3（NeurIPS 数据集轨道）、Wretblad（ACL 短文）、SUQL（Findings）。2025 年有 Spider 2.0（ICLR）、H-STAR 和 FLEX（NAACL）、SQLForge（Findings）、TAG（CIDR）。2026 年有 Arctic（Findings）、BiomedSQL（COLM）、OMOP（研讨会）。执行准确率和换库基准从 2023 年排到 2026 年，一档和 Findings 都还在收。笔记的判语是：只换领域、模板填槽、再报域内执行准确率，已经是重复贡献。OMOP 的 93.55 把「域内高分」收到了合成模板上。拒答从 EHRSQL（NeurIPS 2022）走到 2024 年的 ClinicalNLP 研讨会和 TrustSQL 预印本，再走到 2026 年的 ClinicalNLP 研讨会。2024 年的 Wretblad 和 2025 年的 FLEX 收的是金标噪声和执行准确率审计，2025 年的 Spider 2.0 收的是企业工作流。主创新句从「再做一个域内执行准确率」挪到了审计和工作流难度上。

### 指标与诊断

推理型检索在这份清单里的一档年份是：QUEST（ACL 2023），然后空过 2024，FollowIR（NAACL 2025）、BRIGHT（ICLR 2025）、LIMIT（ICLR 2026）。2025–2026 的一档出现了三篇，这是清单里最清楚的一段升温，篇数仍然只有这三篇加 2023 年的 QUEST。否定和排除（NevIR、ExcluIR）停在预印本。数值约束进的是 BDMA 2026。温度 0 的非确定性是 Atil 等（2024 预印本）。可复现是 ReproRAG（Workshop ’25）。忠实性是 Faithful CoT（IJCNLP-AACL 2023）和 PCN-Rec（2026 研讨会）。诊断类里，进一档的是嵌入容量、推理型相关和指令跟随；温度 0 和集合重叠还停在预印本和研讨会。

### 关系库未来窗口

2024 年 RelBench v1 进 NeurIPS 数据集轨道。ContextGNN 的系统比较在 2024 年的这份 PDF 上没有会议页眉。2026 年 RelAgent 进 NeurIPS，ReFuGe 进 WWW 短文，v2 进 ICLR 的 DATA-FM 研讨会。一档收的是基准和特征 SQL。带用户问句、把一条 SQL 的执行结果当成购买 top-K，这一格在七年论文里都没有出现。手写共现从 2024 年的 v1 到 2026 年的 v2 都没被报过，笔记把它留成漏掉的基线。

## 5. 会议级别 × 创新点类型 × 是否占住我们的空格

空格以 `00_五步之后的网格.md` 第 3 节为准，原句是：LLM 只把已经落到边上的片段写成 SQL，数据库返回关系超集，BM25 或小编码器在商品文档上排序。

「已占住」指网格里已经标成已有的格子，或 07 写明已经贴近、不能再宣称第一次做的格子。那些格子的会议级别写在表里。我们这一格在表的最后一列保持空着。

## 6. 对我们选题的含义

ACL 主会会把这篇读成 STaRK-Amazon 上的检索协议：模型只把已经落到边上的关系片段写成 SQL，数据库返回关系超集，BM25 或小编码器在商品文档上排序，关系片段和整句分开报，人工 81 条另表。要让它看起来像一档主会的工作，创新点需要落在这一句上，并且主结果是超集再排序相对表 6 BM25（Hit@1 44.94，Recall@20 53.77，MRR 55.30）有没有差，同时用现成的谓词匹配、TARr、Jaccard 和执行审计把生成失败单独报出来。STaRK 本身已经是 NeurIPS 2024 的基准，HybGRAG 已经是 ACL 2025 主会的检索器银行，mFAR、BRIGHT、LIMIT 已经是 ICLR 的字段混合和推理型测量，SUQL 已经是 NAACL 2024 Findings 的自由文本 SQL，Spider 2.0 和 FLEX 已经是 ICLR 与 NAACL 的企业工作流和执行准确率审计。这些论文的创新点再写一遍，审稿人手里就有一档的对照。域内执行准确率、无约束语义 ID、拒答可靠性分，在这份清单的一档和 Findings 里也已经有论文占住对应的句子。

## 7. 哪些创新点已经和选题撞车

撞车指的是：审稿人可以拿下面某一句，把我们的稿子读成那篇论文的重复，或读成它在 STaRK 官方全库上的缩小复制。会议级别写在每条后面。我们仍空着的那一句，是第 5 节最后一列里保持空着的协议，不在这条清单里。

1. **物品属性上的 SQL 工具。** InteRecAgent（尚未见会议版）已经让 LLM 写硬条件 SQL，并写明不许用 SQL 找相似物品，标题不能当条件，相似物品交给 ItemCF。只做 WHERE，就是在复现这个工具。它的 Hit@5 来自知道目标的模拟器，所以它没有占住官方全库检索，但「第一次把硬条件交给 SQL」这句已经不能写。
2. **单表布尔 SQL 再接 BM25。** TalkPlay-Tools（尚未见会议版）已经把 SQL、BM25、稠密检索和 Semantic ID 串成管道。领域是合成音乐对话。商品论文若只重复这条工具链，会对上这一篇。
3. **自由文本放进 SQL，用集合精度打分。** SUQL（NAACL 2024 Findings）已经在餐馆表上做了这件事，上限 3 家，作者自己判分。主指标若改成同一种人工判定，笔记写会被看成缩小复制。
4. **Text2SQL 不够，要和检索合成。** TAG（CIDR 2025）已经把这句写成立场：关系代数只覆盖一小块，RAG 只覆盖点查。80 道改写题上的 0.55 是手写上界。再写「纯 SQL 盖不住文本，所以要混合」，对上的是 CIDR 上的这篇。
5. **STaRK 上的混合检索，检索器仍在。** HybGRAG（ACL 2025 主会）是检索器银行加评论模块，没有 Amazon 分割。mFAR（ICLR 2025）是字段上的词法加向量。KAR、AvaTaR、MoR、SAGE / SPARK（均无会议页眉）的文本臂或回退仍是 BM25、ada-002 或 HNSW。把贡献写成「在 STaRK 上做混合检索并超过 BM25」，对上的是这六篇，其中两篇已经是一档主会。
6. **先结构化过滤，再向量排序。** HyST（尚未见会议版）在 STaRK 的 76 条、3,335 件子集上做了，过滤语言是 JSON，`also_bought` / `also_viewed` 被丢掉。它的 Precision@1 0.9211 对的是这个池子里的 BM25 0.8026，对不上官方全库的 Hit@1 44.94。主实验若仍用 STaRK，笔记要求把它列为最近的公开对照，并写明池子大小。
7. **模型写 SQL，执行器返回商品，用 Hit 打分。** ProRetrieval（尚未见会议版）在 3,000 件自建商品上做了，文本和图像以占位符插进 SQL。金标准是构造出来的单篇文档。它自己的表说明只执行 SQL 低于 SQL 加文本。留出购买上的 Recall 仍没有。这是目前笔记里最接近「模型写 SQL、用 Hit 打分」的一篇。
8. **槽位或过滤接口。** MACS（尚未见会议版）把槽位映射成 `WHERE`，评的是自建目录上的通过率。Malik 等（CIKM 2024）把商品搜索句变成过滤 API，指标是 Exact Match。07 写明：不能再写「还没有人把自然语言商品请求编译成结构化过滤」。自由生成的多表 SQL，这两篇都没有占住。
9. **半结构化检索这个任务。** STaRK（NeurIPS 2024 Datasets and Benchmarks）已经定义了关系约束加文本约束、答案是图节点，并给出了表 6 的 BM25。我们用它的协议和它的基线。任务定义本身已经是一档的数据集论文。
10. **域内执行准确率、拒答、金标审计。** BookSQL（NAACL 2024）、SM3（NeurIPS 2024 数据集轨道）、Spider 2.0（ICLR 2025）、FLEX（NAACL 2025）、Arctic（ACL 2026 Findings）、SQLForge（ACL 2025 Findings）、EHRSQL（NeurIPS 2022）、OMOP（ClinicalNLP 2026）、TrustSQL（无会议页眉）已经把这些句子写过。01 的 22 篇没有推荐的 Recall、NDCG 或 Hit。主指标若退回执行准确率或拒答令牌，对上的就是这一串。
11. **无约束下一物品上打赢生成式推荐或弱 SASRec。** TIGER（NeurIPS 2023）、EAGER（KDD 2024）、IDGenRec（SIGIR 2024）、LLM2Rec（KDD 2025）已经占住语义 ID 和 LLM 编码器。Xu 等（无会议页眉）留下的是全量交叉熵 SASRec 的 0.0597。这篇若把无约束 Recall@K 放进主表，或把「超过 SASRec」写成超过调好的序列模型，对上的是这组一档论文和 Xu 的负结果。
12. **SQL 文本充当解释，或用证书保证约束。** Faithful CoT（IJCNLP-AACL 2023）把忠实定义成求解器执行了符号链，并写明翻译阶段不在保证里。PCN-Rec（LARS @ WWW ’26）把提议和确定性校验分开，并写明解释声明本身不被验证。贡献句若写成解释质量，对上的是这两篇，而且笔记写审稿人会要用户研究。
13. **关系库上的 SQL 或 GNN 当成语言贡献。** RelBench v1（NeurIPS 2024 数据集轨道）的输入是实体和种子时间。RelAgent（NeurIPS 2026）和 ReFuGe（WWW 2026 短文）的 SQL 产出特征，再接树模型。ContextGNN（无会议页眉）的 2.93 是成对 GNN 的 MAP。14 个任务各套一句英文模板，笔记写 ACL 审稿人会把它逐出语言主实验。

07 还点了名、但会议身份没有核清、因而不进第 2 节篇数的近邻：CHESS 的作者主页写成 ICML 2025 的 MAS workshop，实验室页面的 bib 仍标预印本；GenFacet 的 HTML 自称 SIGIR 2026，DOI 和 ISBN 仍是占位符。这两篇不参与撞车判定。Jannach 与 Liegl 的打开前两页没有印出会议全称，文件名是 `Conference_IEA_2006.pdf`，只作为「最小放松」的概念前身，不写成一篇已经中稿的过滤论文。
