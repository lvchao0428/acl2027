# 窗口 02：召回。选题还能否写成「模型写协同 SQL」

日期：2026-11-11。对象是 `大纲/02_召回.md` 点名的 24 篇。SIEVE 的会议版与 arXiv 是同一篇，下面只核 arXiv。RecSys 2019 与 TOIS 2021 不并成一篇。WebReco 与 EARL 是两篇，Q′ 那一组线上数字只算一次观察。

数字从 `papers/sql-recall/02-recall/` 的 PDF 文本抽取核对。相对差若由同表两格相除得到，标明是推算。谓词的具体文本按大纲不补。InteRecAgent 的用户模拟器只写「见 03，同一篇」。RecBench+、STaRK、QUEST、RelBench 不在这里重析。

这一窗口只回答：协同自连接有没有被占住，以及论文还能把哪一句写成贡献。

---

## 选题结论

能写成论文的句子只有一句：

自然语言里同时有硬谓词和协同意图时，模型写出带谓词的协同 SQL，数据库执行，在同一组谓词下同时报可行集上的 Recall、NDCG 和约束满足率。对照是三臂，不是再找一个弱 SASRec。序列臂用 Xu 等的全量交叉熵 SASRec，再套同一组谓词。平凡臂是同一条 SQL 写出来的、余弦加收缩的 ItemKNN。向量臂按 SIEVE 的后检索过滤，先搜大约 \(k/\mathrm{sel}\)，不够再翻倍。EASE 只在内存放得下时另报，并且不能把 EASE 的胜负说成自连接的胜负。

这一句现在还是空格，值得做。它值得做，是因为对照表不存在，不是因为已经知道 SQL 会赢。

不能写成主贡献的句子：

- 「第一篇让大模型写协同 SQL。」格子是空的，但写出来的算子就是 ItemKNN 或 Swing。审稿人会把它叫成 SQL 版近邻。空本身不是 ACL 贡献。
- 「无约束的下一物品上，SQL 自连接打得过或打不过全量交叉熵 SASRec 和 EASE。」这张全库排序表不在这 24 篇里。两种说法都写不了。
- 「生成式检索已经超过调好的序列模型。」主表里的 SASRec 是 S3-Rec 公开结果那一档。Beauty 上 NDCG@10 是 0.0318。Xu 等在同一用户数、同一物品数上，全量交叉熵 SASRec 的 NDCG@10 是 0.0597。
- 「过滤向量搜索在推荐约束下 Hit 低于 0.2，所以该换成 SQL。」SIEVE 和 Lim 的 recall 是向量近邻召回率。Lim 的「often below 0.2」绑在高难度、选择率大约 0.1% 或更低。
- 「属性 SQL 还没人做。」InteRecAgent 已经让模型写 SQL，并用 Recall@5 打分。提示禁止用 SQL 找相似物品。只做属性 `WHERE`，是在复现这个工具。

和另外几路的分工保持不动。本窗口不把 STaRK 收成同一张主表。语言主实验仍是关系片段写成 SQL、文档上另排。本窗口的 Beauty 和 Yelp 只负责一件事：序列臂必须用全量交叉熵这一档。模型生成 SQL 放在手写查询已经改变可行集之后。手写查询没有高出后过滤的全量交叉熵 SASRec，就停在测量，不设计新的生成算法。

## 五个问题

### 1. 模型写协同自连接，数据库执行，再用推荐 Recall 或 NDCG 打分

没有。24 篇里最接近的是 InteRecAgent。它让 LLM 写 SQL，SQL 在 SQLite 里执行，表 5 报了全库检索的 Recall@5。提示把协同赶了出去。附录原文六条：标题不能当条件；这个工具不能找相似物品；字符串列用模式匹配；SQL 里只能出现一张物品信息表；选出全部满足条件的物品，不许 `LIMIT`；尽量用 OR 而不是 AND。相似物品走 ItemCF，输入是种子标题。排序 NDCG@20 是 1 个正例加 19 个随机负例。Beauty 的一轮样本是 15,577 用户、8,679 物品、108,166 次交互、492 条，不是标准 5-core。表 5 标题写明单位是百分数：Beauty 检索 Recall@5 是 30.28，排序 NDCG@20 是 40.05。

目录外打开过机制、不另算进这 24 篇的近邻，也没有占住这一格。RecAI（arXiv:2403.06465）沿用同一套工具：SQL 管硬条件，物品到物品的嵌入管软条件。Chat-REC 把历史放进提示，候选来自外部推荐器，不是自连接。ColaRec、A-LLMRec、NLCF 把协同放进参数或嵌入。工程博客里有人用 SQL 写 ItemCF，那是工程师写死的查询，没有推荐榜上的对照表，也没有模型写查询。Spider / BIRD 上的文本转 SQL（包括 arXiv:2601.17942）打的是执行准确率，没有留出交互。

### 2. 工程师写死的物品侧共现，对照表在不在

不在。自连接写得出共现计数、余弦和收缩，也就是 Ferrari 与 Benigni 测过的那一类 ItemKNN。写不出 SLIM 的稀疏线性回归，写不出 EASE 的闭式模型，也写不出吃序列顺序的 SASRec。

这批 PDF 里的 ItemKNN 出现在矩阵式 top-n，不出现在 Beauty 留一，也不和全量交叉熵 SASRec 同表。RecSys 2019 的 Netflix 表：ItemKNN CF 的 REC@20 / REC@50 / NDCG@100 是 0.2088 / 0.3386 / 0.3086，SLIM 是 0.2551 / 0.3995 / 0.3745，Mult-VAE 是 0.2626 / 0.4138 / 0.3756。改切分后 NDCG@20 上 SLIM 0.2473，Mult-VAE 0.2448。Benigni 等的 Amazon-Books（clean）表 2：ItemKNN 的 Recall@10 / NDCG@10 / Recall@20 / NDCG@20 是 0.1133 / 0.0743 / 0.1525 / 0.0863，高于表内 DiffRec 变体；EASE 整行是空的，正文写内存超过服务器上的 64 GB。ItemKNN 用的是余弦加收缩。

用 Benigni 等证明「SQL 版 ItemKNN 没前途」，方向反了。这篇证明的是：新模型要宣称进步，至少要打过这种近邻。它没有测 SQL。

STAR 表 2 的 KNN 是 0.007 / 0.007 / 0.002。正文写的是找 10 个最相似用户再平均打分，是 top-10 UserKNN。不能当成调过收缩的 ItemKNN 很弱。

### 3. 引擎是 BM25 或搜索的那一格是不是假空

是假空。GPT4Rec 的查询是标题，引擎是 BM25。Beauty 是 22,254 用户、11,778 物品、190,726 次交互，不是 22,363 / 12,101。用户序列按 0.8/0.1/0.1 划分，序列截到 15。Recall@40：40 条查询 0.2040，BERT4Rec 0.1161，正文相对差 75.7%。Recall@10 的 0.0810 是 5 条查询，10 条查询是 0.1036。基线里没有 SASRec。PDF 页眉仍是占位会议名，不当档案版引用。

EARL 与 WebReco 的查询是网页，引擎是 Bing。Q′ 两行相同：GPT-4 的线上 CTR +0.89%、RecoDCG@5 +0.760；Mistral-7B 是 +1.71% 和 +0.762。只算一次观察。两篇都是研讨会稿。模型写的是搜索查询，不是用户–物品自连接。

### 4. 语义 ID 生成式检索是不是假空

是假空。TIGER 这一路的协同在码本或模型参数里。自回归生成离散码不是自连接。冷启动图里的 Semantic_KNN 是语义嵌入上的 k 近邻，表 1 没有 ItemKNN，也没有 EASE。

Beauty 上不要横比的对照，方向已经够用：

| 论文 | 他们表里的 SASRec，NDCG@10 或等价格 | 他们自己的方法 | 和 Xu 的 0.0597 的关系 |
|---|---|---|---|
| TIGER 表 1 | Recall@10 0.0605，NDCG@10 0.0318。来自 S3-Rec 公开结果 | Recall@10 0.0648，NDCG@10 0.0384。相对最好基线的 Recall@10 是 +0.15% | 0.0384 低于 0.0597。历史截断和交互次数不对齐，只是方向 |
| EAGER 表 2 | 同一行 0.0605 / 0.0318 | Recall@10 0.0836，NDCG@10 0.0525 | 0.0525 仍低于 0.0597。Toys 的 Recall@20 改进栏是 −3.85% |
| LETTER 表 1 | 他们重做的 SASRec，NDCG@10 0.0313 | 重做的 TIGER Recall@10 0.0610；LETTER-TIGER 0.0672 | 原 TIGER 的 0.0648 不要和 0.0610 横比 |
| IDGenRec 表 4 | 仍是 0.0605 / 0.0318 | HR@10 0.0814，NDCG@10 0.0541。评估对全体物品排序 | 0.0541 仍低于 0.0597。用户数、物品数、交互次数与 Xu 相同：22,363 / 12,101 / 198,502 |
| OneRec-Think 表 1 | 他们的 SASRec 0.0607 / 0.0320 | R@10 0.0791，N@10 0.0471。历史截到 50 | 0.0471 低于 0.0597。Toys 上他们重做的 TIGER R@10 0.0547，低于他们自己的 SASRec 0.0626 |

Xu 等表 3 的损失块把这件事写死了。Beauty 的 NDCG@10：BCE 的 SASRec 是 0.0353，BPR 是 0.0374，全体物品交叉熵是 0.0597。Yelp 的全量交叉熵 NDCG@5 / NDCG@10 是 0.0345 / 0.0415。表里没有 ItemKNN，没有 EASE。不能引用 SQL 自连接打不过它。

### 5. 带谓词的召回测过没有

没有测成推荐指标。SIEVE 测的是找回真正的 top-k 向量近邻，图是 Recall@10 对 QPS。后检索过滤的写法是：选择率 sel 时先搜 top-\(k/\mathrm{sel}\)，不够再搜 top-\(2k/\mathrm{sel}\)。低选择率的 YFCC、Paper、UQV 上，SIEVE 的 recall 可以到 0.99 以上，ACORN-γ 大约停在 0.95。引言里的儿童向视频和价格区间没有对应的推荐 NDCG。

Lim 等第 11 页附近的原句是：高难度负载上多数策略的 recall 急剧下降，often below 0.2，并说这与选择率大约 0.1% 或更低的已知困难一致。0.2 是对图的概括，不是表里的一格。数据集是 SIFT、GIST 上的合成或半真实属性。首页例子是年份和会议。不能挪到选择率是百分之几的品牌、价格或排除已买上。

SQL 的 `WHERE` 在同一谓词上是精确的。这是机制。这 24 篇没有测过它在留出交互上的推荐涨幅。

## 先导里主表长什么样

无约束的下一物品留在附录，用来说明「只把 ItemKNN 写成 SQL」在下一个物品上没有新算子。主表是带谓词的召回。谓词文本不在本窗口补。三臂必须用同一组谓词：

| 臂 | 它是什么 | 本窗口能引用的协议 | 不能写成的话 |
|---|---|---|---|
| 序列 | Xu 的全量交叉熵 SASRec，再按谓词后过滤 | Beauty NDCG@10 0.0597 只说明要用这一档损失 | 不要用 TIGER 表里 0.0318 的那一档当「调好的 SASRec」 |
| 平凡 SQL | 同一条 SQL 写出的物品侧近邻，余弦加收缩 | Benigni 等写明 ItemKNN 就是这个配置 | 不要把 EASE、SLIM、SASRec 说成这条 SQL 写得出来 |
| 向量 | 后过滤，多取倍数大约 \(1/\mathrm{sel}\)，不够再翻倍 | SIEVE 第 2.2 节的 post-search filtering | 不要把 Lim 的 0.2 写成这一臂的预期 Hit |

指标只报三列加一列审计：可行集上的 Recall、NDCG、每个已落地原子谓词是否成立，以及错误 SQL 被执行之后下游指标掉了多少。Hit、Recall、NDCG 不横比。线上 CTR 不证明某个召回算子必要。

停点沿用总览，本窗口只给理由。手写 SQL 在这三臂里没有高出后过滤的全量交叉熵 SASRec，关系谓词没有贡献，生成器救不了，这一路停。高出之后，才用 7B 或一次 API 替换手写查询，并报执行失败率和结果集抖动。

## 二十四篇

每一篇五步：论点，逻辑，隐含假设，证据，能信什么。能信的句子已经收进上面的选题结论。这里只保留核对过的格子和它挡掉的那句话。

### TIGER

Rajput 等。NeurIPS 2023。arXiv:2305.05065。

论点：用 RQ-VAE 把文本嵌成 Semantic ID，序列模型自回归生成下一个物品的 ID。实验是 Amazon 2014 的 Beauty、Sports、Toys。留一，训练历史截到 20。表 1 除 P5 外，基线来自 Zhou 等 S3-Rec 的公开结果。Beauty：TIGER 的 Recall@5 / NDCG@5 / Recall@10 / NDCG@10 是 0.0454 / 0.0321 / 0.0648 / 0.0384；SASRec 是 0.0387 / 0.0249 / 0.0605 / 0.0318；S3-Rec 的 Recall@10 是 0.0647。改进行里 Beauty 的 Recall@10 是 +0.15%。附录三次均值是 Recall@10 0.0642±0.00092、NDCG@10 0.0374±0.00061，低于主表单次。冷启动对照叫 Semantic_KNN，是嵌入近邻。

逻辑：量化成立，所以解码可以代替向量近邻。表底的转折是 Recall@10 几乎打平 S3-Rec，NDCG@5 的百分数很大。

隐含假设：表里的 SASRec 被读成强序列模型。论文自己写明那一行是公开结果。表 1 没有 ItemKNN，没有 EASE。自回归生成离散码不是自连接。

证据强度中。协议写了留一和数据来源。最好基线是抄来的，主表单次高于三次均值。

能信：在抄来的基线上，Semantic ID 的 NDCG 高于表内 SASRec，Recall@10 基本打平 S3-Rec。不能引用：已经打赢调好的序列模型，或 SQL 写不出这种召回。Xu 的 0.0597 对这里的 0.0384 只是方向。

### EAGER

Wang 等。KDD 2024。arXiv:2406.14017。

论点：行为码和语义码分两个解码器生成，再按置信度合并。表 1 的 Beauty 是 22,363 用户、12,101 物品、198,360 次交互。和 Xu 的 198,502 差一百多次交互。表 2 Beauty：EAGER 的 Recall@5 / Recall@10 / Recall@20 是 0.0618 / 0.0836 / 0.1124，NDCG@10 是 0.0525。SASRec 仍是 0.0605 / 0.0318。最后一列是相对该行最优基线。Beauty Recall@5 的 31.49% 对得上 Recforest 的 0.0470。Toys 的 Recall@20 是 0.1024，改进栏 −3.85%，同列 S3-Rec 是 0.1065。

逻辑：双流、对比、迁移是递进。四套数据不是并列的全胜。Toys 的 Recall@20 为负。

隐含假设：抄来的 SASRec 代表传统序列模型。Yelp 的 NDCG@5 改进栏印着 3.51%。同列 TIGER 是 0.0146，EAGER 是 0.0177。按相对差，(0.0177−0.0146)/0.0146 约 21%，对不上 3.51%。这一格百分数不要单独引用。没有协同 SQL。

证据强度中。表 2 自己否定了「四套数据全面更好」。

能信：在历史长度 20、多数基线抄自 TIGER 的这张表里，Beauty 的 Recall@10 高于表内最好基线。不能引用：打赢全量交叉熵 SASRec，或这和 SQL 召回有关。

### LETTER

Wang 等。CIKM 2024。arXiv:2405.07314。

论点：量化时加协同正则和多样性正则，让码本靠近 SASRec 的物品向量。后端仍是 TIGER 或 LC-Rec 的自回归生成。表 1 Beauty，列是 R@5、R@10、N@5、N@10：SASRec 0.0380 / 0.0588 / 0.0246 / 0.0313；他们重做的 TIGER 0.0395 / 0.0610 / 0.0262 / 0.0331；LETTER-TIGER 0.0431 / 0.0672 / 0.0286 / 0.0364；LC-Rec 0.0443 / 0.0642 / 0.0311 / 0.0374；LETTER-LC-Rec 0.0505 / 0.0703 / 0.0355 / 0.0418。

逻辑：码字对齐协同向量，所以两个后端的四个 Beauty 指标都升了。这是同一张重实现表里的递进，没有转折。

隐含假设：表内 SASRec 的 NDCG@10 0.0313 仍是弱行。正则对齐的那个 SASRec 没有写成全量交叉熵。原 TIGER 的 Recall@10 0.0648 和这里的 0.0610 不要横比。协同进的是量化损失。

证据强度中，只在他们的重实现上。没有强序列基线，没有多次种子。

能信：加上两项正则后，两个生成后端的 Beauty 指标都升了。不能引用：因此超过调好的 SASRec。

### LC-Rec

Zheng 等。首页未印会议名。arXiv:2311.09049。

论点：索引用 RQ-VAE，对齐任务把语言和协同一起放进 LLaMA-7B。摘要写 full ranking 上平均提升 25.5%。数据是 Amazon 2018 的 Instruments、Arts、Games，不是 2014 Beauty。正文写明对全体物品排序，不用 sample-based evaluation。表 III 的 HR@10：Games 上 LC-Rec 0.1174，表内最好基线 FDSA 0.1041，相对 +12.78%；Instruments 0.1220 对 S3-Rec 0.1136（+7.39%）；Arts 0.1266 对 S3-Rec 0.1051（+20.46%）。25.5% 是正文的平均说法，不是这三格的算术平均。

逻辑：文本方法做不了全库生成，纯语义 ID 缺协同，索引加对齐补上。表 III 没有拆开「只换 ID」和「对齐任务」各占多少。

隐含假设：表内 SASRec 在 Games 上 HR@10 是 0.0940，低于 FDSA 和 S3-Rec，没有写成全量交叉熵。数据年份和类目都不同于 TIGER Beauty。查询是生成语义 ID，执行器是 beam 20。

证据强度中。全库留一是这批生成式论文里少数写死的。25.5% 的口径和分表的 +7% 到 +20% 不是同一句话。

能信：在这三份 2018 数据的全库留一上，HR@10 高于表内最好基线。不能把「LLM 生成 ID」写成「LLM 写 SQL」。

### IDGenRec

Tan 等。SIGIR 2024。arXiv:2403.19021。

论点：用文本词当物品 ID，生成器和推荐器交替训练。表 3 的 Beauty 是 22,363 / 12,101 / 198,502。第 6 页写明评估不用负采样，对全体物品排序。表 4 Beauty 的 HR@10 / NDCG@10：IDGenRec 0.0814 / 0.0541，SASRec 仍是 0.0605 / 0.0318。

逻辑：文本 ID 按推荐损失改写，所以比整数码更会用语言模型。主表上四套数据都高于抄来的 SASRec。

隐含假设：SASRec 是弱行。NDCG@10 0.0541 低于同一用户数、同一物品数上 Xu 的 0.0597。文本 ID 是给语言模型生成的。

证据强度中。全库写明了。23.55% 这类平均提升是多个指标对各自最好基线的平均，不是单一 HR@10 的相对差。

能信：在抄来的弱 SASRec 和全库留一下，文本 ID 的 Beauty 两格更高。不能引用：已经打赢全量交叉熵 SASRec。

### OneRec-Think

Liu、Wang 等。首页未印会议名。arXiv:2510.11639。

Ren 等。arXiv:1812.02646，带 AAAI 2019 版权行。

论点：会话推荐里显式分开重复和探索。表 3 单位是百分数。DIGINETICA 的 Recall@20：去掉重复机制 42.56，RepeatNet 47.79，NARM 49.70。47.79 没有显著性标记。同表 Item-KNN 的 DIGINETICA Recall@20 是 35.75。正文写这个 Item-KNN 的相似度是会话里的共现次数，不是 Ferrari 那种调过收缩的全库 ItemKNN。

逻辑：消融掉重复头之后 Recall 下降。DIGINETICA 上 RepeatNet 仍低于 NARM，所以消融涨了，并不等于打赢当时的会话模型。

隐含假设：绝对 Recall 远高于 Amazon 留一，是会话推荐的尺度。历史过滤可以用 SQL 写精确集合。这是机制，不是这张表的胜负。

证据对「重复头相对自己的探索支路有用」中等。对「打赢会话推荐」弱。

能信：先导里报重复物品的命中时，对照应包括「只做集合过滤」的 SQL。不能引用：47.79 是要超越的 SOTA。

## 候选题目

按本窗口的证据，三档。

**做。** 带谓词的召回测量。题目写成：同一组已经落到列或边上的谓词下，精确 SQL、后过滤的全量交叉熵 SASRec、以及大约按 \(1/\mathrm{sel}\) 多取的向量，谁改变可行集上的 Recall 和约束满足率。模型写 SQL 是第二阶段。第一阶段是手写查询。平凡臂必须是调过收缩的 ItemKNN，让审稿人无法说基线没调。序列臂必须是 Xu 这一档，让审稿人无法说 SASRec 用的是 2018 年的 BCE。向量臂必须写明多取倍数，让审稿人无法把 Lim 的 0.2 塞进这张表。

这篇的贡献是这张表本身。表现在不存在。负结果也有资格写成测量：若三臂打平，结论是谓词没有给 SQL 留下超出后过滤的空间，生成器不用做。这和两周先导的停点是同一件事。

**可以放进同一篇，但不能当主句。** 温度 0 下 SQL 字符串和结果集是否稳定，以及错误 SQL 被执行的代价。这是生成阶段的审计。手写查询还没赢，审计没有对象。

**不做。**

| 题目形态 | 本窗口把它挡下的理由 |
|---|---|
| 无约束下一物品上，LLM 写 I2I 自连接，主指标是 Recall@K | 写出来就是 ItemKNN。和全量交叉熵 SASRec、EASE 的对照表不存在。既不能宣称赢，也不能把「第一篇」当贡献 |
| 用 TIGER、EAGER、IDGenRec、OneRec-Think 当「已超过 SASRec」的对手 | 他们表里的 SASRec 是 0.0318 那一档。Xu 的全量交叉熵是 0.0597 |
| 用 SIEVE 或 Lim 证明推荐约束下向量 Hit 会塌到 0.2 以下 | 两篇的 recall 是向量近邻。0.2 绑在约 0.1% 或更低的高难度档 |
