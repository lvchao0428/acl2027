# 02 召回

日期：2026-11-11。本窗口回答协同自连接有没有被占住。24 篇里 SIEVE 两份只留 arXiv。InteRecAgent、SIEVE 归这里。输出写到 `proposal/sql-recall/deep/reanalysis/window-02.md`。

## 这个窗口要回答的问题

1. 物品到物品共现、由模型写 SQL 且数据库执行：有没有一篇已经写出协同自连接或物品–物品聚合，再用推荐的 Recall 或 NDCG 打分？网格标成空着且值得做。InteRecAgent 的提示禁止用 SQL 找相似物品，不能把这一篇算成占住了这一格。
2. 工程师写死的物品侧共现：自连接写得出调过收缩的 ItemKNN，但这张对照表在不在？网格标成空着且值得做，并写这张表不存在。
3. 引擎是 BM25 或搜索的那一格是不是假空？GPT4Rec 和 Q′ 的查询是标题或网页，不是协同自连接。
4. 语义 ID 生成式检索是不是假空？TIGER 这一路的协同在参数里；冷启动的 Semantic_KNN 是嵌入近邻，不能代替调过的 ItemKNN。
5. 带谓词的召回还没测。序列臂用 Xu 的全量交叉熵，再套同一组谓词；平凡臂是同一条 SQL 写出来的、调过收缩的 ItemKNN；EASE 只在内存放得下时另报；向量臂按大约 1/sel 多取。谓词的具体文本五份文件没有列出，本窗口不要补。

## 不要做的事

- 不要写「SQL 自连接已经输给全量交叉熵 SASRec 和 EASE」。这张全库排序表不存在。
- 不要把 EASE 的胜负说成自连接的胜负。EASE 不是一条 `GROUP BY` 自连接。
- 不要用 Benigni 等证明「SQL 版 ItemKNN 没前途」。方向反了。
- 不要把无约束的下一物品放回主表。主表放带谓词的召回。
- 不要把「超过 SASRec」写成超过调好的序列模型。生成式检索主表里的 SASRec 是 S3-Rec 公开结果那一档。
- 不要把 Hit、Recall、NDCG 横比。SIEVE 和 Lim 的退化是近邻 recall，不是推荐 NDCG。线上 CTR 不证明某个召回算子必要。

## 交给这个窗口的写法

对上表每一篇按五步写完，不要跳步：（1）逐段提取核心论点和论据（2）论点之间的因果、递进、转折、并列（3）未明说的隐含假设（4）证据强度和推理漏洞（5）最终结论。数字从 PDF 抄。输出写到 `proposal/sql-recall/deep/reanalysis/window-02.md`。不要重析归 01、03、04、05 的论文。RecBench+、STaRK、QUEST、RelBench 都不在这里。InteRecAgent 的模拟器细节只作指针，写「见 03，同一篇」。
