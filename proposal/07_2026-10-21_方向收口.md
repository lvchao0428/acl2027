# 2026-10-21 方向收口

> 阶段仍是选题。距 ARR **2027-01-04** 约 10 周。
> 硬条件（2026-10-21）：人不在公司，没有业务场景、没有平台日志、没有公司机器。实验只用公开数据集，算力是自己的 5090 加上自行租用的单张 A100。可以花个人预算调用闭源 API。
> 这篇只回答：在这个条件下，Agent × RecSys 还剩哪几个方向。

## 0. 留下的方向

| 顺序 | 方向 | 决定 |
|---|---|---|
| 1 | **后悔标签反转的受托 agent** | **做这一篇** |
| 2 | **模拟器当训练奖励之后的失真** | 不并行。方向 1 在造题阶段失败再切换 |
| — | 拒绝下单 | 不单独成篇，作为方向 1 的第三个动作 |
| — | 理由与选择不一致、买卖双方博弈、负反馈序列推荐 | 这次调研后排除 |

一句话：用户委托 agent 选一件商品。用户后来打了 5 星，选中那件算对；打了 1–2 星，选中那件算错。现有购物 agent 的训练把「买下了」当成对，包括 2026 年 8 月的 LOFA。

这个条件排除的是「接公司场景」的论文，不是这两个方向本身。LOFA、AlignUSER、负反馈的在线实验都依赖平台日志或线上 A/B，做不了，只引用。留下的两篇都用别人已经公开的记录当标准答案：方向 1 用 Amazon 的购买和星级，方向 2 用 ReDial、INSPIRED、Reddit-Movie 里的真人对话。不招募用户，不部署购物 agent，不写线上提升。

星级是公开评论里的事后分数，不是我们观察到的一次真实委托。论文里把这句写成局限，不把它说成线上满意度。

## 1. 六个角度，以及 10 月 10 日之后新看到的论文

### 角度 A　后悔标签反转（留下）

**问题。** agent 替这个用户选的时候，该不该复现他后来后悔的那次购买。

**新的邻近工作。**

| 论文 | 它把什么当成对 | 为什么还没占住这个角度 |
|---|---|---|
| LOFA（arXiv 2608.11604，人大 / 京东） | 购买结果 \(i^\*\) 是可验证奖励，RL 的目标是把买下的商品排得更靠前 | 用的是平台私有对话日志。购买即成功，**没有按事后星级把购买拆开**。一个人复现不了他们的数据，但可以把他们的标签当成要反驳的做法 |
| RecPO（ACL 2026） | 下一个交互；另有 Avoidance Rate，避开用户**未来**会打低分的物品 | 任务是序列推荐，不是「带着一句购前需求，从 10 个候选里替他选」。低分物品是后来仍然发生的交互，不是「这次购买本身就是错的」 |
| CoNRec（arXiv 2601.15721） | 预测下一次负反馈，用来过滤不该推的物品 | 推荐器的负反馈建模，不是受托 agent |
| *Learning from Negative User Feedback*（arXiv 2308.12256） | 序列召回里对负反馈加 not-to-recommend 损失 | 同上，且是工业在线实验，没有委托场景 |
| *Personalization Matters*（arXiv 2610.11375，2026-10-08） | 对话轨迹的 LLM 打分 | 没有真实购买和星级 |
| Spotify position paper（RecSys 2026） | 无实验 | 只提供「用 regret 而不是点击来评测」的议程 |

**还空着的句子。** 同一次真实购买，星级高则命中，星级低则避开。模拟器因为要模仿用户，在低星上应当更常踩中。LOFA 一类方法因为奖励的是购买，也会踩中。

**没有公司资源时怎么做。** 数据只用 Hugging Face 上公开、免申请的 Amazon Reviews 2023、UserMirrorer 和 OPeRA。Amazon-C4 只校验改写器。不下载全量进仓库，在租来的机器上流式抽取 3–4 个品类。泄漏检查用规则加两个 LLM，作者自己抽看约 50 条。四个角色里，两个闭源模型走 API，其余用本地或租来的卡推理。训练是 Qwen3-4B/8B 的 LoRA DPO：租到单张 A100 80GB 就用它；租不到就只训 4B，评测仍用 5090 和 API。不做 GRPO，不复现 LOFA 的日志。OPeRA 只作小对照。

**会失败的地方。** 改写把「用两周就漏了」留在需求里；或者前沿模型本来就避开低星商品。前者停在 10 月的造题检查，后者停在四角色对照。失败就换方向 2。

### 角度 B　模拟器奖励的失真（备选，不并行）

**问题。** 用模拟器 A 的打分去优化推荐 agent，换到模拟器 B 或留出的真人对话上，成绩掉多少。

**仍空着。** SMTPO、ShopSimulator、LOFA 都在用模拟器或日志奖励做 RL。Sim2Real、SimEval-IR、Turing-RL 证明了模拟器不可靠，但都不在推荐的训练闭环里。ReDial、INSPIRED、Reddit-Movie 公开。

**不现在做的原因。** 和方向 1 抢同一段时间、同一张个人能租到的卡。方向 1 的造题如果泄漏压不下去，再改做这个。优化只用 best-of-n 重排加少量迭代 DPO，不用 GRPO，也不用 ShopSimulator 那套需要多卡的环境。LOFA 的平台日志不在这个备选里。

### 角度 C　拒绝下单（并进方向 1，不单独写）

*Does Rank Still Matter?*（arXiv 2608.22697）在酒店搜索里看到：人有约三分之一的会话不下单，被测的 LLM agent 几乎总是下单，选择还集中在少数没有被支配的房源上。

这和后悔是同一件事的两个动作。低星购买上，合格的受托人可以另选一件，也可以拒绝。单独写一篇会变成「agent 过于服从」，酒店场景已经被他们做了，而且没有这个用户的事后满意度。方向 1 的动作空间留一个 `abstain`。主文先报「避开率」，`abstain` 作为消融，时间不够就放附录。

### 排除的三个角度

| 角度 | 已经有谁 | 排除原因 |
|---|---|---|
| 书面理由和真实选择不一致 | *Behavioral Fabric*（arXiv 2601.16356）写了推理里提到价值、行动却跟着折扣走；ACES、*Does Rank Still Matter?* 测量了位置和属性 | 再做一轮「理由不可信」是分析笔记，不是一篇 ACL 论文。方向 1 可以在附录里看理由有没有提到被调换的位置 |
| 卖家 agent 改文案来操纵买家 agent | ACES 的卖家 agent、SafeGEO、GEO-Bench、STS | 攻击和防御都有人做了 |
| 负反馈序列推荐 | CoNRec、RecPO 的 Avoidance、not-to-recommend 损失 | 任务是预测下一个物品，不是受托选择。只在相关工作里划界 |

偏好澄清、面向 agent 的商品表示、推理加 GRPO，10 月 10 日已经排除，这次没有看到使它们变空的证据。GRPO 推荐器仍然要多卡。

## 2. 方向 1 的边界（避免又写成零件拼盘）

零件照旧借用：BLaIR 的评论改写、Mirroring Users 的 SFT+DPO、RecPO 的按分差加权、ACES 的位置打乱、OPeRA 的真人会话。

本文独有的对象只有一个：**同一次购买的星级决定这个选择该不该被复现。**

和最接近的三篇对照着写进引言：

- 对 LOFA：你们把购买当奖励，所以低星购买会被学进去。
- 对 RecPO / CoNRec：你们避开的是另一次交互里的低分物品，不是这一次委托里用户已经买错的那件。
- 对 Mirroring Users：模拟器应当复现低星购买；受托人应当避开。两者用同一批题，才能看见这个差别。

## 3. 定题之后的第一段工作（还没开始）

1. 选 3–4 个 Amazon 品类，流式读取，不把全量放进仓库。
2. 5 星和 1–2 星用同一个改写器。两个 LLM 都认为需求里没有使用结果才保留。
3. 作者抽看约 50 条。
4. 若泄漏后 1–2 星不足约 1,000 条，或一个检索基线已经接近大模型，停止方向 1，改方向 2。
