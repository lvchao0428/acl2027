## 0. 一页摘要

| 项目 | 内容 |
|---|---|
| 暂定题目 | **When Agreeing Is Wrong: Training LLM Shopping Delegates on Post-Purchase Satisfaction**（备选：*Don't Repeat My Mistakes*） |
| 一句话 | 用户把一次购物交给 agent。用户事后打 5 星的购买，agent 选中才算对；打 1–2 星的购买，agent 选中算错。现有工作都把「和用户的购买一致」当成对 |

## 1. 方向：只回答一个问题

**问题。** agent 替**这个用户**从一组候选里选一件商品时，它选的是不是这个用户事后会满意的那件。

**操作定义。** 一道题来自一次真实的 verified 购买 \(i^\*\) 和它的事后星级 \(r^\*\)：

- 满意型（\(r^\*=5\)）：好受托人**选中** \(i^\*\)。
- 后悔型（\(r^\*\le 2\)）：好受托人**避开** \(i^\*\)，改选一件同样满足购前需求的替代品。

**不回答的问题。** 推荐器会不会推理；agent 能不能走完下单流程；没有个人偏好时 agent 被位置、赞助拉偏多少（ACES 已做）；agent 该不该自动下单（*Preference Is Not Permission* 已做，见第 2.2 节）；平台如何同时服务人和 agent。

### 1.1 为什么是这个方向

- 2026 年 ACL 推荐方向的主线是推理加 GRPO（OneRec-Think、ReRec、ROS、HARPO、ShopSimulator），要 4–8 张 A100 和工业数据，一个人做不了。
- 关键词统计（`analysis/keyword_stats/关键词统计.md`）显示 2026 年 ACL 推荐摘要里 agent（39%）、shopping / e-commerce（31%）、benchmark（44%）都在快速上升。题目落在 agent × 购物，方向是对的；但「又一个购物 benchmark」已经拥挤，所以卖点只能是标签，不是环境。
- 在仓库整理的 ACL 2024–2026 共 127 篇摘要（建议通读 73、相邻 31、关键词撞车 23）里检索 regret、dissatisf、post-purchase、delegat，没有一篇按事后满意度拆开同一次购买。
- Spotify 的 position paper（arXiv 2609.11945）把「用 regret 而不是点击评测」列为议程，没有实验。

## 2. 基本想法

### 2.1 核心洞察：同一次购买，星级决定该不该复现

| 谁 | 目标 | 在后悔型题上应当 |
|---|---|---|
| 用户模拟器（Mirroring Users、AlignUSER、OPeRA 的评测） | 复现这个人，包括他的错 | **选中** \(i^\*\) |
| 用购买当奖励的购物 agent（LOFA） | 把买下的商品排前面 | **选中** \(i^\*\) |
| 无条件买家（ACES 式 prompt） | 替典型消费者挑 | 不一定避开；避开也不是因为这个用户 |
| **受托人（本文）** | 服务这个人的利益 | **避开** \(i^\*\) |

前三行在满意型题上和受托人表现相同，只有后悔型题能把它们分开。所以 benchmark 必须同时有两类题，并且用同一个改写器造题。

### 2.2 和最近邻的区别（写进引言）

| 工作 | 它把什么当成对 | 本文的差别 |
|---|---|---|
| LOFA（arXiv 2608.11604，人大 / 京东） | 以成功购买的 \(i^\*\) 为目标，用 NDCG@10 作 GRPO 奖励 | 购买即成功，低星购买也会被学进去。他们用平台私有日志，本文只引用，不复现 |
| RecPO（ACL 2026） | 下一个交互；Avoidance Rate 避开**未来**会打低分的物品 | 序列推荐，避开的是另一次交互。本文避开的是**这一次委托里用户已经买错的那件** |
| CoNRec（arXiv 2601.15721）、not-to-recommend 损失（arXiv 2308.12256） | 预测负反馈并过滤 | 推荐器的负反馈建模，没有「带着需求替人选」的委托场景 |
| Mirroring Users（ACL 2026） | 预测用户会选什么 | 本文把它当对照臂：它应当在后悔型上复现踩雷 |
| ACES（WWW 2026）、*Does Rank Still Matter?*（arXiv 2608.22697）、*A Cue's Hidden Price*（arXiv 2610.25843） | 无具体用户；测位置、标签、卖家线索的因果效应 | 没有这个用户的购买和星级。本文最多保留一个位置打乱探针 |
| **Preference Is Not Permission**（arXiv 2610.29216，ZOZO，**2026-10 新出**） | 该「不买 / 先确认 / 自动买」；标签来自 15 名标注者扮演委托人；同样用 Amazon Reviews 2023 的 verified 购买和历史 | **最近的邻居**。它问「能不能下单」，本文问「选哪件」；它的标签是人工授权判断，并且明确**不用星级**，本文的标签是用户本人的事后星级。因此 07 号文档里的 `abstain` 动作降为附录消融，避免和它撞车 |
| *Personalization Matters*（arXiv 2610.11375） | 多 agent RAG 购物对话，LLM 打分 | 没有真实购买和星级作 ground truth |
| HORIZON（ACL 2026 Findings） | 用 Amazon Reviews 重构跨域、跨时间的用户建模基准 | 预测用户行为，不区分满意与后悔。可在相关工作里说明「同一数据源，不同标签」 |
| *Lost in Simulation*（ACL 2026）、*Mind the Sim2Real Gap*（arXiv 2603.11245） | 模拟用户在 τ-bench 零售任务上不可靠 | 支持「模拟器不是受托人」的动机；本文不招人复刻 |

### 2.3 假设

- **H1（差距存在）**：前沿 LLM 受托人在满意型上的 Hit@1 明显高于随机，但在后悔型上仍有可观比例选中 \(i^\*\)。
- **H2（受托 ≠ 模拟）**：UserMirrorer 在后悔型上的踩雷率显著高于受托 prompt 的同尺寸模型；在满意型上两者接近。
- **H3（个人信息有用，但只在个人踩雷上）**：给受托人加该用户的历史后，「个人踩雷」层的避开率上升；「公共踩雷」层（商品本身均分就低）不需要历史也能避开。
- **H4（训练能关差距）**：反转 DPO 训练的 4B/8B 模型，后悔型避开率提升，满意型 Hit@1 不显著下降。只做 SFT 或只用「购买即正例」的 DPO（LOFA 式标签）做不到这一点。

H3 决定这篇是「个性化受托」还是「挑好商品」。如果个人踩雷层的避开率和历史无关，论文退化为商品质量判断，见第 8 节停题条件。

## 3. 任务与 benchmark 构造（DelegateBench）

### 3.1 一道题长什么样

输入：购前需求 \(q\)、该用户在购买时间 \(t\) 之前的最近若干条评论 \(H_u\)、10 张商品卡 \(C\)（含 \(i^\*\)）。输出：选定 1 件，附一句理由。

### 3.2 构造流程

1. **抽样**：在租来的机器上流式读取 Amazon Reviews 2023 的 3–4 个品类，只保留 verified、正文不少于 100 字的评论。5 星进满意型，1–2 星进后悔型，3–4 星不用。
2. **踩雷原因过滤（新增）**：1–2 星里有大量物流、发错货、假货、到手损坏的抱怨，这些购前无法预判，agent 也无从避开。用 LLM 把差评原因分成「属性不符 / 质量不达预期」和「物流 / 随机缺陷」，只保留前者，报告剔除比例。
3. **同一改写器**：满意型和后悔型都用同一个 prompt 改写成第一人称购前需求，只保留「我想要什么」，删掉使用结果。用 Amazon-C4 校验改写器：对 C4 原评论重新改写，比较长度和风格分布。
4. **泄漏检查**：关键词规则（漏、坏、退货、失望、after two weeks 等）加两个不同厂商的 LLM 判断「需求里是否透露了使用结果」，两者都通过才保留，报告一致率和剔除率。作者自己抽看约 50 条。
5. **候选集**：同细分品类里 embedding 检索，再用 LLM 核验每件都满足 \(q\) 的硬约束，\(K=10\)，含 \(i^\*\)。价格档、品牌、均分刻意分散。
6. **商品卡**：标题、价格、均分、评论数、3 条要点、2 条他人评论。**均分和评论数用 \(t\) 之前的评论重算**，元数据里的 `average_rating` 和 `rating_number` 是爬取快照，含未来信息；价格无法回溯，写进局限。卡片不出现该用户自己的评论。
7. **分层（新增）**：后悔型按 \(i^\*\) 在 \(t\) 前的均分分两层。
   - 公共踩雷：\(i^\*\) 均分低于候选中位数。按均分挑就能避开。
   - **个人踩雷**：\(i^\*\) 均分不低于 4.0，别人大多满意，这个用户不满意。主结论放在这一层。

   满意型同样按 \(i^\*\) 是否为候选里均分最高的那件分层，防止「挑最高分」就能拿满分。
8. **规模**：评测满意型 3,000、后悔型 1,500（其中个人踩雷目标不少于 500）；训练另造约 3 万道。按用户和时间切分，评测集用户不进训练集。

### 3.3 每道题都要报的 sanity 基线

随机、挑 \(t\) 前均分最高、挑评论数最多、BM25 / BLaIR 按 \(q\) 检索、SASRec 或只看历史的 LLM（看不到 \(q\)）。如果「挑均分最高」在个人踩雷层上的避开率就接近前沿模型，说明分层没有起作用。

## 4. 可能的技术

### 4.1 测量：四个角色答同一批题

| 角色 | 看到什么 | 实现 |
|---|---|---|
| 受托人 | \(q\) + \(H_u\) + 候选；prompt 写明「替这个用户选他事后会满意的」 | 2 家厂商的闭源前沿模型；Qwen3-4B/8B/32B（4-bit）、Llama-3.x-8B；本文训练的小模型 |
| 模拟器 | \(H_u\) + 候选；「预测这个用户会买哪件」。不告诉它 \(i^\*\)（PEPPER 指出的猜谜问题） | UserMirrorer-Llama/Qwen-DPO（3B） |
| 无条件买家 | 只有品类、\(q\) 和候选；「给一个典型消费者挑」 | 与受托人同一批模型 |
| 历史排序器 | 只有 \(H_u\)，没有 \(q\) | SASRec、历史-only LLM |

两种条件：有 / 无 \(H_u\)。每道题打乱候选顺序 3 次，报告均值和位置敏感度。闭源模型先跑 200 道估算费用，再跑全量。

### 4.2 方法：满意度加权、后悔反转的 DPO

**第 1 步 SFT。** 强模型在已知答案的情况下写选择理由（Mirroring Users 的做法），按自一致性过滤后训练 Qwen3-4B/8B LoRA。已知答案时，后悔型的理由要指向替代品，而不是 \(i^\*\)。

**第 2 步 偏好对。** 对每道训练题 \(x=(q,H_u,C)\)：

- 满意型：\(y_w=i^\*\)，\(y_l\) 为难负例（检索排名最高的非 \(i^\*\)，或 SFT 模型自己选错的那件）。
- 后悔型：\(y_w=a(x)\)，即 \(C\setminus\{i^\*\}\) 中满足 \(q\)、\(t\) 前均分最高且评论数不少于阈值的那件；\(y_l=i^\*\)。

**损失。**

\[
\mathcal{L}=-\,\mathbb{E}_{x}\Big[w(x)\,\log\sigma\Big(\beta\big(\log\tfrac{\pi_\theta(y_w\mid x)}{\pi_{\text{ref}}(y_w\mid x)}-\log\tfrac{\pi_\theta(y_l\mid x)}{\pi_{\text{ref}}(y_l\mid x)}\big)\Big)\Big],\qquad w(x)=\frac{|r^\*-3|}{2}
\]

5 星和 1 星权重为 1，2 星为 0.5。变体：把 \(w\) 放进 RecPO 式的自适应 margin，而不是乘在损失外面。

**第 3 步 一致性正则（可选）。** 同一道题的扰动副本（打乱位置、给干扰项加 [Sponsored]）应选同一件，用两副本选择分布的对称 KL 作正则。时间紧时砍掉。

**关键消融。**

| 设置 | 标签 | 用来说明 |
|---|---|---|
| SFT only | 无偏好对 | 差距不是靠多看数据关掉的 |
| 购买即正例 DPO | 后悔型也是 \(i^\*\succ\) 其他（LOFA 式） | 这是要反驳的做法，应当在后悔型上变差 |
| 反转 DPO（本文） | 见上 | 主结果 |
| 反转 DPO − 历史 | 训练和评测都去掉 \(H_u\) | 对应 H3 |
| + `abstain` 动作 | 后悔型允许拒选 | 附录。和 *Preference Is Not Permission* 的差别在于标签来自真实星级 |

不做 GRPO：单张 A100 做不动，且 DPO 已足以检验 H4。

### 4.3 指标

| 指标 | 定义 |
|---|---|
| Hit@1（满意型） | 选中 \(i^\*\) 的比例 |
| Regret-Avoidance（后悔型） | 没选 \(i^\*\) 的比例，分公共 / 个人两层报告 |
| Chosen-Quality（后悔型） | 所选商品在 \(t\) 前的均分；防止「随便选一件别的」也算避开 |
| Constraint Satisfaction | 所选商品是否满足 \(q\) 的硬约束；两家 LLM judge，报一致率 |
| Delegation Score | \(\tfrac12\)(Hit@1 + 个人层 Regret-Avoidance)，主表的单一数字 |
| Position Sensitivity | 3 次打乱之间的选择一致率 |

Hit@1 是固定 10 个候选上的选择准确率，不是全库召回，论文里写明（Krichene & Rendle 的提醒）。

## 8. 风险与停题条件

| 如果出现 | 说明 | 动作 |
|---|---|---|
| 改写后的后悔型需求仍透露使用结果 | 避开 \(i^\*\) 变成阅读理解 | 收紧 prompt 再过滤一轮；仍不行就停后悔型，切备选 |
| 差评多为物流 / 随机缺陷，过滤后剩得太少 | 后悔不可预测 | 增加品类，或放宽到 2–3 星并单独报告 |
| 「挑均分最高」在个人踩雷层接近前沿模型 | 个人踩雷层没有分出来 | 收紧阈值（\(i^\*\) 均分 ≥ 4.3 且评论数 ≥ 50）；仍不行就停 |
| 有无历史在个人踩雷层上没差别（H3 不成立） | 这是质量判断，不是个性化 | 主张改写成「受托人不该复现购买」，降低个性化的分量，投 Findings |
| 训练只提高 Hit@1，避开率不变（H4 不成立） | 学到的是模仿购买 | 退回 benchmark + 分析 |
| 同期工作抢先 | 这条线 10 月已有 *Preference Is Not Permission* | 11 月底前挂 arXiv 预印本（投稿前核对 ARR 匿名政策）；引言写清「选哪件 vs 能不能下单」 |
| 审稿人质疑星级只是噪声代理 | 是真的 | 写进 Limitations：星级是公开评论的事后分数，不是观察到的委托；未写评论的购买不可见；离线结论不等于线上满意度 |
