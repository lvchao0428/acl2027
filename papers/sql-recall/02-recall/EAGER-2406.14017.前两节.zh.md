## 摘要

生成式检索把序列推荐里的候选召回写成自回归生成：模型直接吐出物品标识，而不是先学向量再做近邻搜索。已有工作通常只吃行为序列，或只吃物品的文本/视觉语义，两边的互补被丢掉。EAGER 要在同一个生成框架里同时用这两类信息，并点出三件必须分开处理的事：两种特征如何共用一套生成结构、每一路如何学得够且不互相干扰、以及如何做很轻的交叉而不是早融合。

对应的设计是三块。双流生成：共享编码器读用户历史，两个解码器分别生成行为 token 和语义 token，推理时用各路预测的置信度做排序合并。全局对比：在码序列上加 summary token，让解码器除了逐 token 生成，还具备对整段码的判别能力。语义引导迁移：用重建和估计两类目标，把语义侧的全局信息间接传给行为侧。作者称在四个公开基准上优于已有方法，代码将放到 PapersWithCode.com。摘要没有给出具体指标数字。

## 1 INTRODUCTION

这一节的主张是：推荐召回长期把「表示学习」和「索引」拆开做，生成式检索把两步收成端到端，但现有生成式推荐仍然只用行为或只用语义。传统流程先用双塔或序列模型把用户和物品映到同一空间，再用 Faiss、SCANN 做近似最近邻。两段各自优化，整体效果受限。树索引把匹配模型和树结构一起训，推理效率受树结构拖累，物品语义也用得有限。生成式检索改成：把物品 \(x\) 切成离散码 \(C=\{c_1,c_2,\ldots\}\)（文中 code 与 token 互换使用），用 Transformer 一类的编码器–解码器当索引。编码器读交互历史 \(\{x_1,\ldots,x_{t-1}\}\)，解码器自回归写出下一物品 \(x_t\) 的码序列 \(C_t\)。Fig. 1 画的就是这条链路。

缺口在信息来源。行为信息来自用户–物品交互；语义信息来自文本或视觉描述。RecForest 用预训练 DIN 抽行为嵌入再造码，TIGER 用 Sentence-T5 从文本抽语义嵌入。行为序列更贴用户偏好，语义（可借助 BERT、ViT 这类预训练模态编码器）更少受单一领域交互偏置影响，适合跨域泛化。作者认为两边互补，但特征空间不同，在编码器侧做特征融合并不合适，先前双塔工作已经显示过这种早融合的困难。

EAGER（two-strEAm GEnerative Recommender）因此把协作拆成三步，而不是合成一个向量。架构上为行为和语义分别造码，共享编码器只负责历史，两个解码器各自接受一路监督，避免过早交互；推理时用各流预测熵当置信度，再合并排序。学习上，逐 token 自回归偏局部，所以在序列末尾加 summary token，用全局对比去对齐预训练编码器里的物品表示，让解码器同时具备生成和判别。交互上，另设语义引导的迁移：语义可以指导行为；辅助 Transformer 有两个目标，一是用全局语义特征预测被掩掉的行为 token（重建），二是判断某个行为 token 是否对得上给定的全局语义特征（识别）。节末把贡献收成三点：行为–语义协作的生成式推荐框架、上述三个模块，以及在四个公开基准上同时超过生成式和传统方法。四个基准的名字和指标不在本节。

## 2 RELATED WORK

相关工作分成序列推荐和生成式检索两条线，用来把 EAGER 放在「端到端索引」而不是「再做一个 ANN」上。序列推荐一侧，GRU4REC 用 GRU 建模序列，SASRec 用接近 decoder-only Transformer 的自注意力，BERT4Rec 把掩码语言建模搬到推荐，\(S^3\)-Rec 在掩码之外用四项自监督任务预训练用户和物品嵌入。这些方法取下一物品时仍依赖近似最近邻索引（如 Faiss）。树方法另开一路，RecForest 建多棵树，并用 Transformer 做路由。TIGER 则引入 semantic id：物品由侧信息变成一组 token，再按 seq2seq 预测下一物品的 token。作者在这里把本文的增量说清楚：继续用生成模型当 top-k 检索的端到端索引，但改成双流。

生成式检索被概括成两段：离散语义切分，以及自回归生成标识符。文档检索里，DSI 和 NCI 用 T5 生成层次化文档 ID；SEAL（骨干为 BART）和 ULTRON（T5）用标题或子串当标识；AutoTSG 用 term-set。跨域例子包括 IRGen 用基于 ViT 的模型做图像搜索，TIGER 用 T5 做推荐。作者指出这些工作共同的限制是依赖预训练语言模型，放到推荐里的大规模物品检索上开销大。本节没有实验数字或表。结尾的定位是：本文要在推荐场景的生成式检索里同时纳入行为与语义，而不是只更换一种文档标识符。
