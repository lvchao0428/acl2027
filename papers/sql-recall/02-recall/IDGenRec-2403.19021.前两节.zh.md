## 摘要

生成式推荐把排序换成 text-to-text，但推荐物品不是自然语言词表里的词。现有工作还没找到一种又短、又有语义的 ID，能把物品放进这个生成框架，所以 LLM 推荐的潜力仍大多没被用上。IDGenRec 为每个物品学一个独特、简短、语义丰富、且不绑平台的文本 ID，token 来自人类语言。做法是让一个文本 ID 生成器和基于 LLM 的推荐器一起训练，使个性化推荐能嵌进自然语言生成。

用户历史因此用自然语言写出，并和原数据集解耦。作者认为这打开了基础生成式推荐模型的可能。标准序列推荐设定下，框架稳定超过已有模型。他们又用该方法在来自 19 个数据集的数据上训练基础模型，再在跨平台的 6 个未见数据集上做完全 zero-shot。摘要称，这个预训练基础模型的零样本表现可以比得上、甚至好于一些靠监督训练的传统推荐模型。摘要没有给出具体指标数字。

## 1 INTRODUCTION

引言把生成式推荐的瓶颈从「会不会生成」改写成「物品如何变成语言 token」。用户历史写成文本提示，目标推荐也用自然语言生成；但平台上的物品是不断增长的独立实体，编码成 Item ID 才是推荐特有的问题。P5 给物品分配词表外的数值 token，长度固定，大致按在数据集里出现的顺序编号，例如第一件是 1001、第二件是 1002。后续工作考察了不同的数值 ID 初始化。作者认为这类 ID 丢掉了物品文本里的语义，也用不上 LLM 预训练得到的语言知识；数字本身没有上下文，模型学到的是数据集内部的共现，而不是物品的一般特征，知识不能跨数据集迁移，也就没有对未见数据的 zero-shot，基础推荐模型因此做不出来。

对照问答和机器翻译：知识落在有限词表里，基础模型才能从大语料学到可迁移的东西。若推荐物品也完全由预训练 LLM 本来就会处理的自然语言 token 表示，再在推荐语料上训练，模型才可能学到真正的推荐知识。理想 ID 被收成三条：由预训练 LLM 原有 token 组成；有意义、信息足、适合推荐；短而且唯一。现成的物品信息满足不了这三条，所以要另训一个 ID 生成器。它本身也是语言模型，输入物品的全部文本元数据，输出合格的文本 ID。用户历史和目标物品于是不再含「没有上下文的」token。同一个生成器还可以把历史里所有物品的文本收成一个用户 ID，当作偏好的高层画像；这一步可选，消融放在后文实验。Figure 1 是生成器从纯文本元数据抽出抽象文本 ID；Figure 2 是整条生成式推荐流程。

三件具体困难在引言里先点明。元数据又长又杂，生成器要抓住对推荐重要的细节：作者选了一个原本做文章标签生成的 T5，再用推荐目标微调。ID 要短又要唯一，物品一多就会撞车：用 diverse ID generation 保证每件物品分到唯一 ID。两个 LLM（生成器和基础推荐器）必须协作：用交替训练，异步更新，避免同时训导致不稳。Table 1 用来区分已有模型：P5 及其变体是生成式模型，但因为使用 OOV token，不是基础模型；UniSRec 和 Recformer 是 encoder-only，因此不是生成式模型；Recformer 的物品文本模板是为 Amazon 数据集严格设计的，只算部分基础模型。生成式相对判别式的好处被概括为：检索和排序收成一次生成，不必逐件打分，并能用上预训练生成式 LLM 里的知识。encoder-only 方法仍被留作 zero-shot 的基线。实验分两段，数字只给到规模：标准序列推荐用 4 个公开数据集，相对传统和生成式序列基线有显著提升；基础模型则用来自 Amazon Review Datasets、覆盖多个领域的 19 个数据集训练，再直接用到 6 个未见数据集（平台内或跨平台），在完全 zero-shot 下甚至超过许多监督训练的传统模型。第 1 节没有指标表。

## 2 APPROACH

方法节把流程固定成：先规定提示如何把 ID 嵌进 text-to-text，再用物品元数据生成 ID，并用多样性算法保证唯一，然后由基础推荐器在这些 ID 上做自回归生成，最后让生成器和推荐器按推荐目标交替训练。序列推荐被选作基础模型的场景，是因为用户历史本身就是有顺序的提示。模板示例是 “User [user_ID] has purchased items [item_ID], …; predict the next possible item to be bought by the user.”，历史物品 ID 按顺序填入。用户 ID 由同一生成器根据历史物品的元信息产生，可选；正文称实验里它对推荐有帮助，但没有在本节给出幅度。作者准备了 10 套差别不大的模板，每条训练样本随机抽一套，让模型更看物品序列而不是提示的字面格式。解码器逐 token 生成 “[target_item_ID]”。

ID 生成器吃的元数据可以包括标题、类目、价格、描述、创建时间、流行度、地点等，随平台而变。键值字典被摊成纯文本，例如 “name: zeppelin; categories: cocktail bars, restaurants; stars: 4.0; ...”，由模型自己决定生成 ID 时优先看哪些字段。设物品描述为长 token 序列 \(\mathbf{w}=[w_1,\ldots,w_m]\)，输出是短得多的 ID \(\mathbf{d}=[d_1,\ldots,d_n]\)，\(n\ll m\)。生成第 \(i\) 个 ID token 时同时看整段描述和已生成的 ID，概率写成式 (1) 的连乘 \(p_\theta(d_i\mid d_{<i},\mathbf{w})\)。短和唯一互相打架，所以在 diverse beam search 上加一层检查：beam 分成组，多样性惩罚为 \(\lambda\)，\(\lambda\) 越大越鼓励不同序列。每次生成 \(k\) 组 ID，与已有 ID 集合比对；撞车就加大 \(\lambda\)，直到得到唯一 ID，或 \(\lambda\) 达到预设上限（文中例子是 10）。上限仍不够就把允许的 ID 长度加长，并把 \(\lambda\) 复位后重来。Algorithm 1 的初值是：唯一 ID 集合 \(\mathcal{U}\) 为空，\(\lambda\) 从 1 开始，长度上限 \(L\) 从 10 开始；\(k\) 在本节只作为组数符号出现，没有给出具体整数。

基础推荐器把填好的提示分词后，自回归生成目标 ID。为了生成结果必须是数据集里真实存在的物品，采用约束解码：全部候选 ID 放进前缀树，下一步只允许那些能延续成某条已有 ID 的 token。式 (2) 把不在合法子集 \(\mathcal{V}(y_{<i})\) 里的 token 概率置 0，整条 ID 的概率是式 (3)。两个模块互相依赖，同时更新会不稳，因此按若干轮交替训练，并在推荐器两轮训练之间异步刷新 ID。两边的损失都是推荐流水线最终预测相对真实目标 ID 的负对数似然。训推荐器时，先用当前生成器为所有物品预计算 ID，填进抽到的模板得到 \(\mathbf{x}\)，再用 teacher forcing，损失为式 (4) 的 \(\mathcal{L}_{\mathrm{rec}}\)。训生成器时冻结推荐器。ID 是离散 token，梯度过不去，于是对历史中每个物品取出生成器在整个词表上的 logits，再用推荐器的参数把这些 logits 变成连续的平均嵌入，在嵌入层插回提示，记为 \(\mathrm{Emb}_{\mathrm{interp}}\)，损失 \(\mathcal{L}_{\mathrm{id}}\) 为式 (5)，只回传到生成器。初始化上，两边都用 T5：一是本文要看的是 ID 生成这个想法，而不是比较 LLM 结构；二是先前生成式推荐也用 T5，便于把提升归因于 ID 的选择。推荐器从标准预训练 T5 起步。生成器因为要从长文本抽出短 ID，改用已经在文章标签生成上微调过的 T5-small，该模型在 190k 篇 Medium 文章上训练，任务和「用几个词概括物品」相近。第 2 节没有实验指标。
