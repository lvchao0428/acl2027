# GPT4Rec: A Generative Framework for Personalized Recommendation and User Interests Interpretation

## Abstract 摘要

自然语言处理（Natural Language Processing, NLP）的近期进展催生了基于 NLP 的推荐系统，并展现出更优的表现。然而，当前模型通常把物品仅仅当作 ID，并采用判别式建模，因而存在以下局限：（1）无法充分利用物品的内容信息以及 NLP 模型的语言建模能力；（2）难以解释用户兴趣以提升相关性与多样性；（3）难以适应物品库不断增长等实际情形。为解决这些局限，我们提出 GPT4Rec，一个受搜索引擎启发的、新颖且灵活的生成式框架。它首先根据用户历史中的物品标题生成假设的“搜索查询”，再通过搜索这些查询来检索用于推荐的物品。该框架在语言空间中同时学习用户嵌入与物品嵌入，从而克服先前的局限。为了从不同侧面和粒度上更好地捕捉用户兴趣、以提升相关性与多样性，我们提出结合 beam search 的多查询生成技术。生成的查询自然地充当用户兴趣的可解释表示，并且可以被搜索，从而推荐冷启动物品。使用 GPT-2 语言模型和 BM25 搜索引擎，我们的框架在两个公开数据集上，以 Recall@K 分别超出最先进方法 75.7% 和 22.2%。实验进一步表明，结合 beam search 的多查询生成同时提升了检索物品的多样性以及用户多重兴趣的覆盖。我们用定性案例讨论所生成查询的适应性与可解释性。

## 1 Introduction 引言

推荐系统是信息过滤系统，为特定用户提供与之相关的个性化物品建议，被广泛用于包括电子商务和社交媒体服务在内的应用 [4, 11, 14, 19]。随着自然语言处理（NLP）的发展，许多基于 NLP 的模型通过建模用户–物品交互序列来做个性化推荐 [9, 27, 30]。近期，大语言模型（Large Language Models, LLM, [1, 5, 17, 24]）在各种 NLP 任务或对话（ChatGPT [16]）上取得了优异表现，这推动了基于 LLM 的推荐系统研究 [6, 10, 15, 22, 23, 29]。其中，BERT4Rec [23] 采用了 BERT [5] 的双向自注意力结构，并优于其他基于 NLP 的模型以及序列模型 [9, 10, 18]。

尽管模型表现有所提升，现有基于 NLP 的模型 [6, 10, 15, 22, 23, 29] 通常把物品仅仅当作 ID，并采用判别式建模，因而有如下局限：第一，这些模型无法充分利用物品的内容信息以及 NLP 模型的语言建模能力。第二，这些模型无法适应不断变化和不断增长的物品库，而这两者都是重要的实际问题 [12, 21]。此外，判别式模型难以解释用户兴趣，而解释用户兴趣对于提升推荐的多样性与质量至关重要 [2, 3, 13, 28]。

为解决这些局限，我们提出 GPT4Rec，一个用于个性化推荐的新颖且灵活的生成式框架，同时提供对用户兴趣的解释。我们的框架受搜索引擎启发：GPT4Rec 首先用生成式语言模型生成假设的“搜索查询”；模型输入是用户历史中的物品标题，并与一条生成提示相结合。然后，GPT4Rec 用搜索引擎搜索所生成的查询，从而检索用于推荐的物品。GPT4Rec 的关键组件是一个强大的生成式语言模型，它在语言空间中同时学习用户嵌入与物品嵌入，使我们能够利用物品标题中的语义信息，并捕捉用户多样的兴趣。为了解码用户的多重兴趣并提升推荐多样性，我们在查询生成中采用多查询 beam search 技术。这些查询是人类可理解的，并且本身就具有解释用户兴趣的独立价值。此外，搜索那些代表用户兴趣的查询来做推荐，能够自然地解决物品冷启动问题和物品库变化问题。最后，GPT4Rec 在实践中也有利，因为它可以灵活地接入更先进的 LLM 或搜索引擎来提升表现。

总之，我们的贡献包括：（1）我们提出 GPT4Rec，一个新颖且灵活的生成式框架，把推荐任务视为查询生成加搜索；（2）我们采用多查询 beam search 策略，以产生多样且可解释的用户兴趣表示；（3）我们在两个公开数据集上做实验，表明相对最先进方法，Recall@\(K\) 有实质性提升；（4）通过定量与定性分析，我们考察并表明，生成查询的数量会提升检索物品的多样性以及用户多重兴趣的覆盖。

## 2 Methodology 方法

所提出框架的架构如图 1 所示。给定用户的物品交互序列，GPT4Rec 用一条提示来编排物品标题，并使用生成式语言模型在语言空间中同时学习物品嵌入与用户嵌入。模型随后生成多条代表用户兴趣的查询，这些查询被送入搜索引擎以检索用于推荐的物品。本文选择 GPT-2 语言模型和 BM25 搜索引擎，但该框架可以灵活地纳入更先进的模型。

### 2.1 Query Generation with the Language Model 用语言模型生成查询

GPT4Rec 的第一个组件是生成式语言模型，其目标是从物品交互序列中在语言空间学习用户表示，然后生成多条代表用户兴趣的查询。所选的 GPT-2 模型有 117M 参数，具有复杂的 Transformer 型架构，并在巨大的语言语料上预训练；对其微调，符合我们捕捉用户兴趣与物品内容信息的目的。通过实验，我们决定使用如下提示来编排模型输入：

> Previously, the customer has bought:  
> \<ITEM TITLE 1\>. \<ITEM TITLE 2\>...  
> In the future, the customer wants to buy

（此前，该顾客购买过：\<物品标题 1\>。\<物品标题 2\>…… 未来，该顾客想购买）

该提示包含物品标题中的语义信息，并对每个用户 \(u\) 记为 \(W_u\)。GPT-2 从 \(W_u\) 学习用户表示，随后能够依据条件分布 \(P(\cdot \mid W_u)\) 以序列方式生成查询。

为了很好地表示用户多样的兴趣并提高推荐结果的多样性，我们提出不只生成单条查询，而是用 beam search 技术生成多条查询 [18, 25]。给定 beam size \(m\)、生成得分函数 \(S(\cdot)\)，以及长度为 \(l\) 的候选查询 \(Q_l = (q^l_1, q^l_2, \ldots, q^l_m)\)，beam search 算法把 \(Q_{l+1}\) 更新为长度为 \(l+1\)、使 \(S(W_u, q)\) 最大的前 \(m\) 条查询，其中 \(q \in \{|q| = l+1,\ q[1:l] \in Q_l\}\)（集合记号的抽取在括号处不完整，【抽取不清】，此处按抽取到的符号转写）。最重要的是，这种 beam search 策略生成的用户兴趣表示在不同侧面和粒度上是多样的。

### 2.2 Item Retrieval with the Search Engine 用搜索引擎检索物品

所提出框架的第二个组件是搜索引擎，它起到“判别器”的作用。它把每条生成的查询作为输入，用匹配得分函数把库存中最相关的物品作为输出检索出来。匹配得分函数衡量语言空间上的相似度，作用类似于向量嵌入方法中的内积相似度 [4, 19]。我们选择采用 BM25 匹配得分函数 [20]，因为它是使用最广的基线搜索引擎之一，并用两个对应参数 \(k_1\) 和 \(b\) 来考虑词频饱和与文档长度。

令 \(K\) 表示推荐物品的总数，\(m\) 表示生成查询的数量，我们提出一种基于排序的策略来合并每条查询的搜索结果。它首先从生成得分最高的查询的搜索结果中检索前 \(K/m\) 个物品，然后按其得分排名，从其余查询中依次加入 \(K/m\) 个不重复的物品。该策略能够在检索物品的相关性与多样性之间取得平衡。

### 2.3 Training Strategy 训练策略

我们提出一种灵活的两步训练流程，分别优化语言模型和搜索引擎，这在实践中有利于模型迭代。给定每个用户 \(u\) 的物品交互序列 \(i_1, i_2, \ldots, i_T\)，我们取 Section 2.1 所示提示中的前 \(T-1\) 个物品标题，再将其与最后一个物品 \(i_T\) 的标题拼接，形成训练语料，以微调预训练的 GPT-2 模型。该策略的动机来自对比学习文献 [8]，其基本想法是：最细粒度、最准确的搜索查询就是目标物品标题本身。语言模型训练完成之后，我们通过网格搜索参数 \(k_1\) 和 \(b\) 来优化 BM25：选择在搜索所生成查询以检索目标物品时表现最好的参数。
