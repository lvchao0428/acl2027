## 摘要

现有 NLP 推荐尽管成绩更好，仍把物品当成 ID，并用判别式建模。作者认为这带来三处限制：物品内容和语言模型的生成能力都用不满；用户兴趣难以解释，相关性和多样性因此受限；物品库增长、变化这类实际情形也接不住。GPT4Rec 改用搜索引擎的思路：根据用户历史里的物品标题生成假设的 search queries，再搜索这些查询来取回推荐。用户和物品的表示都放在语言空间里。

为了同时盖住兴趣的不同侧面和不同粒度，生成阶段用 beam search 一次产出多条查询。这些查询本身可读，可以解释兴趣，也可以拿去检索冷启动物品。实例化时语言模型用 GPT-2，检索引擎用 BM25。摘要称在两个公开数据集上，Recall@K 相对已有方法分别提高 75.7% 和 22.2%。进一步的实验说明，多查询生成同时提高了检索结果的多样性，以及对用户多重兴趣的覆盖；查询的适应性和可解释性放在定性案例里讨论。两个数据集的名字不在摘要中。

## 1 INTRODUCTION

引言把 GPT4Rec 放在「序列推荐已经开始用语言模型，但建模方式仍是判别式」这个缺口上。推荐系统被定义为给特定用户滤出相关物品，电商和社交媒体都在用。NLP 模型通过用户–物品交互序列做个性化；大语言模型在各种 NLP 任务以及对话（文中举了 ChatGPT）上的成绩，又催生了一批 LLM 推荐。其中 BERT4Rec 借用 BERT 的双向自注意力，超过了其他 NLP 模型和序列模型。作者认为这些模型的共同短板不在注意力结构，而在于物品只是 ID、目标是判别：内容信息和语言建模能力用不满；物品库的变化和增长处理不了；兴趣难以解释，而解释对多样性和推荐质量是必要的。

GPT4Rec 把推荐拆成两步，而不是直接对 ID 打分。生成式语言模型的输入是历史物品标题加上一段生成提示，输出假设的搜索查询；搜索引擎再按查询取回物品。关键组件是那个生成模型：它在语言空间里同时学习用户和物品，从而用上标题语义，并抓住用户并不单一的兴趣。解码时用 multi-query beam search，让多条查询对应多方面兴趣，并提高多样性。查询对人可读，单独就能当兴趣的解释。用代表兴趣的查询去搜，冷启动物品和变动中的库存可以自然进入候选，而不必先给新物品学一个 ID 向量。实践上，语言模型和搜索引擎都可以换成更强的组件。

贡献收成四条。框架把推荐任务写成查询生成加搜索。多查询 beam search 用来产生多样、可解释的兴趣表示。实验在两个公开数据集上比较 Recall@K，正文此处只说有实质提升，75.7% 和 22.2% 出现在摘要。定量和定性分析则用来说明：生成查询的条数会提高检索物品的多样性，以及对用户多重兴趣的覆盖。第 1 节没有表。

## 2 METHODOLOGY

方法节用 Figure 1 把数据流固定下来：用户交互过的物品标题配上提示，送入生成式语言模型，在语言空间里学习物品和用户表示，再生成多条兴趣查询，交给搜索引擎检索。本文选用 GPT-2 和 BM25，并强调这两件都可以替换。

### 2.1 Query Generation with the Language Model

查询生成的目标是从交互序列学到语言空间中的用户表示，再吐出多条兴趣查询。选用的 GPT-2 有 117M 参数，是在大规模语料上预训练的 Transformer。实验后采用的提示是：先写 “Previously, the customer has bought:”，接上各物品标题，再接 “In the future, the customer wants to buy”。这段文本记为用户 \(u\) 的 \(W_u\)。模型从 \(W_u\) 学习用户表示，并按条件分布 \(P(\cdot\mid W_u)\) 逐词生成查询。

多样性不靠检索阶段硬打散，而靠一次生成多条查询。beam search 的 beam 大小为 \(m\)，打分函数为 \(S(\cdot)\)。长度为 \(l\) 的候选查询集 \(Q_l\) 在下一步被换成长度 \(l+1\)、前缀属于 \(Q_l\)、且 \(S(W_u,q)\) 最高的 \(m\) 条。作者认为这样得到的兴趣表示在侧面和粒度上都会分开。

### 2.2 Item Retrieval with the Search Engine

搜索引擎在框架里扮演判别器：每条查询进去，库存里最相关的物品出来。匹配分数衡量的是语言空间里的相似度，角色类似向量方法中的内积。BM25 被选中，是因为它用两个参数 \(k_1\) 和 \(b\) 处理词频饱和与文档长度。设最终要推荐 \(K\) 个物品、生成了 \(m\) 条查询，合并规则按生成分数从高到低进行：先从最高分查询取前 \(K/m\) 个物品，再按分数依次从其余查询补入不重复的 \(K/m\) 个。这一步同时照顾相关性和多样性。

### 2.3 Training Strategy

训练分成两步，语言模型和搜索引擎分开优化，便于各自迭代。对用户 \(u\) 的物品序列 \(i_1,\ldots,i_T\)，把前 \(T-1\) 个标题放进 2.1 的提示，再拼上最后一件 \(i_T\) 的标题，组成微调预训练 GPT-2 的语料。作者把这个做法联系到对比学习：最细、最准的搜索查询就是目标物品标题本身。语言模型训完之后，再网格搜索 BM25 的 \(k_1\) 和 \(b\)，使这些生成查询找回目标物品的效果最好。第 2 节没有给出搜索范围、数据集规模或指标表。
