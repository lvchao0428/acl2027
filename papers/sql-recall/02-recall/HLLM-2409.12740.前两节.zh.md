## 摘要

已有工作把大语言模型放进推荐，相对传统模型只有有限提升。作者认为三件事还没说清：预训练权重里的世界知识在推荐里到底值多少、推荐任务是否必须再微调，以及语言模型在其他领域的可扩展性能否在推荐里重现。HLLM 是一个分层结构。下层 Item LLM 从物品的详细文本描述抽出内容特征，上层 User LLM 用这些特征、按交互历史预测用户接下来的兴趣。

摘要的实验结论是：开源 LLM 的预训练能力确实被用上了，再针对推荐微调还会明显抬高性能。最大配置里，物品特征抽取和用户兴趣建模各用 7B 参数，并称训练和服务效率足以落地。评价数据集是 PixelRec 和 Amazon Reviews，结果优于传统 ID 模型，幅度被说成 wide margin，摘要没有给出具体百分点。线上 A/B 测试也有可见收益。具体指标表不在摘要。

## 1 INTRODUCTION

第一节先把主流推荐写成 ID 路线的局限。物品和用户被换成 ID，再配一张嵌入表；序列模型用来抓住随时间变化的多样兴趣。这类模型的参数大多堆在嵌入上，网络本身偏浅，于是冷启动差，也难以刻画复杂兴趣。ChatGPT 之后，LLM 的世界知识和推理能力让推荐研究者分出三条用法：用 LLM 给行为做摘要或扩充物品信息；把推荐改成对话；或者改模型，使输入输出不限于文本，包括把 ID 特征送进 LLM，以及直接用 LLM 优化点击率一类目标。

作者认为这些接法在复杂度和效果上都不理想。把行为历史写成文本，同样一段时间的历史会比 ID 序列长得多，而自注意力的复杂度随序列长度平方增长。推荐一件物品还要生成多个文本 token，等于多次前向，效率低。效果上，相对传统方法的提升也不显著。由此留下三个开放问题。预训练权重在大规模推荐数据上训练时还有没有价值，不能只看零样本和少样本。继续用推荐目标微调，是增强还是损害预训练知识，并不清楚。可扩展性方面，已有推荐工作验证过 scaling law，但那些模型参数远小于 LLM；参数超过 10 亿之后，推荐里是否仍然随规模变好，仍是开放问题。

HLLM 的回答是把物品建模和用户建模拆开。Item LLM 在每条物品文本描述末尾加一个特殊 token，用该 token 的输出当物品特征。User LLM 再吃这些特征，预测未来行为。长文本被压成嵌入后，行为序列长度回到 ID 模型的量级，比直接把历史摊成文本的 LLM 推荐更省。引言还提前给出后文实验要支撑的判断：即便 Item LLM 只做特征抽取、User LLM 的输入输出都是物品嵌入，而不是常规的文本对话，预训练权重对两边都有用，说明世界知识对推荐有价值；但这不能代替面向推荐目标的微调，微调才是超过传统方法的关键。在资源允许的范围内，参数增大到 70 亿时性能仍持续上升。训练效率上，引言称只用少量训练数据就能超过 ID 模型，没有给出具体数据量。贡献对应三条：分层框架在大规模学术数据和工业线上都有效，且训练与服务效率好；预训练知识能迁到物品特征和用户兴趣两侧，但任务微调必不可少；数据和参数变大时性能继续上升。第 1 节没有表。

## 2 Related Work

相关工作把传统推荐收成两条线索，用来对照后文的分层 LLM。一条是 ID 嵌入上的特征交互：DeepFM 用 FM 做低阶、用 DNN 做高阶；DCN 在每一层显式做特征交叉以得到更高阶交互。另一条是从历史行为里抽兴趣：DIN 和 DIEN 用注意力抓多样兴趣，SASRec 把 Transformer 的自注意力用于序列推荐。CLUE 和 HSTU 则说明，参数量在数亿（hundreds of millions）以内的模型仍服从 scaling law。另有工作把内容特征引进推荐模型，在泛化上显示出一定好处。本节没有给出这些模型的指标数字。

语言模型推荐被分成三类，并点名代表系统。第一类用 LLM 摘要或补充用户与物品信息：RLMRec 做用户/物品画像，再用跨视图对齐把 LLM 的语义空间和协同关系的表示空间对齐；也有工作用 LLM 为冷启动物品生成额外训练信号。第二类把推荐数据改成对话，或当成指令跟随，把历史行为以文本送进 LLM 来预测下一步。第三类让输入或输出超出纯文本：LLaRA 用混合提示把 ID 嵌入和文本特征放在一起；LEARN 用预训练 LLM 抽物品特征；也有工作把 LLM 改成多分类或回归来做评分预测。本节的收束判断是：这些方法相对传统推荐模型的提升有限。第 2 节在此结束，HLLM 的公式和训练目标从第 3 节才展开。
