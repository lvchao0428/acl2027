## Abstract 摘要

基于大语言模型（LLMs）的生成式推荐，已经把传统的、基于排序的推荐方式转变成文本到文本（text-to-text）的生成范式。这一路线受到大量关注。然而，与天生就在人类词表上运作的标准自然语言处理（Natural Language Processing, NLP）任务不同，当前的生成式推荐研究难以在文本到文本框架内，用简短却有意义的 ID 表示来有效编码推荐物品。由于这一问题尚未解决，基于 LLM 的生成式推荐系统的潜力在很大程度上仍未被探索。

为了让 LLM 更好地对齐推荐需求，我们提出 IDGenRec：用人类语言 token，把每个物品表示成唯一、简短、语义丰富、且与平台无关（platform-agnostic）的文本 ID。做法是把一个文本 ID 生成器与基于 LLM 的推荐器一起训练，从而使个性化推荐能够无缝接入自然语言生成。值得注意的是，由于用户历史以自然语言表达，并与原始数据集解耦，我们的方法暗示了基础性生成式推荐模型（foundational generative recommendation model）的可能。实验表明，在标准实验设置下的序列推荐（sequential recommendation）中，我们的框架持续超过现有模型。随后，我们探索用所提出的方法、在收集自 19 个不同数据集的数据上训练一个基础推荐模型（foundation recommendation model）的可能性，并在完全零样本（zero-shot）设置下，于跨不同平台的 6 个未见数据集上测试其推荐表现。结果表明，该预训练基础模型的零样本表现与某些基于监督训练的传统推荐模型相当，甚至更好，显示出 IDGenRec 范式作为生成式推荐之基础模型的潜力。代码与数据开源于 https://github.com/agiresearch/IDGenRec。

## 1 Introduction 引言

在大量信息上预训练的、带有 LLM 的生成模型 [1, 2, 28, 32]，正在持续变革机器学习领域。由于它们能够理解复杂指令，并生成有创造性、与上下文相关的预测，其用途已迅速扩展到 NLP 任务之外，为多个研究领域的应用提供基础。生成式推荐就是这样一个例子。（原文此句为 “Due to their successful in understanding complex instructions and generate ...”，措辞不完整，但用词可辨。）

传统方法把推荐当作检索（候选选择）加排序的过程，而生成式推荐把它解释为直接的文本到文本生成任务：用户历史被表达成文本提示（prompt），目标推荐则以自然语言形式生成。然而，与只阅读并生成人类语言 token 的 NLP 任务不同，推荐平台上的物品是一个不断增长的宇宙中的独立实体。因此，如何把物品编码成能够轻松接入文本到文本范式的语言 token（即 Item ID），是生成式推荐研究中一个独特且关键的问题。

已有一些工作尝试处理这一问题。生成式推荐的最早工作之一 P5 [8] 提出：在推荐平台内为物品分配词表外（out-of-vocabulary, OOV）token。这些被分配的 ID 是定长数值 token，大致按其在数据集中的出现顺序构造（例如，第一个物品为 1001，第二个物品为 1002）。随后，[14] 评估了用不同策略初始化数值 ID 时，推荐表现还能如何进一步提升。

然而，尽管这些开创性工作在标准推荐设置下取得了可观表现，LLM 在推荐中的真正能力在很大程度上仍未被探索。首先，这些方法忽略了物品文本描述中丰富的语义信息，从而削弱了使用 LLM 的主要动机之一——利用其在预训练阶段获得的语义知识。其次，分配给物品的数字是没有真实上下文含义的无意义 token。用推荐目标训练这类模型，并不会引导它们学习物品的一般特征，而只是学习这些 ID 在每个数据集内部的共现模式。因此，尽管这些模型以文本到文本的面貌出现，本质上不过是以传统键值字典（key-value dictionary）的方式学习每个物品的表示，这给生成推荐的质量设置了上限。与此同时，由于学到的 ID 表示缺乏一般含义，它们获得的知识无法跨数据集迁移。这意味着预训练的推荐模型在未见数据上没有任何零样本推荐能力。于是，推荐社区长期追求的基础性推荐模型，无法由上述任何方法实现。

我们认为，上述局限主要来自不充分的物品编码。考虑人类语言中的任务，例如问答和机器翻译，其中每一份知识都表示在一个有限 token 集合之内。这使基础模型能够从大规模文本语料的训练中轻松学到普遍适用的知识，并毫不费力地适配任何下游任务。倘若推荐系统中的物品也同样完全用人类词表来表示，每个物品由一组特定的自然语言 token 来描述，那么 LLM 的能力就能更紧密地对齐推荐系统的要求。这样，通过在推荐专用语料上训练，LLM 将能够学到真正与推荐相关的知识，从而显著提高模型在推荐任务上的准确率与泛化能力。

因此，我们提出：生成式推荐中理想的 ID 应具备以下性质：1）它们应是由预训练 LLM 原本就处理的 token 组成的文本 ID；2）它们应有意义、信息充分，并适合推荐目的；3）生成的 ID 应简短且唯一，从而有效标识推荐物品。然而，满足如此严格要求的 ID，显然并不存在于现有的物品信息中。因此，本文提出训练一个 ID 生成器（ID generator），为每个物品自动学习一个满足上述标准的文本 ID。这一新框架名为 IDGenRec，把 ID 生成当作另一个文本到文本过程。如图 1 所示，ID 生成器本身也是一个语言模型，它接收物品的元数据（metadata，即关于该物品的全部可用文本信息），并产出合格的文本 ID。于是，用户历史与推荐目标物品都可以用自然语言表示，而不含任何“无上下文”（“uncontextualized”）token，从而适合用来训练基于 LLM 的生成式推荐器。这一整体过程如图 2 所示。值得注意的是，把用户历史中全部物品的文本都考虑进去之后，同一个 ID 生成器还可以产出另一个文本 ID，作为用户 ID，表示用户偏好的一种“高层画像”（“high-level profile”）。创建用户 ID 是可选的，我们将在实验中给出消融结果。

这项工作中有许多挑战。我们在文中针对每一项提出了相应策略，包括：

(1) ID 生成器应当理解可能包含无关信息的冗长元数据，并生成覆盖那些对推荐重要的物品关键细节的 token。为此，我们选择了一个原本为文章标签生成而训练的 T5 模型，再用推荐目标对它进行微调。

(2) 生成的 ID 应当简短且唯一，适合用来标识推荐物品。然而，自动生成的 ID 并不总是满足唯一性，尤其是当物品数量增加时。因此，我们提出一种多样化 ID 生成算法，始终保证每个物品被分配到一个唯一 ID。

(3) 由于该框架依赖两个 LLM——ID 生成器与基础推荐器（base recommender）——之间的协作，需要一套精心设计的训练策略，才能使它们无缝协作。我们提出一种交替训练策略，异步地训练基于 LLM 的 ID 生成器与基础推荐器，以确保它们学到的知识彼此对齐。

我们注意到，一些近期基于 LLM 的推荐模型采用仅编码器（encoder-only）结构，类似于 BERT，作为其表示函数。其中一些模型 [12, 18] 也具备（或部分具备）基础性推荐模型的特征，尽管它们并不作为生成模型运作。这些模型之间的区别见表 1。然而，生成模型相对判别式方法有若干优势。这包括：把检索与排序过程转变成更精简的生成过程，省去逐个物品计算分数的需要，并利用预训练生成式 LLM 中嵌入的大量知识。尽管如此，这些仅编码器方法作为零样本评测的基线仍然有价值。

我们进行两类实验来说明所提出方法的有效性。首先，我们在标准序列推荐设置下评估该方法。在 4 个广泛使用的公开数据集上的实验表明，相对序列推荐基线——包括传统模型与生成模型——它有显著提升。然后，为探索训练一个能学习一般推荐知识的基础性生成模型的可能性，受标准 NLP 任务中 LLM 训练范式的启发，我们汇集来自 Amazon Review Datasets 的 19 个数据集中的用户历史，覆盖多样的推荐领域，以构建大规模推荐训练语料。在这一大规模数据集上训练模型之后，我们把该基础模型直接应用到 6 个未见数据集上，这些数据集或为平台内、或为跨平台，并在完全零样本设置下评估推荐表现。结果呈现出很有希望的推荐表现，甚至超过许多基于监督训练的传统推荐模型。

## 2 Approach 方法

我们首先介绍生成过程，包括提示如何构造，以及生成的 ID 如何接入文本到文本格式，如 Section 2.1 所讨论。然后，在 Section 2.2 与 Section 2.3 中，我们描述如何利用物品元数据生成 ID，并采用多样化 ID 生成算法，以保证每个物品的 ID 是唯一的。有了这些生成的 ID 之后，基础推荐系统在 Section 2.4 给出。最后，在 Section 2.5 中，我们说明 ID 生成器与推荐器如何相对推荐目标交替训练，以确保它们协作并且有效。

### 2.1 Generative Process 生成过程

在本研究中，我们在序列推荐系统的语境下引入这一基础性生成模型。这一路线特别合适，因为它自然地对齐用户历史的序列表示，并以此作为输入提示。在生成式推荐系统既有工作 [8, 14, 38, 41] 的基础上，我们的模型需要为生成过程预定义提示模板。例如，一个典型模板可以是：“User [user_ID] has purchased items [item_ID], [item_ID], ..., [item_ID]; predict the next possible item to be bought by the user.”（用户 [user_ID] 已购买物品 [item_ID], [item_ID], ..., [item_ID]；预测该用户下一步可能购买的物品。）在该模板中，用户历史中的全部物品 ID 按顺序填入占位符。此外，同一个 ID 生成器也可以产出用户 ID，其输入是用户历史中全部物品的元信息。生成用户 ID 是可选的，并且在实验中被证明对推荐表现有益。（原文拼写为 “benifitial”。）我们开发了 10 个这样的模板，彼此只有细微差别；对每个训练实例随机选择其中一个，使模型更多地关注与推荐相关的信息，例如物品序列，而更少关注提示的确切格式。一个填完的提示示例见图 2。解码器随后逐 token 生成目标物品 “[target_item_ID]”，它能够唯一标识目标推荐。后文将详细说明我们生成过程中的两个主要 LLM 组件：ID 生成器与基础推荐器。

### 2.2 ID Generator ID 生成器

ID 生成器是一个生成模型，它用物品的元信息产出物品 ID。该元信息涵盖与物品相关的全部文本数据，其中既有对推荐有关的方面，也有无关的方面。这些信息可能的要素包括物品的标题、类别、价格、一般描述、创建时间、流行度、地点等。具体内容在很大程度上取决于平台与数据集。尽管元信息通常以键值字典格式呈现，我们在处理时把它转换成纯文本，例如 “name: zeppelin; categories: cocktail bars, restaurants; stars: 4.0; ... ”。这使 ID 生成器可以自由学习：在生成 ID 时，哪些信息片段应当被优先考虑。

考虑一个物品，其纯文本描述是一长串 token \(\boldsymbol{w}=[w_1,w_2,\ldots,w_m]\)。token 嵌入将由模型参数从 \(\boldsymbol{w}\) 生成，并与位置嵌入合并后送入语言模型。与位置嵌入的合并在其后的公式中省略，因为这一过程在大语言模型中是通用的。ID 生成器的输出将是一组简短的 ID token \(\boldsymbol{d}=[d_1,d_2,\ldots,d_n]\)，其中 \(n\ll m\)。在生成物品 ID 的每个 token 时，模型同时关注物品的整段纯文本描述以及此前已生成的 ID 单元。因此，一个生成 ID 的概率记为：

式 (1)：

```
p(d_1, ···, d_n) = ∏_{i=1}^{n} p_θ(d_i | d_<i, w)
```

抽取文本中连乘号显示为 “Ö”，上下标结构为 \(n\) 在上、\(i=1\) 在下，其后为 \(p_\theta(d_i\mid d_{<i},\boldsymbol{w})\)。此处按连乘写出。其中 \(d_{<i}=[d_1,\cdots,d_{i-1}]\)，\(\theta\) 为 ID 生成器的参数。该过程如图 1 所示。

### 2.3 Diverse ID Generation 多样化 ID 生成

生成 ID 的两个主要性质是：1）ID 应有合理的长度；2）ID 应唯一。然而这两个性质在一定程度上相互矛盾：被约束在更短长度上的一组 ID，由 ID 生成器生成时更可能出现重复。因此，我们提出一种算法，以保证生成的 ID 既短又唯一。该算法的核心概念从根本上基于多样化束搜索（diverse beam search, DBS）[33]，这是句子生成中常用的方法。它是标准束搜索的一种变体，旨在生成更多样的序列集合。DBS 把束划分成组，并引入一个多样性惩罚，记为 \(\lambda\)，作为超参数，以抑制在同一组内选择相似序列。较大的 \(\lambda\) 促进更多样性，较小的 \(\lambda\) 则更重视模型概率，可能导致输出较少样。

ID 生成器在生成 ID 时使用 DBS。为确保生成 ID 的唯一性，算法每次生成 \(k\) 组 ID，并把每个生成的 ID 与一组已经存在的 ID 比较。若检测到重复，算法就提高束搜索中的多样性惩罚。这一惩罚持续增加，直到产出一个唯一 ID，或直到多样性惩罚达到预设的最大阈值（例如本文中的 10）。若最大惩罚仍不足以生成唯一 ID，算法就放宽允许的 ID 长度，并用初始多样性惩罚重复这一过程。Algorithm 1 详细说明了该过程。

图 2：一个展示生成式推荐工作流的真实例子。ID 生成器接收用户历史中物品的纯文本，并为这些物品生成物品 ID。然后，生成的 ID 被填入模板。此外（图注原文拼写为 “Addtionally”），用户 ID 通过使用用户历史中全部物品的文本来生成，展示用户偏好的一种“高层画像”。随后，位置嵌入与 token 嵌入合并，以捕捉交互序列。最后，基础推荐器基于约束解码生成被推荐物品的 ID。图内具体示例字符串未在文本抽取中逐字出现。

Algorithm 1 Diverse ID Generation Algorithm 多样化 ID 生成算法

```
1:  初始化集合 U，用于存放唯一 ID
2:  将多样性惩罚 λ 初始化为 1
3:  将 ID 长度上限 L 初始化为 10
4:  for 数据集中的每个 item do
5:      将 found 初始化为 False
6:      while not found do
7:          用 ID Generator，以当前的 L 与 λ 生成 k 个 ID
8:          for 每个生成的 ID id do
9:              if id 不在 U 中 then
10:                 将 id 加入 U，并保存该 item 与 ID 的对应
11:                 将 found 置为 True
12:                 break
13:             end if
14:         end for
15:         if not found then
16:             λ ← λ + 1
17:             if λ 超过预定义上限 then
18:                 增大 L，并将 λ 重置为 1
19:             end if
20:         end if
21:     end while
22: end for
```

### 2.4 Base Recommender 基础推荐器

在生成物品 ID 并把它们填入提示模板之后，系统对填完的提示做分词，并送入基于 LLM 的推荐器。推荐器随后以自回归方式生成目标推荐物品 ID 的 token。

为确保解码出的 ID 对应一个真实存在的物品，我们采用约束序列解码（constrained sequence decoding）策略 [5]。更具体地说，用一棵前缀树（prefix tree）存放全部已生成的候选 ID。每一个新生成的 token 都受此前已生成 token 的约束，从而保证生成过程只考虑那些有可能构成数据集中某个已有候选 ID 的 token。设填完的输入提示记为 token 序列 \(\boldsymbol{x}=[x_1,x_2,\cdots,x_n]\)。在此情况下，基础推荐器模型旨在生成 \(\boldsymbol{y}=[y_1,y_2,\cdots,y_n]\)，其中 \(\boldsymbol{y}\) 是数据集中某个真实物品的 ID。我们把 \(\mathcal{V}(y_{<i})\) 定义为词表中的有效 token 子集，它由以前已生成 token 为节点的前缀树所约束。解码器对每个 token 的生成定义为：

式 (2)：

```
p(y_i | y_<i, x) = p_φ(y_i | y_<i, x)    若 y_i ∈ V(y_<i)
                 = 0                      否则
```

抽取中分段大括号显示为 “(”。此处按分段函数写出。

因此，推荐某个目标物品 \([y_1,\cdots,y_n]\) 的概率为：

式 (3)：

```
p(y_1, ···, y_n) = ∏_{i=1}^{n} p_φ( y_i | y_<i, x, V(y_<i) )
```

连乘号同样被抽成 “Ö”；\(p_\phi\) 的自变量括号在抽取中显示为控制字符。此处按连乘与成对括号写出。

### 2.5 Alternate Training 交替训练

训练 ID 生成器与训练基础推荐器是两个分开、但相互依赖的任务。ID 生成器被训练来产出基础推荐器容易解释的最优 ID。与此同时，基础推荐器调整其参数，以加强对物品的正确推荐，而每个物品由其当前生成的 ID 表示。同时训练两个组件可能导致不稳定的训练过程。因此，我们提出交替进行 ID 生成器与基础推荐器的训练轮次，并经历指定的迭代次数。这一做法在基础推荐器的两段训练阶段之间异步更新 ID，以便更好地整合并提升表现。

ID 生成器与基础推荐器的训练，都是通过最小化推荐流水线最终预测相对真实目标物品 ID 的负对数似然（negative log-likelihood）来完成的。

#### 2.5.1 Training Base Recommender. 训练基础推荐器

在每一轮训练基础推荐器时，我们用当时的 ID 生成器为全部物品预先计算物品 ID。对训练数据中的每个用户，把该用户历史中物品的当前 ID 填入抽到的模板，以完成输入提示 \(\boldsymbol{x}\)。然后，基础推荐器 \(\omega\) 用常见的教师强制（teacher forcing）策略 [34] 训练，即下一个 token 的损失是在前一个 token 取真实值的条件下计算的：

式 (4)：

```
L_rec = − ∑_{i=1}^{|y|} log P_ω(y_i | y_<i, x)
```

求和号在抽取中带有变体选择符，结构为从 \(i=1\) 到 \(|\boldsymbol{y}|\)。

#### 2.5.2 Training ID Generator. 训练 ID 生成器

在这一训练过程中，基础推荐器中的全部参数固定，只更新 ID 生成器。目标是让 ID 生成器产出适合基础推荐模型的 ID。

由于 ID 生成器的输出是一组离散 token（即 ID），它本质上不可微。这给使用基于梯度的优化技术来训练模型带来挑战，因为梯度无法回传通过这些离散输出。为绕过这一点，对用户历史中的每个物品，我们计算 ID 生成器在整个词表上每个 token 的输出 logits，记为 \(\mathrm{Logits}_\phi(\mathcal{V})\)，其中 \(\phi\) 是 ID 生成器模型，\(\mathcal{V}\) 是词表。然后，我们通过基础推荐模型的参数，计算 ID 中每个 token 的平均嵌入，记为 \(\mathrm{Emb}_\omega(\mathrm{Logits}_\phi(\mathcal{V}))\)，其中 \(\omega\) 是基础推荐器模型。这就为生成的 ID 建立了一个连续、可微的表示。这些 ID 嵌入随后在嵌入层面、于相关位置被直接插值进提示模板。我们用 \(\mathrm{Emb}_{\mathrm{interp}}\) 表示这一填完的输入嵌入。这样，ID 生成器 \(\phi\) 就可以在由推荐输出计算出的损失指导下被训练。该过程表述为：

式 (5)：

```
L_id = − ∑_{i=1}^{|y|} log P_ω( y_i | y_<i, Emb_interp )
where Emb_interp = Insert( Emb_ω(prompt), Emb_ω( Logits_φ(V) ) )
```

抽取中 \(\log\) 与 Insert 的分组括号显示为控制字符，此处按成对括号写出。

基础推荐器模型的参数（即 \(\omega\)）是固定的，损失只反向传播到 ID 生成器（即 \(\phi\)），从而确保生成的 ID 以其元信息所决定的方式，捕捉每个物品的本质特征，并且其格式能被基础推荐模型有效解释。

### 2.6 Model Initialization 模型初始化

我们选择 T5 模型 [28] 作为 ID 生成器与基础推荐器二者的骨干，主要有两个原因：1）保持模型简单，因为本文的目标不是对 LLM 结构做大规模实证研究，而是聚焦 ID 生成这一核心概念；2）确保与先前的生成式推荐工作公平比较，那些工作同样基于 T5，从而表明推荐能力的提升仅来自更精巧的 ID 选择。

对于基础推荐器，选用标准的预训练 T5 检查点作为骨干，以便把预先学到的知识纳入推荐任务。对于 ID 生成器，鉴于从长文本生成 ID 并非平凡、且高度任务特定，一个更专门的起点更可取。因此，我们选择一个在文章标签生成任务上微调过的 T5 small 模型，作为 ID 生成器的初始配置。该模型在 190k 篇 Medium 文章上训练，擅长从文章文本内容生成简短标签。做此选择，是因为新闻文章的标签生成与用少量词概括物品之间有显著相似性。
