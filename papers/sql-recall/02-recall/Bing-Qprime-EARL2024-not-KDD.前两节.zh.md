## 摘要（Abstract）

Explore Further @ Bing 是一项网页到网页的推荐产品，通过呈现与搜索结果 URL 相关联、能吸引用户的网页推荐，增强 Bing 上的搜索体验。本文介绍我们利用大语言模型（LLM）来增强网络规模推荐系统的方法。我们描述由 LLM 驱动的推荐质量指标 RecoDCG 的开发与验证。我们讨论利用 LLM 使排序阶段具备质量感知能力的核心技术。此外，我们详述 Q' recall，这是一条召回路径，借助 LLM 生成互补且能吸引用户的推荐候选，从而增强系统的候选生成阶段。我们还说明如何针对多个目标优化系统，在推荐质量与点击指标之间取得平衡。我们将这项工作部署到生产环境，推荐质量获得显著提升。我们分享离线与在线实验的结果，以及为确保这些方法能够有效扩展、满足网络规模需求而形成的见解与所采取的步骤。

## 第 1 节 引言（Introduction）

Explore Further（如图 1 所示）位于 Bing 搜索结果页上，提供与查询和用户都无关的网页推荐。我们的推荐系统是业界规模最大的系统之一，索引总量超过 2000 亿个网页。开发大规模推荐系统时，一项始终存在的重大挑战是：为训练这些系统获取可靠的质量与相关性标签。人工标注者通常能提供高质量的相关性标签，但人工标注成本高、耗时长，而且往往不一致。仅依靠人工标签，很难把一个不断变化的超大规模推荐系统扩展起来。这一点对系统的训练和评估都成立。

业界许多产品把隐式反馈（例如用户点击）当作优化推荐系统的有价值信号。然而，过度关注点击指标有时会导致系统偏向标题党和低质量推荐 [6]。由于整个网页上文档质量差异很大，这一问题对网页推荐系统尤为关键。历史上，我们的系统主要依据用户交互与行为信号进行训练。随着时间推移，我们在用户针对该功能提交的 Bing 不满意反馈中反复看到同一主题，即对标题党和低质量网页推荐的担忧。

对于我们这种规模的索引，不可能逐一策展进入索引的网页，因此我们面临向用户暴露垃圾内容、标题党甚至不当网页的风险。LLM 已展现出一种涌现能力：理解用户意图，并捕捉用户意图与文档内容之间的语义关系。近期研究表明，LLM 能够准确理解网页搜索者的偏好，并生成高质量的相关性标签 [11]。受此推动，我们开发了 RecoDCG，一种由 LLM 驱动的离线推荐质量指标，便于快速评估新技术。我们进一步使用这些质量标签，使排序阶段具备质量感知能力。

我们首先简要概述生产环境中的网页到网页推荐系统，并说明如何使用 LLM 开发可靠的质量评估指标 RecoDCG，给出我们遵循的一套过程。我们在第 4 节深入讨论质量感知排序系统，并在第 5 节阐述如何将 LLM 用于互补候选生成。

## 第 2 节 系统概览（System Overview）

我们网页推荐功能的关键产品目标，是向用户提供有趣、互补且相关的文档，这些文档与出现在搜索结果前 3 个位置的 URL 相关联。最好的网页推荐，要么满足用户的下一次查询意图，要么提供一种替代视角，要么引入与 URL1 相关的探索性主题。我们将主网页（触发网页）称为 URL1，将推荐候选称为 URL2。在图 1 中，cheatsheet.md 是 URL1，Explore Further 下方被推荐的网页则视为 URL2。

这些推荐只依赖于 URL1，与用户以及用户的搜索查询都无关。在召回阶段（候选选择），我们从 Bing 数千亿网页文档的索引中生成相关候选。系统有多条召回路径：共点击（co-click）、协同过滤、双塔嵌入模型，以及我们将在第 5 节详述的、由 LLM 驱动的新召回通路。如图 2 所示，候选网页被聚合后送入两层排序阶段。

图 2：Bing 网页推荐系统示意图。

### 2.1 候选生成阶段概览（Candidate Generation Stage Overview）

我们的生产系统有多个候选生成器，称为召回路径。每条召回路径都经过调优，以便从 Bing 的 2000 亿网页索引中产生特定数量的候选。这些候选在进入排序阶段之前会被聚合并去重。我们将两个网页之间的共点击（共现点击）定义为：多个 Bing 用户浏览会话中两者都被点击，从而表明二者具有一定程度的相关性。基于共点击信息构建图之后，我们在数十亿网页的规模上用协同过滤（CF）学习网页嵌入。我们训练一个基于 6 层 XLM-Roberta [4] 的双塔 Transformer 模型，以点击日志为标签学习网页嵌入；每个塔处理 URL 及其关联的文本特征。对触发 URL1 做推理时，CF 与双塔模型这两条召回路径都基于嵌入的余弦相似度，用近似最近邻（ANN）搜索检索相似网页 [5]。本文引入一条新的、由 LLM 驱动的 Q' 召回路径，为数亿个 URL1 生成多样且互补的候选。我们在第 5 节详细讨论 Q' recall。

### 2.2 排序阶段概览（Ranking Stage Overview）

系统的排序阶段按顺序包括：

（1）阶段 1：使用较小一组低成本特征的 LightGBM 排序器，主要是不同时间窗口上 URL1–URL2 的点击计数与曝光计数特征。

（2）阶段 2.a：MT RecoLM，一个多任务交叉编码器模型，有两个头，分别针对成对点击预测和推荐质量任务进行训练。

（3）阶段 2.b：使用更大一组、成本更高特征的 LightGBM 排序器，其中包括交叉编码器模型各头的分数。以成对点击预测目标（LTR）进行优化。

（4）阶段 2.c：将阶段 2 的 LightGBM 排序器分数与推荐质量头分数做线性组合。

我们在第 4 节详细讨论质量感知排序。
