## 摘要

领域推荐模型擅长用大量行为数据做物品推荐，像轻量的领域专家，但解释和多轮对话并不擅长。LLM 则强在理解指令、常识推理和与人交互，却不掌握具体商品目录和领域行为规律，电商这类偏离通用世界知识的场景尤其如此；按领域逐个微调既不经济也不高效。

作者把两边接起来，提出 InteRecAgent：LLM 当大脑，推荐模型当工具。摘要先给出把 LLM 变成该代理所需的最小工具集，再给出执行工作流，核心是记忆、用动态示例增强的任务规划，以及反思。这样，连基于 ID 的矩阵分解这类传统模型，也可以通过自然语言接口变成可交互系统。若干公开数据集上，它作为对话推荐系统表现令人满意，并超过通用 LLM。代码放在 https://aka.ms/recagent。

## 1 Introduction

推荐系统已从协同过滤走到融合深度学习的混合方法，但用户越来越用对话来找商品，系统需要听懂并回应多样意图。GPT-3、PaLM 以及 ChatGPT、Claude 这类代理让“把 LLM 放进推荐”变得有吸引力，交互可以比传统打分更自然。作者同时指出三条硬限制：互联网预训练抓不住细粒度、尤其是训练数据极大的领域行为；私有或网上很少的领域数据 LLM 理解不好；预训练截止日期之后的新物品它不知道，用新数据微调又太贵。领域内模型正好补这三处。AutoGPT、HuggingGPT、Visual ChatGPT 代表的做法是 LLM 当大脑、领域模型当工具。

InteRecAgent（Interactive Recommender Agent）把这个范式收成面向推荐的框架，工具分成查询、检索、排序三组，对应日常问询的不同需求。候选物品通常很多，把物品名写进工具的输入输出再塞进提示不现实，因此用 shared candidate bus 存中间状态、让工具之间通信。为了长对话甚至终身对话，再用 long-term and short-term user profile 跟踪偏好和历史，并作为排序工具的输入。这两块一起构成框架里的高级记忆。

规划上作者不用一步一步调用，而用 plan-first execution：一次生成全部工具调用步骤并严格按计划执行，既降低 LLM 推理成本，也方便接上动态示例。对话中先解析用户意图，再检索最相似的少量示例，帮助写出正确计划。另外有反思：另一个 LLM 当批评者，检查结果质量和执行错误；不满意或发现错误就回到初始状态，重新计划再执行。实验里用 GPT-4 当大脑效果很好，于是作者问更小的模型能否充当大脑。他们用 GPT-4 驱动的 InteRecAgent 和用户模拟器交互，做成工具计划的模仿数据，再微调 LlaMA 2，得到 RecLlama；这个 70 亿参数模型作为推荐代理核心，超过了若干更大的模型。贡献归纳为四点：用三组传统推荐工具把交互推荐接成紧凑的 LLM 代理；针对推荐场景补上候选总线、长短用户画像、动态示例增强的先计划策略和反思；用 GPT-4 模仿数据微调出 70 亿参数的 RecLlama；三个公开数据集上有效，在世界知识覆盖较少的领域优势更明显。具体数据集名称和实验表不在这两节。

## 2 Related Work

**2.1 Conversational Recommender System。** 对话推荐被分成两类。一类是基于属性的问答：尽量少轮就把合适物品推出来，交互主要是追问物品属性、逐步收紧兴趣；难点是选哪些属性来问，以及探索与利用的权衡。另一类是开放式对话，处理自由格式的交谈：早期用预训练语言模型做对话理解和回复生成，后来引入外部知识。作者认为这些方法仍难以对复杂问询做推理，也难以和用户保持顺畅沟通，而 LLM 提供了重做对话推荐的机会。

**2.2 Enhancing LLMs。** 参数和数据放大带来上下文学习、指令遵循、规划与推理。推荐里使用 LLM 已是快速增长的方向。模型出现涌现能力之后，研究转向把 LLM 做成带记忆、规划和工具使用的自主代理：外接记忆让模型可以积累；规划上，CoT 和 ReAct 走逐步推理，ToT 和 GoT 走多路径以保证一致和正确，Self-Refine 与 Reflexion 则让模型反思错误再提高后续解题率；工具方面则包括网页搜索、数学工具、代码解释器和视觉模型。作者声称，就他们所知，本文是第一次在推荐系统里探索 “LLM + tools” 这一范式。本节没有实验数字或表号。
