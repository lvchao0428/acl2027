## Abstract

摘要把两类系统的短处对在一起。推荐模型能利用大量行为数据做领域内的物品推荐，也能当轻量的领域专家，但解释和对话做不好。LLM 理解指令、常识推理和跟人说话很强，却不掌握领域目录和行为模式，电商这种偏离通用世界知识的域尤其如此。为每个域去微调 LLM 既不经济也不高效。InteRecAgent 因此让 LLM 当大脑、推荐模型当工具。摘要先给出把 LLM 变成这个智能体所需的最小工具集，再给出一套执行流程：记忆组件、用动态示例增强的任务规划，以及反思。传统的、基于 ID 的矩阵分解一类模型，可以由此带上自然语言界面。作者还用 GPT-4 造了一份模仿数据，并据此微调出一个 7B 模型，称为 RecLlama。三个公开数据集上的实验被用来说明有效，优势在世界知识覆盖较少的域里更明显。

## 1 Introduction

第 1 节沿摘要的对照展开，并把「不能微调每个域」写成设计约束。推荐模型是领域专家，输入输出却是 ID 和分数，解释与多轮对话要另做。LLM 能对话，但私有目录和用户行为不在它的参数里。把整个目录塞进上下文不现实，为每个域做指令微调也不划算。

由此得到的系统形状是工具调用，而不是让 LLM 记住商品。节内点名的最小工具职责是：用查询读物品信息，用检索按条件找候选，再用排序把候选按用户偏好排好。记忆、动态示例规划和反思是为了让多轮执行稳定，不是另一套推荐算法。贡献列表与摘要一致，并强调 RecLlama 是用 GPT-4 的轨迹去带一个 7B 模型，使闭源大脑可以被换掉。实验数字和工具提示里的 SQL 限制不在这一节展开。

## 2 Related Work

第 2 节分两支，用来说明 InteRecAgent 站在对话推荐和 LLM 智能体的交界，而不是再做一个属性问答系统。

**2.1 Conversational Recommender System。** 对话推荐被分成属性问答和开放对话。属性问答要在尽量少的轮数里问到合适的属性，研究点是问哪个属性，以及探索与利用。开放对话处理自由格式的话，早期用预训练语言模型做理解和生成，后来加外部知识。作者认为这两类都难以对复杂问句做推理，也难以把对话维持下去。LLM 被写成改变对话推荐构造方式的机会。

**2.2 Enhancing LLMs。** 这一支从上下文学习、指令遵循、规划与推理，接到推荐里正在变多的 LLM 用法。接着把 LLM 智能体拆成记忆、规划和工具。记忆的例子是外接记忆让模型能积累；规划从 Chain-of-Thought、ReAct 的逐步推理，到 Tree-of-Thoughts、Graph-of-Thoughts 的多路径，再到 Self-Refine 和 Reflexion 的事后反思。工具使用被用来补领域技能。第 2 节的收束是：这些能力可以接到推荐上，但领域目录和行为仍要交给专门模型，而不是指望 LLM 自己记住。工具的具体 SQL 规则留在后文。
