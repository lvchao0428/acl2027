## 摘要（Abstract）

LLM agent 推荐被写成一次范式变化：用推理和角色扮演做自主、自适应的决策，从复杂环境里动态收集并解释用户–物品交互，策略要能跨场景。缺的是标准化评测。AgentRecBench 给三样东西：一个带用户和物品元数据的交互式文本推荐模拟器，场景是经典推荐、兴趣演化和冷启动；一个搭 agent 推荐系统的模块化框架；以及第一个把 10 种经典方法和 agent 方法放在一起比的基准。摘要的结论是 agent 系统更强，并据此给出组件设计准则。基准通过一场公开挑战赛检验，排行榜持续维护。

## 1 Introduction

推荐从规则走到深度学习之后，准确率和效率上去了，仍有三处缺口：结果是黑箱；主要吃历史交互，没用上真实场景里的上下文；依赖人工特征和固定策略，换场景就僵。

LLM agent 被看成能用规划、反思和迭代行动处理复杂任务。相对传统推荐，作者强调三点：用自然语言说出推荐理由；自己从环境里收集个性化上下文，而不是只看 ID 交互；用外部反馈和内部记忆持续改策略。缺基准，就无法判断这些说法是否站得住，也不知道能不能部署。

AgentRecBench 的四项工作写在第 1 节。一是把 Yelp、GoodReads 和 Amazon 做成统一的文本交互环境，用标准函数接口检索，底下是多领域库。二是三种场景：经典任务看一般性能，兴趣演化看动态适应，冷启动看泛化。三是模块化 agent：动态规划、复杂推理、工具使用、记忆。四是对 10 种现有推荐 agent 和传统方法做评测，从能力和局限里抽设计准则。

实用性用 AgentSociety Challenge 说明：全球 295 支队伍，37 天里超过 1400 份提交；开发阶段推荐赛道提升 20.3%，最终阶段再提高 15.9%。贡献再收成三条：多样场景下的首个大规模基准；带多领域数据和标准开发框架的模拟器，形成闭环；从 10 种方法里抽出可执行的设计准则。

## 2 Definition of Agentic Recommender System

agent 推荐被定义成一个 LLM agent 与环境 E = (U, I, H) 交互后给出推荐。U、I 是用户和物品的特征空间；H 是带上下文 c（如评分、评论）和时间戳 τ 的历史交互。每一步 t，agent 看到状态 s_t（用户与物品画像、交互和其他反馈），按策略 π_θ 选动作 a_t。动作空间是物品推荐加上信息寻求动作；θ 参数化推理、记忆等内部模块。图 1 是这个文本环境模拟器的总框架。

和第 1 节呼应，这里把区别于传统方法的特征收成三条：能按场景自己收集个性化上下文，并保持可泛化、零样本的策略；能靠经验和外部反馈改内部表示和决策；会主动发起有目标的交互，而不只是被动应答。模块和实验从后文才展开。
