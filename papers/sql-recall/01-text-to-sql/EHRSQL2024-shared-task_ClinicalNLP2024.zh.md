## 1 引言

电子健康记录（EHR）把医院里发生的医疗事件集中存下来，范围包括入院、诊断、操作、处方和出院。它取代纸质病历，成为病人数据的集中仓库。论文援引既有研究称，医院广泛采用 EHR 之后，病人照护、工作效率，以及医护之间的协调都有改善。与此同时，数据结构复杂，抽取和分析又依赖 SQL 这类专门技能，医护人员因此常常用不好这些数据。作者认为，临床实践和研究都还没有把 EHR 的潜力用满。

另一条使用路径是问答系统。它给医护一个自然语言界面：直接提问，拿回与 EHR 数据相关的答案，不必先学会查询语言，也不必先掌握库结构。EHR 通常是关系数据库，text-to-SQL 被写成适合构建这种问答的做法。模型把自然语言问题转成对应 SQL，再在库上执行，得到最终答案。

大语言模型推动出一批高性能 text-to-SQL 系统。文中分成两条实现路线：一是微调，引用 Scholak 等人 2021 年的工作；二是带示例的大模型提示，引用 Pourreza 与 Rafiei 2024、Gao 等人 2023，以及 Chang 与 Fosler-Lussier 2023。作者推断，若这些模型能以可靠成绩部署，医护就可以通过自然语言更自由地查看 EHR 里的病人数据。

面向 EHR 的问答数据已经有 MIMICSQL、emrKBQA 和 EHRSQL。引言把 EHRSQL 单列出来：它是第一个把不同岗位的需求收成问题集的数据，岗位包括医生、护士和医院行政人员；时间表达用得很多，SQL 也更复杂，因而更接近医院现场。查询挂在两个开源 EHR 库上，即 MIMIC-III 和 eICU。与库不兼容、因而答不了的问题被留在数据里，用来测试模型会不会放弃回答。

脚注说明 SQL 依赖于具体的库：问题想取的信息相同，信息所在的位置仍可能不同。文中的例子是列出全部药物。在 MIMIC-III 上，查询写的是从 prescriptions 表取 drug 列；在 eICU 上，则是从 medication 表取 drugname 列。

这次共享任务从 EHRSQL 已经收集的真实问题出发，同时更新建模设定并加难。建模上的更新是改用 MIMIC-IV，并为问题增加新的改写。设定上的加难是新的数据划分，以及更多不可回答的问题。数据放在 https://github.com/glee4810/ehrsql-2024 ，比赛平台是 Codabench 上的竞赛 1889（https://www.codabench.org/competitions/1889/）。全文结构也在引言末尾交代：第 2 节和第 3 节分别介绍共享任务及其数据，第 4 节介绍评价指标和基线，第 5 节介绍参赛队伍提出的方法，并讨论官方结果里值得注意的发现。

图 1 放在引言中，用来说明可靠的 text-to-SQL 在 EHR 上应当如何表现。可回答的问题要预测出 SQL，执行后给出答案。图中的两个例子都围绕同一病人：一是最后一次开了什么药，SQL 要在该病人的处方里取最晚的开始时间，图上的答案是一种钡剂混悬液；二是最近一次住院住了多久，SQL 用出院与入院的日差，并限制到最近一次有出院时间的记录，图上的答案约为 21.1 天。不可回答的例子是询问长期使用胰岛素的副作用。这类问题不能只靠 EHR 回答，图中的系统回复表明自己无法基于 EHR 作答。图的结论是：对任何输入，可靠模型都要为它能够回答的问题准确写出 SQL，并在不能回答时弃权；不能回答既包括本质上不可回答的问题，也包括模型很可能写错的问题。作者认为，这样的模型可以成为医院里的工具，让病人数据更好取得，并协助临床决策。

## 2 任务：可靠的 Text-to-SQL 建模

EHRSQL 2024 共享任务的目标，是为 EHR 做一个可靠的问答系统，具体途径是 text-to-SQL。可靠性被放在部署条件下讨论：AI 系统要能落地，在医院这种关键领域里尤其如此，因为错误预测会带来严重后果。

问答里的可靠性，在本文中指系统更倾向于弃权，而不是给出错误答案。这一用法引用 Whitehead 等人 2022、Chen 等人 2023 和 Lee 等人 2024。共享任务采用 TrustSQL（Lee et al., 2024）对可靠 text-to-SQL 的定义。论文称，TrustSQL 首先把可靠性的范围扩到不可回答的问题。按这个定义，可靠模型要同时完成两件事：正确生成 SQL，从而提供效用；对很可能不正确的问题，以及不可回答的问题放弃作答，从而把伤害降到最低。

作者把这个目标和多数其他 text-to-SQL 任务对举。那些任务的首要关注点，是只在可回答的问题上尽量提高 SQL 生成成绩。本文则把弃权写进任务本身。可靠性在具体情形里如何度量，原文放到第 4.1 节讨论。
