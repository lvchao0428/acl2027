## 1 引言

电子健康记录是关系数据库，保存病人在医院中的全部病史。从入院、治疗到出院，医院里发生的医疗事件都会写入 EHR。记录既有个体层面的信息，也有群体层面的认识，形式包括表格、文本和图像。医生、护士和管理人员不断与这些记录交互，写入并取回病人信息，以便做出更好的临床决策。

多数医院人员使用的是预先定好规则的转换系统。一旦要查找规则之外的信息，就得经过专门培训，去修改和扩展这套系统。作者把这一点看成充分利用 EHR 的巨大瓶颈。替代办法是做一个能把问题直接译成对应 SQL 的系统：使用者打字或口头提问，系统返回答案，中间不再经过那套复杂流程。论文预期，这样的系统能把 EHR 数据的潜力释放出来，并大大加快任何需要从库中取数的工作。

当时已有的结构化 EHR 问答数据是 MIMICSQL 和 emrKBQA。MIMICSQL 是第一个针对 MIMIC-III 的医疗问答数据，问题用预定义模板自动生成。emrKBQA 来自临床阅读理解数据 emrQA，再落到 MIMIC-III 的结构化记录上。作者在一家大学医院做了问卷调查，结论是：已有数据在好几个方面都远未覆盖医院工作现场的真实需求。

EHRSQL 是新的大规模 text-to-SQL 数据，连接到两个开源库 MIMIC-III 和 eICU。数据以 CC BY-SA 4.0 发布。据作者所知，这是第一个同时做到两件事的 EHR 问答数据：反映医院人员的多样需求，并把医疗问答系统在部署时会遇到的实际问题引进数据集。挑战被写成三点。

问题范围宽。问卷收集的是人们经常针对结构化 EHR 提出的问题，受访者共 222 人，从业年限各不相同，分布见图 1。过滤并做成模板之后，覆盖面从简单取数一直到群体运算。简单一侧包括病人记录，例如测过的生命体征和住院费用；复杂一侧包括诊断某病之后开得最多的前 N 种药，以及计算 N 年生存率。原文表 1 给出抽样问句，并把问句类型和提问部门放在一起。人口学问题如询问出生日期，处方问题如第一次开药的时间，生命体征问题如最近一次动脉收缩压，这些多与护理有关，生命体征还涉及医生、病案和其他岗位。费用问题问的是涉及无创机械通气的平均住院总费用，部门为保险审核。生存率问题问四年生存率最低的五种诊断。纵向统计则问：自 2104 年起、两个月内被诊断为 hypotension nos 的病人，最常被开出的五种药，提问岗位包括医生和护理。这些年份是数据里的时间，不是对公历年份的改写。

问题对时间敏感。问卷让作者看到，医院里的真实问题含有大量时间表达，因为时间是医疗中最关键的因素之一。他们把时间分成三类再与模板组合，用来模拟现场那些依时间而变的提问。表达类型分为绝对、相对和混合；单位包括一次就诊、月和日；区间类型包括自某时起、直到某时，以及在某段之内。更细的构造放在第 3.1.2 节。表 1 的例子与这三类对应：绝对时间如比较同一病人在两个具体时刻的心率，以及询问 2105 年 10 月做过的最后一项标本检验；相对时间如上一次 ICU 就诊期间胃药的日均摄入；混合时间如某病人在「今年 5 月」第一次被开出的药物。

问答系统要值得信赖。论文认为，医疗场景要采纳 AI，可信系统是前提；问答系统也应当只返回准确答案，并拒绝超出自身能力的问题。为检验这一点，数据中放入不可回答的问题，材料是问卷里余下的那些说法。它们答不了，原因是与数据库模式不兼容，或者需要外部领域知识。表 1 的两类例子是：造影检查期间不应当使用哪种药物（需要外部知识，来自护理岗位的提问），以及某病人下一次最早的就诊在什么时候（超出库中模式所能回答的范围，同样来自护理）。

## 2 相关工作

相关工作分成三块：EHR 问答、语义解析数据，以及问答中的不可回答问题。

### EHR 问答

Pampari 等人提出 emrQA，在临床笔记上做问答，问题来自医生的常见提问。Raghavan 等人随后提出 emrKBQA，把 emrQA 改到 MIMIC-III 的结构化病人记录上。由于原数据面向门诊，emrKBQA 的问题范围有限，大多是在问检验结果。脚注写明，在本文写作时 emrKBQA 尚未公开。Wang 等人的 MIMICSQL 第一次把 EHR 问答做成 text-to-SQL 生成：按预定义规则自动出题，再经众包过滤。作者对它的评价是问题范围有限、SQL 简单，而且只限制在五张表上，离医院中的实际用法很远。EHRSQL 的起点则是真实问卷，覆盖多种经常在结构化 EHR 上被问到的问题，涉及的表平均为 13.5 张。表 1 被用来对照这种差异。

### 语义解析数据集

语义解析把自然语言说法转成逻辑形式。这些形式常常是可执行程序，例如 Python 脚本或 SQL。论文把它称为过去几十年自然语言处理中很活跃的方向。WikiSQL 和 Spider 是评估模型在未见数据库上表现的主要数据。WikiSQL 的库取自维基百科的 HTML 表格，领域广，但 SQL 简单，而且都是单表。Spider 针对复杂查询，包括连接和集合运算，表和数据库领域都是多个。其后出现更贴近实际的数据，用来缩小学术设定和应用设定的距离。KaggleDBQA 使用 Kaggle 上的真实数据库，构造领域专用问题，出题时并不倚靠数据库模式。SEDE 处理的是 Stack Exchange 用户在真实使用中提出的复杂 SQL。作者认为自己的动机与这些工作一致：现实中的医疗问答会带来额外的挑战。

### 问答中的不可回答问题

问答研究的早期，不可回答的问题经由远程监督、基于规则的改写，或众包人员的对抗式构造产生。到了语义解析，多数工作假设输入问题都有效、也都能回答。论文指出实际并非如此：为了系统可靠，对每一个输入都返回答案并不总是可取的。Zhang 等人用其他 text-to-SQL 数据和闲聊数据构造不可回答的问题，并把任务做成分类，用来检测一个问题能否回答。EHRSQL 把系统可靠性和语义解析放在同一个数据里处理，不可回答的问题来自问卷，是收集过程中自然得到的。

任务型对话里，同一问题以域外检测的名字被研究过。近期一些工作出于实用考虑，训练时不向模型显式展示域外样本。EHRSQL 沿用这一设定：不可回答的问题只放进验证集和测试集。
