## 第 1 节　引言

电子健康记录的存放方式并不统一。关系库如 PostgreSQL 或 Oracle 把数据组织成表和行，用 SQL 访问。文档库如 MongoDB 把数据看成文档集合，用 MQL 访问。图数据库分成两类：Neo4j 一类的属性图用 Cypher，Ontotext GraphDB 一类的 RDF 图用 SPARQL。关系模型和 SQL 仍是电子健康记录的主要选择。文档模型和图模型更受关注，因为模式灵活，也便于连接分散的数据源。欧洲数字医院试点 AICCELERATE 就用图模型连接病历、医院数据、可穿戴设备与物联网设备。以 SPARQL 为主的 RDF 图库在生命科学中已经常用，医学也在跟上。

库以及底层数据模型会明显改变读写性能和查询复杂度。图模型可以直接表示患者、医生、治疗和病情之间的多对多联系。关系库要完成同样的联系，往往需要代价较高的连接和更复杂的查询。文档库对多对多只有初步支持，更适合数据互联不密、又需要灵活模式的文档集合。数据库研究和工业界早已知道这些差别，文本到查询系统却几乎还没有考察它们。

图 1 用同一请求比较四种语言：找出与某家护理机构相关联的患者姓名。SQL 约 25 个词元、8 个关键词、2 处连接，嵌套深度为 0。Cypher 更短，约 12 个词元、3 个关键词，但要沿 3 段关系遍历，嵌套深度为 1。SPARQL 约 49 个词元、8 个关键词、4 处连接或遍历，嵌套深度为 1。MQL 的聚合管道约 60 个词元、8 个关键词，连接或遍历只有 1 处，嵌套深度达到 5。长度、关键词、连接和嵌套并不朝同一方向变化。

文本到查询系统近来增多，分数也更高，主要得益于 Transformer 和大语言模型。用户用自然语言说出意图，系统在能够访问底层库的前提下生成合法查询，例如 SQL 或 SPARQL。这一点在数字医疗里尤其要紧。护士、医生和行政人员通常不会写复杂查询，现有系统又常常依赖事先规定的规则转换，能提出的问题因此受到限制。

已有数据集大多只覆盖一种数据模型和一种查询语言。文本到 SQL 一侧包括 Spider、WikiSQL、BIRD、ScienceBenchmark、Statbot.swiss 和 EHRSQL。文本到 SPARQL，也就是知识图谱问答，包括 LC-Quad 2 和 Spider4SPARQL。FootballDB 开始在同一个数据库系统内部、用不同模式存放同一批数据，考察数据模型的影响。跨两种模型和语言的比较也刚出现：在 MIMICSQL 上对照 SQL 与 SPARQL，准确率相差 34 个百分点。无论是在医疗领域还是在医疗领域之外，都还没有工作能让文本到查询在多种核心数据模型和多种查询语言上一起评估。这就是本文数据集和基准的目标。

SM3-Text-to-Query 是基于合成患者数据的多模型医疗文本到查询基准，有三项特征。其一，数据来自合成患者模拟器 Synthea，发布内容不涉及真实患者；模式遵循跨机构、跨国使用的医学本体 SNOMED-CT，以支持健康数据互操作。其二，数据库专家为 PostgreSQL、MongoDB、Neo4j 和 RDF 图库 GraphDB 设计表示，并从 Synthea 输出做转换。内容相同，语言分别是 SQL、MQL、Cypher 和 SPARQL，对应关系、文档和图三种模型。作者认为这是第一份同时具备这些特征的基准，系统选择也对照 DB-Engines 排名中使用较广的一类。其三，人工编写 408 条模板，覆盖 Synthea 的主要实体和属性，再用可调抽样填入患者姓名、过敏等信息。每种语言得到 1 万条自然语言与查询的配对，四种语言合计 4 万条。新模板、其他语言、改写，或按 SNOMED-CT 建模的真实患者库，都可以继续接入。

## 第 2 节　相关工作

相关工作按两类回顾：面向医疗数据的文本到查询，以及更一般的基准。

医疗数据方面，MIMICSQL 源自 MIMIC-III，包含 1 万条面向医疗质量保证的不重复问题。为减轻问句结构过于固定的问题，专家自由职业者做过过滤和改写。MIMIC-SPARQL 沿用这一框架，把问题模板改到经过调整的模式上，改用 SPARQL 查询，规模同样约为 1 万条医疗问答。EHRSQL 则是面向电子健康记录的文本到 SQL 基准，数据来自 MIMIC-III 和 eICU。它的 230 条问题模板来自用户调查，并据此生成 2.4 万条 SQL 问句与查询配对。

一般基准方面，WikiSQL 有 8 万条以上文本与 SQL 的配对，查询分布在 24,241 张表上。Spider 是常用的跨领域文本到 SQL 数据，含 10,181 条问题、5,693 条不重复 SQL，覆盖 200 个数据库。KaggleDBQA 建立在 Spider、WikiSQL 这类大规模数据之上，提供带有领域特有数据类型的跨领域集合。BIRD 从 Kaggle、CTU Prague 和 Open Tables 等来源收集 12,751 条不重复问题，涉及 37 个主题；它面向真实应用，例子取自 95 个大型数据库，合计 33.4 GB。ScienceBenchmark 给出三份真实且领域化的文本到 SQL 数据，用来说明领域基准对实际任务的重要性。FootballDB 在单个数据库内部考察不同模式如何影响文本到 SQL，问题来自有终端用户参与的真实部署。

这些工作衬出 SM3 的范围。作者认为，它是第一份能够在关系、图、文档三种核心模型，以及 SQL、SPARQL、Cypher、MQL 四种语言上评估文本到查询的数据集与基准。FootballDB 同样分析模式依赖，但只处理关系模型和 SQL，而且局限在一个数据库内部。模板化构造受到 EHRSQL 启发；SM3 补上的是按广泛使用的医学标准 SNOMED 生成合成数据。因此，这份基准可以对应到各地遵循该医学命名体系的数字健康场景。
