## 引言（Introduction）

自动生成代码被看成人与数据之间的桥梁。关系数据库里的大量数据要靠 SQL 才能做日常查询、编排工作流和业务智能；text-to-SQL 把自然语言写成查询，用来减少重复劳动。大语言模型已经能完成这种转换。基于 GPT-4 的方法在 Spider 1.0 上的执行准确率是 91.2%，在 BIRD 上是 73.0%。

这些高分主要来自非工业库：表和列少，SQL 与问句简单，不同系统的方言也很少进入评测。企业数据分散在多种数据库中，每种方言有自己的语法和函数；应用库可以有数千列和嵌套结构。真实流程还要读项目代码、外部知识和多种上下文，分多步完成清洗、变换和分析。图 1 用一份销售日报把环境摆出来：汇总已完成任务、活动、线索和商机状态；库类似 Salesforce，图中出现第 495 张表，并略去 8695 列；代码侧有模型、宏、配置文件和二十多个文件。示例查询用日期截断和条件分支区分赢单、输单和仍在管道中的商机，再按日期连接活动表。解题要同时看元数据、方言文档和执行反馈。

Spider 2.0 包含 632 个真实的清洗、变换和分析任务。库来自 Google Analytics、Salesforce 等应用，平均约 812 列，数据量到 TB 级，系统包括 SQLite、DuckDB、BigQuery 和 Snowflake，并有嵌套列、多模式等结构。方言材料来自教程、论坛和开源项目。金标准 SQL 平均约 144 个词元，并使用高级函数，例如 `ST_DISTANCE(x_1, x_2)` 计算两点最短距离。每题都配有项目代码、文档和数据库接口。

智能体的输入是项目代码和数据库接口。它用 SQL 以及 Python 或 Shell 与库交互，在库内做变换或抽出分析结论，并根据反馈得到最终结果。为了能和旧的 text-to-SQL 方法比较，作者另建 Spider 2.0-lite 和 Spider 2.0-snow。二者预先给出模式和文档，去掉代码库，只要求输出 SQL，因此不必预测最终答案或改写数据库。引言写明 lite 托管在 BigQuery、Snowflake 和 SQLite，snow 全部托管在 Snowflake。它们与完整版同源。作者把 lite 和 snow 当作现有解析器可以直接做「文本进、SQL 出」的题目，同时指出这种设定接触不到执行反馈，难度仍然很高。第 2.1 节补充：lite 的库仍像完整版那样分布在多种系统上，snow 更集中地考察 SQL 生成。完整版则要求与多种信息源交互，完成变换和分析。

引言用成绩说明缺口。以 o1-preview 为底座的代码智能体只完成 21.3% 的任务。lite 上最强的解析器只解决 5.7% 的问题，与 Spider 1.0 的 91.2%、BIRD 的 73.0% 对照。引言归纳的障碍是：在极大库上做模式链接，处理不同方言，为变换和分析规划嵌套查询，以及使用外部文档和项目级代码。分模型的实验不在这两节。

## 基准构建（Benchmark Construction）

第 2 节给出任务定义、六步标注，以及三套数据的统计。

### 任务定义（Task Definition）

图 2 并列代码智能体和传统 text-to-SQL。完整版给定问题 \(Q\)、数据库接口 \(I\) 和代码库 \(C\)。\(C\) 含有项目上下文、配置和文档，也是被反复修改的 SQL 或 Python。第 \(k\) 次观察和最终答案写成

\[
O_k = \mathrm{execute}(C, I, Q), \qquad A = O_k
\]

\(\mathrm{execute}\) 表示针对问题 \(Q\)，在接口 \(I\) 上运行当前代码 \(C\)。\(O_k\) 是第 \(k\) 轮返回的观察。答案 \(A\) 取最后一次观察，可以是文本、表或数据库。

lite 与 snow 是自包含任务。输入为数据库模式 \(D\)、自然语言问题 \(Q\) 和辅助文档 \(E\)，解析器 \(f(\cdot)\) 在参数 \(\theta\) 下输出 SQL

\[
S = f(Q, D, E \mid \theta)
\]

\(S\) 是预测查询，\(\theta\) 是解析器参数。lite 的库分布在多种系统上；snow 全部托管在 Snowflake，重点是 SQL 生成。

### 标注流程（Annotation Pipeline）

八名计算机专业、精通 SQL 的作者分六步标注。

收集阶段要求每个库超过 200 列，或模式为嵌套结构。筛后保留 74 个 BigQuery、54 个 Snowflake、30 个 SQLite、40 个 DuckDB、10 个 PostgreSQL 和 5 个 ClickHouse 库。再从教程和论坛收集 1021 条复杂 SQL，以及 157 个来自 Fivetran 和 DBT 的变换项目。SQL 按空白分词须超过 50 个词元；作为参照，BIRD 平均 30.9 个词元。查询来自真实项目或教程。最终留下 547 条高质量 SQL 和 78 个 DBT 项目。

第二步改写 SQL，以避免泄漏，并确认改写后没有错误。表层改写占 84.2%，语义改写占 42%；两个比例之和超过 100%，因此有例子同时做了两档。改写结果必须成功执行、时间可接受，并且非空。其中 85.98% 使用方言高级函数，10.76% 还需要 DBT，因而要接入项目上下文。表层改写动的是参数和答案形式：单一渠道改为按会话数排名，过滤条件加难（共享单车比出租车更快），或按选定论文计算原创性分数。语义改写扩大含义：页面浏览顺序改为转化率，地理查询与天气查询合并，或修改项目中的 SQL 与 YML。

随后为 lite 和 snow 收集方言与外部函数文档；完整版保留原始代码库和数据库接口。一句问话写不清的变换，会补上数据模型说明或预置答案文件。自然语言说明按两种设定各写一版。智能体题目可以更口语，因为上下文和预置文件约束着答案；text-to-SQL 题目把条件写全，优先消除歧义。说明由人工撰写，SQL 中的条件都要出现。DBT 项目只进入完整版。初稿之后核对 SQL 与说明是否语义等价，并用语言模型帮助改写。

评测脚本从库中取结果，可处理字符串、表和数据库文件。题目常常不规定返回哪些列，预测表会多出列。脚本只核对说明中的核心列，以减少假阴性。lite 和 snow 必须输出 SQL，比较的仍是执行后的表。每条说明、金标准 SQL 和脚本至少三人审阅，并反复检查正确性、自然性与是否含糊。首轮校验在 45% 的例子上发现错误；第二轮之后降到 5%，随后全部改正。红队评估提交错误结果和格式正确的结果，检查前者是否被判错、后者是否被判对。

### 数据统计（Dataset Statistics）

表 2 比较各基准在测试集上的规模：例子数、库数、每库列数、每条 SQL 的词元数和函数数。星号表示该格来自开发集，因为测试集不可得。外部知识、SQL 方言、项目级代码三列用勾和叉表示是否纳入。

WikiSQL 有 15878 例、5230 个库、每库 6.3 列、12.2 个词元、0 个函数，三列皆叉。Spider 1.0 有 2147 例、40 个库、27.1 列、18.5 个词元，开发集上的函数数为 0，三列皆叉。KaggleDBQA 有 272 例、8 个库、23.4 列、13.8 个词元、0 个函数，表中只勾外部知识。SEDE 有 857 例、1 个库、212.0 列、46.9 个词元、1.4 个函数，三列皆叉。BIRD 有 1789 例、15 个库、54.2 列、30.9 个词元，开发集平均 0.4 个函数，并勾选外部知识。lite 有 547 例、158 个库、803.6 列、144.5 个词元、6.5 个函数，勾选外部知识与方言。snow 同为 547 例、152 个库、812.1 列、161.8 个词元、6.8 个函数，勾选与 lite 相同。完整版有 632 例、213 个库、743.5 列、148.3 个词元、7.1 个函数，三列都勾，是表中唯一的项目级设定。

图 3 是这 213 个库的系统构成，与收集清单一致：BigQuery 34.7%（74 个），Snowflake 25.4%（54 个），DuckDB 18.8%（40 个），SQLite 14.1%（30 个），Postgres 4.7%（10 个），ClickHouse 2.3%（5 个）。表 3 改按 632 道题统计，百分比因此不同：BigQuery 214 题（33.86%），Snowflake 198 题（31.33%），SQLite 135 题（21.36%），DuckDB 68 题（10.76%），Postgres 10 题（1.58%），ClickHouse 7 题（1.11%）。正文写明，85.98% 的例子要使用方言专用函数，金标准 SQL 平均 7.1 个；表 3 把「含函数」另计为 474 条，占 75.00%。

难度按金标准 SQL 的空白词元划分。少于 80 为简单，160 题（25.32%）；不少于 80 且少于 160 为中等，279 题（44.15%）；不少于 160 为困难，193 题（30.54%）。分区表 54 题（8.54%），多个模式 140 题（22.15%），嵌套模式 117 题（18.51%）。答案为表的 392 题（62.03%），字符串或数字 162 题（25.63%），整个数据库 78 题（12.34%）。项目级 DBT 任务同样 78 题（12.34%），需要文档的 82 题（12.97%）。这些库还包含按日更新的动态表，类型、体量和范围更广。

题目来自真实教程和论坛，覆盖清洗、变换和分析，SQL 的列数、词元和函数都高于旧基准。完整版为每题提供代码库，其中一部分是用 DBT 管理的项目级数据变换。做对这类题，需要在项目和数据库中查找，读懂文档，处理很长的上下文，并通过多步执行写出多种查询。
