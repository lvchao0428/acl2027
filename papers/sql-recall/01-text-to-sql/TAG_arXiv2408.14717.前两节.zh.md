## 摘要

用自然语言查询数据库的系统，若能同时用上语言模型的推理与知识和数据管理系统的可扩展计算，用户就可以对自己的数据源提出任意自然语言问题。现有方法和基准没有充分覆盖这种设定。Text2SQL 只处理能写成关系代数的问题，只是真实用户问题中的一小部分。Retrieval-Augmented Generation（RAG）则限于对一条或少数几条记录做点查。

本文提出 Table-Augmented Generation（TAG），作为一种统一、通用的范式，用来回答数据库上的自然语言问题。TAG 要表达的是此前较少被研究的、语言模型与数据库之间的多种交互，从而把模型的世界知识和推理用到数据上。作者系统性地构造基准来研究这个问题，发现标准方法正确回答的查询不超过 20%，并据此认为这一方向仍需要进一步研究。基准代码发布在 https://github.com/TAG-Research/TAG-Bench 。

## 1 Introduction

语言模型让用户用自然语言问数据，带动了大量 Text2SQL 和 RAG 研究。作者根据自身经验，包括 Databricks 的内部负载和客户，认为用户的问题经常超出这两种范式：既要数据库的逻辑推理，也要现代语言模型的自然语言推理。真实业务问题往往同时需要领域知识、世界知识、精确计算和语义推理。数据库提供的是最新的领域数据，以及语言模型不擅长的大规模精确计算。

语言模型从两个方向补数据库。一是对文本做语义推理。Databricks 客户调查里的例子包括：产品 X 的哪些评论是正面的，以及某一时期销售额为什么下降。前者要对自由文本做情感分析，后者要概括趋势，都不是传统数据库的精确计算或关系原语能直接表达的。二是用训练进权重的世界知识补上表模式里没有写明的信息。一个 Databricks 内部问题是：表里有账户名、产品和收入，问“retail”这个垂直行业的 QoQ 趋势。系统必须知道业务如何定义 QoQ（上一季度到本季度，或去年同季到今年同季），以及哪些公司算零售。这适合预训练或微调过的语言模型。

Text2SQL 只适合有直接关系等价物的那部分问句，处理不了需要语义推理或世界知识的问题。判断评论是否正面，可能要对每一行用模型做分类；解释销售额为何下降，则要跨许多行汇总。RAG 只做基于相关性的少数记录点查，再调用一次模型。计数、数学和过滤都留给容易出错的模型；长上下文上的表现也限制了它在生成阶段按规模推理数据。

TAG 用三步把两者合在一起，如 Figure 1。查询合成 syn 把任意自然语言请求 \(R\) 变成可执行的数据库查询 \(Q\)；查询执行 exec 在数据库上算出相关数据 \(T\)；答案生成 gen 利用 \(R\) 和 \(T\)，由语言模型生成最终自然语言答案 \(A\)，编排方式可以是迭代或递归。写成：

- 查询合成：\(\mathrm{syn}(R) \rightarrow Q\)
- 查询执行：\(\mathrm{exec}(Q) \rightarrow T\)
- 答案生成：\(\mathrm{gen}(R, T) \rightarrow A\)

Text2SQL 和 RAG 被看成 TAG 的特例，各自只覆盖有限的用户问题。作者给出第一个端到端 TAG 基准，问题需要模型的推理和知识。评测包括普通 Text2SQL 和 RAG，以及两个更强的基线：带语言模型生成的 Text2SQL，以及带语言模型重排序的检索。各类查询上，每个基线的 exact match 都没有超过 20%。他们在 LOTUS 运行时上写的手工 TAG 流水线，准确率比这些基线高出最多 20%–65%。这个差距被用来说明高效 TAG 系统值得做。

## 2 The TAG Model

TAG 接收自然语言请求 \(R\)，返回扎根于数据源的自然语言答案 \(A\)。系统实现查询合成、查询执行和答案生成三步。为便于处理，这里把 TAG 定义成这三步的一次迭代，也可以扩展成 multi-hop。

2.1 Query Synthesis 中，syn 根据 \(R\) 生成数据库要执行的查询 \(Q\)。这一步要判断哪些数据与问题相关（例如借助表模式），并把请求语义解析成可执行查询。查询语言不限定，文中的例子用 SQL。Figure 1 的问句是：总结票房最高、且被视为 “classic” 的爱情片的评论。表里有片名、票房、类型和评论。模型生成的 SQL 会用到 movie_title、review、revenue 和 genre。该例子里的数据库 API 能在 SQL 中执行语言模型用户定义函数，因此这一步还会为每一行调用模型，以判断哪些电影是经典。

2.2 Query Execution 中，exec 执行 \(Q\) 得到表 \(T\)，由数据库引擎在大量存储数据上高效完成。接口可以来自多种系统，后文再展开；有的接口允许基于语言模型的算子，使执行阶段也能用到模型的世界知识和推理。Figure 1 的查询是 SQL 上的选择加排序：用模型按 movie_title 判断是否经典，用普通条件过滤 genre 为爱情片，再按 revenue 排序找票房最高者。图中结果集中在电影 Titanic 的评论，其票房标为 2257.8；同图里未被选中的例子包括动作片 Shang-Chi，票房 432.2。

2.3 Answer Generation 与 RAG 的生成步类似。gen 用语言模型，依据 \(R\) 和已经算出的 \(T\) 生成答案 \(A\)。Figure 1 的最后阶段输出对 Titanic 评论的总结，图中的回答大意是这些评论讨论了银幕上的化学反应。相关数据 \(T\) 被编码成字符串，与原始请求一起送给模型，由模型对 review 列做语义推理来完成总结。
