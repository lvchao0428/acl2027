## 第 1 节 Introduction

把自然语言问题写成 SQL，也就是 Text2SQL，在作者看来同时是自然语言理解和人机交互问题。若系统足够可靠，不懂查询语言的人也能直接向结构化数据库提问，数据分析的使用门槛会因此下降。大语言模型已经明显提高了 SQL 的流利程度和表面覆盖，但“写出来像 SQL”仍不等于“写得对并且能够执行”。多表连接、嵌套逻辑，以及对 schema 的细致理解，使复杂查询继续成为瓶颈。现有多数做法是在问题与 SQL 的配对上做监督微调。作者的判断是，这种训练往往推不动可靠、可泛化的 SQL 所依赖的中间推理。

Arctic-Text2SQL-R1 被定义为一套强化学习框架，以及按这套框架训练出的模型族。奖励被刻意做轻：只根据 SQL 执行是否正确来打分，避开脆弱的部分奖励，让训练更稳，并与最终任务对齐。他们同时强调，这个奖励必须和经过筛选的数据、合成数据、基于模型的选择，以及一个强的监督初始化放在一起。在作者的表述里，高质量数据、强监督初始化和简单的执行奖励，共同产生准确、可扩展、稳健的 Text2SQL 模型。

引言把后续贡献收成几条可检验的说法。第一条是强化学习形式本身：只看执行的轻量奖励可以跨模型规模和基准泛化，不必靠复杂奖励设计来换稳定训练和强结果。第二条是榜单表现。在六个差异较大的 Text2SQL 基准上，该模型族同时超过面向 SQL 的专用模型和通用大模型，文中点名 GPT-4o 与 DeepSeek-V3，用来说明跨领域泛化。BIRD 排行榜上，32B 模型的执行准确率是 71.83%，加上 self-consistency 后升到 73.84%。排名被限定在公开了细节的系统之中：在这个口径下 Arctic-Text2SQL-R1 居首，作者同时强调透明度、可复现性和可获得性。规模效率被单独列出，7B 模型已经超过此前 Zhai 等人报告的 70B 量级系统。

第三条转向数据和训练。作者总结数据过滤、合成数据生成和基于模型的选择的实用做法，并说明在线强化学习的作用：它接在强监督检查点之后，再配上设计过的提示，可以继续抬高性能。第四条是评价范围。六个数据集覆盖不同的 schema 复杂度和查询难度，用来提供泛化证据，并防止过拟合到单一数据集或单一评价格式。第五条是推理阶段。value retrieval 和 majority voting 这类简单扩展，能以很小的系统开销再提高准确率，被当作走向实际部署的依据。第六条是给后续工作的经验：实验同时报告成功结果和负面结果，为以后基于强化学习的 Text2SQL 提供可操作的参考。

## 第 2 节 Related Work

相关工作把这篇论文放在两条研究线上：如何做出更稳的 Text2SQL 系统，以及如何用强化学习加强语言模型的推理。

前一条从通用推理讲起。近期研究表明，只要对逻辑正确性和逐步推理给出明确奖励，强化学习就能明显加强大模型的推理，模型有可能自己找到有效策略，其形态接近结构化的人类推理。数学题上，针对逐步正确性或最终答案准确率做强化学习微调会带来明显提升；代码生成上，偏好优化和基于人类反馈的强化学习提高了代码的有效性与效率。这些方法大多建立在策略梯度上。较早的代表是 PPO，较新的代表是 GRPO。GRPO 不把每条生成孤立打分，而是在一组回答之间做相对比较。作者认为，当一道题存在多个合理解时，这种组内比较尤其有用，因为它推动模型分辨什么样的推理才算高质量。文中的例子是 DeepSeek-R1-Zero：在 GRPO 下，模型只因最终答案正确而获得奖励，却发展出多步思维链和自我验证。作者同时指出，这类框架常常依赖精心构造的偏好数据，以及能够反映逻辑细节的奖励模型。Arctic-Text2SQL-R1 从这里取用的是 GRPO，并把奖励集中到最终能否正确执行，希望模型把查询的组合结构从头考虑到尾。

后一条回顾 Text2SQL。早期系统靠规则和手工文法，遇到语言歧义或 schema 变化就很脆。神经序列到序列模型把语义解析的一部分自动化了，但往往仍需要精细的 schema 编码器和很强的监督。预训练大模型改变了局面，一批工作用它们做不依赖模板的 SQL 生成。模型不加专门训练时常常已有基本 SQL 能力，可一旦变成复杂的多表查询，表现就有限，除非显式鼓励组合式推理。这一观察推动了思维链提示、查询分解，以及基于执行的反馈。

在这个背景里，用强化学习做 Text2SQL 的工作正在变多。它们往往把奖励做成多项之和，把执行反馈、语法合法性、字符串部分重叠、schema 一致性等捆在一起。作者借用强化学习用于语义解析时的观察，指出复杂奖励工程可能鼓励表面的 reward hacking。因此他们主张更简单、以执行为中心的奖励，并回溯到更早的 Seq2SQL。推论是：奖励项更少，实践中可以更稳，也可以更有效。

表 1 把这一对照写成具体配置。Reasoning-SQL 用 GRPO，奖励同时包含执行、语法、n-gram、LLM 评分、schema 和格式。SQL-R1 同样用 GRPO，项为执行、长度、语法和格式。Think2SQL 用 GRPO，项为 precision、recall、基数，以及计两次的格式项。ExCoT 使用 DPO，奖励只看执行。Arctic-Text2SQL-R1 也用 GRPO，表中列出的是执行与语法。正文据此区分最近的推理式 Text2SQL 和成对偏好优化：作者认为自己的特点，是把精简的数据过滤流水线、基于组的相对策略优化，以及严格以执行为中心的奖励放进同一套设计。引言把奖励概括为只看执行正确性，表 1 则同时列出语法项；两处并列出现，执行正确性仍是他们相对多项奖励所强调的主信号。
