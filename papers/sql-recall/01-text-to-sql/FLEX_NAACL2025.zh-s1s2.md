# FLEX: Expert-level False-Less EXecution Metric for Reliable Text-to-SQL Benchmark

## Abstract 摘要

Text-to-SQL 系统对于在各行各业把自然语言翻译成 SQL 查询已变得至关重要，使非技术用户能够执行复杂的数据操作。随着这些系统变得更加复杂，对准确评测方法的需求也在增加。然而，最普遍的评测指标执行准确率（Execution Accuracy, EX）仍然表现出许多假阳性和假阴性。因此，本文引入 FLEX（False-Less EXecution），一种使用大语言模型（large language models, LLMs）评测 text-to-SQL 系统的新方法，以模拟人类专家级别的 SQL 查询评测。借助全面的上下文和精细的标准，我们的指标提高了与人类专家的一致性（Cohen’s kappa 从 62 提高到 87.04）。我们的大量实验得出若干关键认识：（1）模型性能平均提高超过 2.6 个点，实质性地影响 Spider 和 BIRD 基准上的排名；（2）EX 对模型的低估主要源于标注质量问题；（3）模型在特别困难的问题上的表现倾向于被高估。本工作有助于对 text-to-SQL 系统进行更准确、更细致的评测，并可能重塑我们对该领域最先进性能的理解。

## 1 Introduction 引言

Text-to-SQL 系统把自然语言问题翻译成 SQL 查询，通过使数据获取更加普及并促进数据驱动的决策，已在各行各业变得不可或缺（Shi et al., 2024; Hong et al., 2024）。随着这些系统变得更加复杂，准确而高效的评测方法日益重要。虽然最初的评测依赖人类专家，但这一做法对于大规模评估过于耗时、成本过高。为此，Spider（Yu et al., 2018）等基准引入了执行准确率（Execution Accuracy, EX）指标，并被 BIRD（Li et al., 2023c）等其他工作广泛采用。然而，EX 指标根据查询的执行结果来评测，具有显著局限，可能导致评估偏离人类专家。我们的分析表明，EX 会因数据库状态的巧合而错误地判定查询有效，或因问题有歧义而不公平地惩罚正确查询，从而误估模型生成正确且有效 SQL 查询的能力（Pourreza and Rafiei, 2023b）。尽管已提出基于 LLM 的评测方法（Kim et al., 2023; Zheng et al., 2023; Zhao et al., 2024），它们因上下文有限而表现欠佳。它们未能利用关键的上下文信息，难以处理噪声金标准问题，并采用不适合 text-to-SQL 评测的含糊标准。因此，在已有的 text-to-SQL 基准上评估时，它们甚至不如传统的 EX 指标。

为解决这些问题，我们提出 FLEX（False-Less EXecution），一种利用 LLM 来模拟专家级 SQL 查询评测的新方法。FLEX 专门为评测 text-to-SQL 任务而设计，并通过全面的上下文分析克服现有局限，同时考虑自然语言问题、数据库模式和外部知识。它还利用精心设计的评测标准，以及用于评估查询正确性的详细指南。我们的方法通过 FLEX 判断与人类专家评测之间的强一致性得到验证，其一致性显著更高（Cohen’s kappa 为 87.04），高于现有 EX 指标（62.00），并优于此前基于 LLM 的方法。

为展示 FLEX 的实际影响，我们在 Spider 和 BIRD 基准上重新评测了 50 个公开的 text-to-SQL 模型，揭示出若干关键认识。本研究使用 BIRD-dev 集的 20240627 版本；由于金标准被修改，所得 EX 分数与先前研究不同。如表 1 所示，模型排名发生显著变化，尤其是在 BIRD 上，从而对模型能力给出更准确的评估。此外，FLEX 对错误情形进行了分类，并识别出噪声标注是当前基准低估模型性能的主要因素。如图 1 所示，FLEX 分数总体上高于 EX 分数，表明 FLEX 捕捉到先前被低估的模型能力方面。此外，FLEX 发现模型在 BIRD 的困难问题上被高估，从而标出未来研究应关注的地方。

我们的关键贡献如下：1）我们识别当前 text-to-SQL 评测指标的关键局限，尤其是执行准确率（EX）指标；2）我们引入 FLEX，一种基于 LLM 的新评测方法，它与人类专家推理对齐，并与专家评估表现出更好的一致性。3）通过用 FLEX 重新评测 50 个 text-to-SQL 模型，我们揭示显著的排名变化，并对基准和最先进模型提供更清晰的理解，强调需要更先进的评测方法。FLEX 框架公开于 https://github.com/HeegyuKim/FLEX 。

## 2 Related Work 相关工作

精确匹配（Exact Matching, EM）和执行准确率（Execution Accuracy, EX）被提出来评测 Spider 中的 text-to-SQL 系统（Yu et al., 2018）。EM 评估两条查询在语法层面的等价；然而，它容易出现高假阴性率，因为同一逻辑意图可以用多种查询表述来表达。因此，EX 被用作 BIRD（Li et al., 2023c）中查询准确率的主要指标，关注执行结果而不是句法形式。尽管有这一改进，EX 仍然因标注质量问题而遭受假阴性，并且可能产生假阳性：它会奖励那些碰巧与金标准得到相同结果的错误查询。这些局限凸显了需要更稳健的语义评测方法。

基于 LLM 的评测作为人类评估者的替代，在评估自然语言生成模型的人类偏好方面已变得流行。MT-Bench（Zheng et al., 2023）和 AlpacaEval（Li et al., 2023e）等框架利用 LLM 作为评判者，提供比人类评估更快、更省成本的评测。然而，这些框架主要依赖专有的 GPT-4（OpenAI et al., 2024），这带来可复现性风险，因为提供方可能在不通知的情况下更改或停用模型。作为回应，Kim et al. 引入开源 LLM 评判者 Prometheus，在 GPT-4 的性能水平上提供一种可复现且无成本的替代。尽管如此，Prometheus 主要聚焦一般的人类偏好评测，而不是 text-to-SQL 评测这类专门任务。

为了专门利用 LLM 做 text-to-SQL 评测，Zhao et al. 提出 LLM-SQL-Solver。该方法不区分假阳性与假阴性，展示了 LLM 用两种提示策略评估两条查询之间执行等价性的能力：Miniature-and-Mull，评估两条查询之间的语义等价；以及 Explain-and-Compare，要求 LLM 比较它们显著的逻辑差异。尽管有所进展，LLM-SQL-Solver 仍不足以完全取代 EX 作为评测指标。我们将在第 4.3 节考察这些具体局限。
