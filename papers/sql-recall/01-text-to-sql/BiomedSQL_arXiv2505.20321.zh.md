## 第 1 节 Introduction

作者把现代生物医学研究写成数据驱动的日常工作：电子健康记录、高通量检测和人群规模研究不断填入大型数据库，研究者每天都要查询它们。自然语言接口，尤其是 text-to-SQL，看上去能降低使用这些资源的门槛。现有系统却多半把查询生成当成句法翻译，把问句结构映射成 SQL 结构，缺少更深的领域理解。这种抽象一进入生物医学就失效。领域专家常问的是带科学惯例的问题，例如哪些 SNP 与阿尔茨海默病的关联最显著，或哪些药物靶向在帕金森病中上调的基因。问题背后是统计阈值、药物审批路径，以及跨模态的因果推断。

全基因组显著性界值、试验阶段过滤、效应量解释这类约定，单看 schema 是看不见的。通用 text-to-SQL 基准，如 Spider 和 BIRD，推动了领域进展，却不考察复杂领域里的科学推理。面向电子健康记录的基准更强调时间逻辑或患者检索，也没有把大规模数据库上的科学推理单独、严格地测出来。作者所说的科学推理，包括像生物医学分析人员那样推断统计显著性阈值，或沿着本体做多步过滤。

BiomedSQL 被用来填这个空缺，并被称作第一个专门评估生物医学 SQL 生成中科学推理的基准。它包含 68,000 条问题、SQL 和答案三元组，对应真实研究中的复杂科学查询。这些查询由模板展开，模板来自 40 道互不重复的问题。问题由领域专家撰写并核验，标准是对真实生物医学研究有用，并且确实能用结构化数据回答。查询运行在一个经过协调、公开可用的 BigQuery 数据库上，库中整合了基因与疾病关联、多组学因果推断和药物审批记录。这些数据源由日常从事计算研究的领域专家核验为当时最新。每道题都要求模型把带细微差别的定性科学语言写成可执行的 SQL。

图 1 给出评测流程：模型看到问题和数据库 schema，生成 SQL，执行后还要把结果收成针对原问题的简短自然语言回答。图中的示例是在问 C9orf72 是否存在会提高帕金森病风险的突变，生成的查询需要写入显著性阈值和效应方向，再根据执行结果作答。作者用这套流程比较多种提示方式和交互方式。结论是生物医学 text-to-SQL 仍有很大空间：表现最好的 Gemini-3-Pro 执行准确率只有 58.1%；他们自己的多步智能体 BMSQL 提高到 62.6%，仍低于专家的 90%。

贡献对应三件事。基准方面，发布这 68,000 条由模板扩增的三元组，用来在真实生物医学数据库上评估 text-to-SQL 的科学推理。基础设施方面，公开 BigQuery 数据库、专家编写的标准查询、执行结果和评测工具。评测方面，比较一批模型、提示风格和交互范式，其中包括自建的 BMSQL，并报告与领域专家之间大约 25 到 30 个百分点的差距。

## 第 2 节 Related Work

相关工作分成四条：通用 text-to-SQL 基准、临床数据库上的 text-to-SQL 基准、自然语言处理中的科学推理评测，以及 BiomedSQL 与已有基准的直接比较。

通用基准推动了跨领域的 SQL 生成。Seq2SQL 处理的是简单的单表查询。Spider 用 200 个多表数据库把泛化做成主要困难，并催生了 schema linking。KaggleDBQA 和 BIRD 进一步加入企业级数据的现实约束，要求模型注意数据质量、连接和延迟。尽管如此，在 BIRD 这类通用基准上，最好的模型按执行准确率仍比人低 15% 到 20%。作者认为这些基准考的是句法翻译和 schema 泛化，不是科学查询背后的推理。BiomedSQL 使用带领域语义的多表 schema，要求模型解释统计惯例和生物医学本体，而这些能力此前没有被评估过。

临床数据库方向面向电子健康记录。MIMICSQL 在 MIMIC-III 上构造合成 SQL 基准，schema 较窄。EHRSQL 向临床医生众包，在 MIMIC-III 和 eICU 上收集一千条以上的自然语言查询，把时间逻辑和数据稀疏显成难点。更新的数据还把查询分散到关系、文档和图等不同数据模型上，以反映电子健康记录越来越混杂的形态。这些基准的重点是以患者为中心的信息检索，以及依赖 schema 的查询映射。BiomedSQL 转向生物医学研究中的发现：查询要做隐含的科学推理，例如套用显著性阈值、合并多组学关联、理清药物、基因与疾病的关系。作者把它写成对现有临床基准的补充，侧重推理密集的数据探索。

第三条讨论自然语言处理里的科学推理。SciFact 和 EntailmentBank 分别考察科学主张的验证，以及基于文本证据的多步推理。Chain-of-Thought 和 ReAct 这类提示方法，在一般场景和生物医学场景的多步推理上都提高过成绩。较新的工作把评测延伸到结构化数据，SQL-R1 和 Science Hierarchography 评估模型在本体和关系程序上的推理。作者认为，即便有这些进展，把模型推理对齐到生物医学所要求的严格性、安全性和可解释性，仍然是未解决的问题。BiomedSQL 的切入点是：在大型生物医学知识库的 text-to-SQL 里，检查模型能否推断并落实科学推理，包括统计阈值、本体解析和复杂过滤。

直接比较放在表 1。BiomedSQL 被写成有四点独特之处：三元组数量最多；平均 SQL 长度处在最长的一档，仅次于 EHRSQL；评测目标明确是科学推理，而不是 schema 翻译；既评生成的 SQL，也评模型的自然语言回答。它还是表中唯一在 schema 本身之外考察推理的生物医学基准，也是唯一使用 BigQuery 这种云原生 SQL 方言的基准，以便更接近部署环境。

表中的数量支持前两点。MIMICSQL 有 10,000 个问题和 10,000 条查询，平均 57.4 个 token。EHRSQL 为 24,000 与 24,000，平均 109.9 个 token。SM3 有 10,000 个问题和 40,000 条查询，平均 26.1 个 token。BIRD 为 12,751 与 12,751，平均 50.6 个 token。BiomedSQL 为 68,227 与 68,227，平均 96.4 个 token，因而在条数上最多，在长度上只短于 EHRSQL。表中另有 Knowledge 与 Template 两列：Knowledge 只标在 BIRD 和 BiomedSQL 上，Template 除 BIRD 外都标上。科学推理、自然语言回答和 BigQuery 三列只有 BiomedSQL 被标上。正文没有再解释 Knowledge 与 Template 的判定标准。
