# FinSQL: Model-Agnostic LLMs-based Text-to-SQL Framework for Financial Analysis

## ABSTRACT 摘要

Text-to-SQL 为操作关系数据库提供零代码接口，在金融分析中受到很多关注，因为金融专业人员可能并不擅长 SQL 编程。然而，直到目前，还没有面向金融分析的实用 Text-to-SQL 基准数据集，现有 Text-to-SQL 方法也没有考虑金融应用中数据库的独特特征，例如普遍存在的宽表。为解决这些问题，我们收集一个实用的 Text-to-SQL 基准数据集，并提出一个与模型无关的、基于大语言模型（Large Language Model, LLMs）的 Text-to-SQL 框架，用于金融分析。基准数据集 BULL 收集自恒生电子（Hundsun Technologies Inc.）的实际金融分析业务，包括基金、股票和宏观经济数据库。此外，所提出的基于 LLM 的 Text-to-SQL 框架 FinSQL，从提示构造、参数高效微调和输出校准的角度，对金融 Text-to-SQL 给出系统处理。在 BULL 上的大量实验结果表明，FinSQL 以较小的代价取得了最先进的 Text-to-SQL 性能；此外，在需要少样本跨数据库模型迁移的场景中，FinSQL 可以带来高达 36.64% 的性能提升。

CCS 概念：信息系统—关系数据库查询语言。关键词：Text-to-SQL、大语言模型（Large Language Models, LLMs）、金融分析（Financial Analysis）。

## 1 INTRODUCTION 引言

Text-to-SQL 旨在把自然语言问题变换为可执行的 SQL 查询，从而为关系数据库实现低代码操作。它可以为不熟悉 SQL 的非专业数据库用户方便数据访问过程，并在各个领域，尤其是金融分析中受到很多关注。金融专业人员（例如投资顾问）需要频繁查询相关数据库，但他们通常并不擅长 SQL 编程。因此，Text-to-SQL 对金融分析非常重要，并已受到很多关注。然而，目前没有面向金融分析的 Text-to-SQL 基准数据集，现有 Text-to-SQL 方法也没有考虑金融分析所用数据库的独特特征。

为解决这些问题，我们基于恒生电子智能投资助手产品，构建一个面向金融分析的实用 Text-to-SQL 数据集。该产品服务超过 50 家金融机构（包括支付宝、招商银行等），并服务数百万个人用户。这个被称为 BULL 的数据集包含三个数据库，分别对应基金、股票和宏观经济。此外，该数据集中有 4,966 对由恒生电子的金融专业人员、数据科学家和软件工程师标注的自然语言问题–SQL 对。而且，BULL 同时有英文和中文版本。与广泛使用的 Text-to-SQL 基准数据集（例如 Spider [37] 和 BIRD [20]）相比，BULL 的每个数据库有多得多的表，每张表有多得多的列，如表 1 所示。此外，BULL 中的表名和列名常常用缩写或含糊的表示来表达。这些特点要求金融 Text-to-SQL 模型支持很长的输入上下文，并具有很强的上下文理解能力。

幸运的是，基于大语言模型（LLMs）的 Text-to-SQL 可以满足这些要求，最近也已提出若干基于 LLM 的 Text-to-SQL 方法。然而，现有最先进的基于 LLM 的 Text-to-SQL 方法通常依赖 OpenAI 的 API，例如 GPT-3.5-turbo 或 GPT-4，这些 API 昂贵，并且有信息泄露风险。因此，这些方法不能用于信息隐私至关重要的金融应用。为避免信息泄露，一种可行方式是采用开源 LLM（例如 LLaMA [30] 和 Baichuan [35]），并在私有领域中训练它们。然而，这面临三个挑战：（1）模式链接困境与数据稀缺。金融数据库通常有大量列和表，难以在问题与模式项之间建立联系。此外，由于标注成本，已标注的问题–SQL 对在数量和多样性上都有限。这些问题阻碍简洁而多样的提示的构造，从而妨碍模型性能；（2）消耗资源的微调与跨数据库泛化困难。在下游任务上微调 LLM 需要在多块 GPU 上计算数日。与模型更新和迭代相关的巨大成本构成相当大的挑战。此外，把模型迁移到新数据库会带来显著成本，这阻碍跨数据库迁移；（3）输出不一致。由于固有的随机性以及采样这一解码策略，LLM 常常生成不一致的输出，导致句法不正确且无效的 SQL 查询。

为应对这些挑战，本文提出一个与模型无关的、基于 LLM 的金融 Text-to-SQL 模型训练与推理框架，称为 FinSQL。它可以用来基于任何开源 LLM 开发 Text-to-SQL 模型。图 1 展示 FinSQL 的总体概览，它由三个关键组件组成：提示构造、参数高效微调，以及输出校准，分别对应上述挑战。具体而言，提示构造由并行模式链接方法和混合数据增强方法组成，它们有助于构造更简洁、更多样的提示，并从输入侧增强模型性能。参数高效微调组件采用低秩适配（Low-Rank Adaptation, LoRA），只微调很小比例的参数（<1%），以获得面向不同业务场景的权重插件，并通过插件中心管理这些插件。基于这一插件中心，数据库特定的 Text-to-SQL 模型可以高效地实现少样本跨数据库迁移。在输出校准中，执行 SQL 后处理以增强所生成 SQL 的正确性。这三个组件促成了 FinSQL 的优越性能。

我们的贡献可以概括如下：

- 我们提出 BULL，一个面向金融 Text-to-SQL 的实用基准数据集。
- 我们提出 FinSQL，一个与模型无关的、基于 LLM 的 Text-to-SQL 框架，用于金融分析。
- 在 BULL 上的大量实验结果表明，FinSQL 与模型无关，并且能够取得最先进的性能；此外，在需要少样本跨数据库模型迁移的场景中，FinSQL 可以带来高达 36.64% 的性能提升。

## 2 RELATED WORKS 相关工作

本节介绍各种 Text-to-SQL 数据集。我们探讨各种数据集的显著特征，并突出这些数据集与真实世界金融场景之间的现有差距。此外，我们概述 Text-to-SQL 模型的近期发展。

### 2.1 Text-to-SQL Datasets Text-to-SQL 数据集

高质量数据集在 Text-to-SQL 系统的开发与评测中起着重要作用。早期 Text-to-SQL 数据集如 GeoQuery [38] 和 Scholar [14] 提供了有价值的认识，但它们在查询数量上有限，聚焦单数据库场景，并且 SQL 查询相对简单。另一方面，WikiSQL [41] 和 Spider [37] 提供超过 10,000 条 SQL 查询，支持跨数据库迁移场景，并引入复杂的多表查询。尽管取得了这些改进，这些数据集与真实世界场景之间仍有相当大的差距。真实应用中使用的数据库往往更大，并且可能提供外部知识来帮助用户理解模式信息。KaggleDBQA [15] 在八个数据库上创建了 272 条 SQL 查询，并引入外部知识来解释列的含义。BIRD [20] 提供更多的 SQL 查询样本和更大的数据库，并在问题与数据库内容之间纳入外部知识，使 Text-to-SQL 数据集更适合真实世界情形。然而，这些数据集仍然不能完全满足业界的需求，业界需求往往更复杂、更具挑战性。如表 1 所示，在真实工业场景中，数据库中的表数和列数远远超过现有开源数据集。这给现有 Text-to-SQL 方法在纳入模式信息方面带来挑战，使它们难以在这一场景中有效工作。

### 2.2 Text-to-SQL Models Text-to-SQL 模型

Text-to-SQL 模型近年来取得了显著进展 [25]。早期基于规则的方法依赖手工模板来生成 SQL，显示出一定效果，但严重依赖人工定义的规则。它们对其他场景的适用性有限，缺乏可扩展性，并且难以泛化。为克服这些局限，研究者基于 Seq2Seq 架构开发 Text-to-SQL 方法。IRNet [10] 使用编码器表示问题和模式，而 RAT-SQL [31]、LGESQL [1] 和 S²SQL [13] 采用图神经网络来捕捉问题与模式之间的对齐关系，然后用解码器生成 SQL 查询。随后，随着大语言模型的发展，T5、mT5、LLaMA 等预训练模型展示出增强的语言理解与泛化能力。基于微调这些模型的方法在 Text-to-SQL 任务上取得了更好的结果。Graphix [19] 使 T5 具备多跳推理能力。Picard [28] 使用约束解码器来提高所生成 SQL 查询的质量。RESDSQL [18] 使用两阶段方法，先检索与问题相关的模式元素，再生成相应的 SQL 查询，它目前是 Spider 排行榜上基于微调的 SOTA 方法。更近一些，大语言模型（LLMs）展现出显著能力并留下深刻印象。借助上下文学习（In-context learning）技术，这些模型可以理解人类指令并执行任务，而无需重新训练。目前，Spider 排行榜上的领先方法基于使用上下文学习的 GPT 模型，例如 C3、DIN-SQL 和 DAIL-SQL。然而，这些方法涉及调用 OpenAI API，可能成本高昂并带来隐私风险。此外，指令模板需要针对不同场景重新设计。
