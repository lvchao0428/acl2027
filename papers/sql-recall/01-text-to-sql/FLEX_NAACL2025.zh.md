## 1 引言

Text-to-SQL 把自然语言问题写成 SQL，论文认为它已经在多个行业里成为关键能力：不会写查询的人也能访问数据，并据此做决策。系统越复杂，评测就越要同时做到准确和可扩展。最初的做法是请人类专家逐条判断，但作者指出，专家评测在大规模评估里又慢又贵。Spider 为此引入执行准确率 EX，只看查询在库上跑出来的结果；BIRD 等后续基准也沿用了这一指标。

作者认为 EX 和专家判断会系统性偏离。查询只要执行结果碰巧相同就会被判对，即便逻辑并不符合问题，原因是当前数据库的状态恰好掩盖了错误条件，这是假阳性。反过来，能够正确表达问题的查询也可能因为问题本身含糊而被判错，这是假阴性。两种偏差都会歪曲“模型能否写出正确且有效的 SQL”这一能力。已有的大模型评测并没有补上这个缺口。论文点名的一类方法上下文用得有限：该用的上下文没有用上，有噪声的标准答案处理不好，评判标准又过于含糊，并不适合 Text-to-SQL。放到已有基准上、拿专家判断做参照时，这些方法的表现甚至低于传统 EX。

FLEX（False-Less EXecution）是针对上述问题提出的评测方法。它用大模型模仿专家判断 SQL，并且只为 Text-to-SQL 设计。相对只看执行结果，FLEX 把自然语言问题、数据库模式和外部知识一起纳入上下文，并使用专门拟定的正确性准则和配套说明。作者用与人类专家的一致性来验证这套判断：FLEX 的 Cohen’s kappa 为 87.04，EX 为 62.00，同时也高于此前的大模型评测。论文没有在这两节给出 kappa 的计算公式。

为了看换尺子会不会改写对模型的认识，作者用 FLEX 重评了 50 个公开的 Text-to-SQL 模型，基准是 Spider 和 BIRD。脚注说明，BIRD 用的是 20240627 版开发集；标准答案做过修改，因此这里的 EX 与先前研究中的数字不同。表 1 把 BIRD 榜前十按 FLEX 重排，并把 FLEX 减去 EX 定义为低估误差。名次变化在 BIRD 上尤其明显，作者认为重排后的名次更能反映模型能力。

表中上升的主要是若干提示型系统。SuperSQL 的 FLEX 为 64.08、EX 为 57.37，差值 +6.71，名次上升 2 位，排到第一。TA-ACL 为 59.97 对 55.67（+4.30，上升 2 位）。DAIL_SQL 的两个 9-shot 变体分别是 59.26 对 53.52（+5.74，上升 3 位）和 58.47 对 53.06（+5.41，上升 4 位）。不带这组设定的 DAIL_SQL 为 51.83 对 45.89（+5.93，上升 2 位）。另一侧几乎没有被低估，个别还被略微高估。CHESS-GPT-4o-mini 虽有 +3.59（62.71 对 59.13），名次仍下降 1 位，落到第二。DTS-SQL-BIRD-GPT4o 只有 +0.39（58.47 对 58.08），下降 3 位，并与 DAIL_SQL_9-SHOT_QM 以相同的 FLEX 并列第五。三个 SFT CodeS 模型的差值分别是 +0.46、−1.30 和 −0.20，名次下降 3 位、2 位和 1 位；其中 7B 和 3B 的 FLEX 低于 EX。

FLEX 还对错误情形做了归类，并把有噪声的标注看成当前基准低估模型的主要原因。图 1 比较的是 Spider 上的 EX 与 FLEX，红色对角线表示两种分数相等；点的整体位置高于这条线，作者据此认为 FLEX 记回了一部分原先被低估的能力。与此同时，在 BIRD 特别难的问题上，FLEX 发现模型成绩被高估。引言把这块标成后续研究需要盯住的地方。

贡献被收成三点。第一，指出现行 Text-to-SQL 指标的关键缺陷，重点是 EX。第二，提出 FLEX：它与专家的推理方式对齐，并且和专家判断更一致。第三，用 FLEX 重评 50 个模型，展示显著的名次变化，从而把基准和当前最强系统的含义说清楚，并强调评测方法本身需要升级。框架代码公开在 https://github.com/HeegyuKim/FLEX 。

## 2 相关工作

Spider 同时提出了精确匹配 EM 和执行准确率 EX。EM 判断两条 SQL 在句法上是否等价。同一种逻辑意图可以写成很多种查询，所以 EM 的假阴性很高。BIRD 因此把 EX 当作查询准确率的主要指标，比较的是执行结果。相关工作接着写明，换到执行结果之后问题仍在：标注质量会让本应算对的查询对不上标准答案，形成假阴性；错误查询也可能碰巧得到和标准答案相同的结果，从而被记成假阳性。作者由此认为，评测需要更稳的语义比较。

另一条线是用大模型代替人工，判断自然语言生成是否符合人的偏好。MT-Bench 和 AlpacaEval 让大模型当裁判，比人工更快、也更省钱，但它们主要依赖闭源的 GPT-4。提供方若修改或停用模型，已有评测就难以复现。Kim 等因此提出开源裁判 Prometheus，在不付调用费用的前提下，把可复现性做到接近 GPT-4 的水平。论文同时指出，Prometheus 面向的是通用人类偏好，覆盖不到 Text-to-SQL 这种专门评测。

把大模型专门用于 Text-to-SQL 评测的工作，作者重点讨论 Zhao 等的 LLM-SQL-Solver。该方法不区分假阳性和假阴性，而是展示大模型可以判断两条查询在执行意义上是否等价。它使用两种提示策略：Miniature-and-Mull 用来评估语义等价，Explain-and-Compare 让模型比较双方在逻辑上的重要差别。作者承认这一步说明大模型有能力做执行等价判断，但仍不足以整个替换 EX。更细的局限留在第 4.3 节，不在本导读范围内。
