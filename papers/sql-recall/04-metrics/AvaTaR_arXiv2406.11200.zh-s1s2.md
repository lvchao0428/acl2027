# AVATAR: Optimizing LLM Agents for Tool Usage via Contrastive Reasoning

## Abstract 摘要

大语言模型（large language model, LLM）智能体在利用外部工具与知识以提高准确率、减少幻觉方面已展现出突出能力。然而，开发能让 LLM 智能体有效使用这些工具与知识的提示技术，仍然是启发式且劳动密集的工作。本文提出 AVATAR，一种新颖的自动化框架，优化 LLM 智能体以有效利用所提供的工具，从而提升给定任务上的表现。优化过程中，我们设计比较器（comparator）模块，通过对训练数据中采样的正例与负例做对比推理，迭代地向 LLM 智能体提供有洞察且全面的提示。我们在四个复杂的多模态检索数据集（含文本、视觉与关系信息）以及三个通用问答（question-answering, QA）数据集上演示 AVATAR。我们发现 AVATAR 在全部七项任务上一致优于最先进方法，应用到新情形时具有较强泛化能力，在检索数据集的 Hit@1 指标上平均相对提升 14%，在 QA 数据集上提升 13%。代码与数据集见 https://github.com/zou-group/avatar 。

## 1 Introduction 引言

由大语言模型（LLM）驱动的自主智能体为复杂问题求解提供了很大前景 [6, 39, 41, 55, 65]。这些智能体在推理 [46, 47, 54, 55] 与规划 [8, 13, 14, 62] 上表现出显著能力。此外，外部工具扩展了其功能，使其能访问外部或私有数据以及专门操作，例如与知识库和搜索引擎交互的 API。这些工具使智能体能执行多步问题求解与多样信息检索等复杂任务，这对复杂检索与问答（QA）至关重要 [13, 21, 26, 33, 38, 40, 48]。

尽管 LLM 智能体能力可观，要设计有效提示、引导它们完成面向真实问题求解的多阶段过程仍然困难。该过程包括：（1）把复杂问题分解为带更简单步骤的可执行计划；（2）有策略地使用所提供的工具收集相关信息；最后（3）综合中间结果，产生连贯且准确的回答。每一步都需要大量人工，以及多次试错来打磨提示。

现有方法主要关注用复杂的、人工设计的 “mega-prompts” 直接部署智能体 [18, 24, 55]，这需要大量人工试错。然而，这种手工打造的巨型提示也可能导致脆弱实现和次优准确率（见图 2(a)）：ReAct 智能体 [55] 很容易对顾客关于特定产品的查询给出平凡且误导的答案。进一步，把 LLM 用作优化器的现有研究 [4, 5, 45, 50, 56, 60, 64] 往往不能充分打磨用于加强工具集成与使用的复杂策略。缺少策略性优化，会使智能体应用在复杂真实场景中效果较差、且难以泛化。

**本文工作：AVATAR。** 为应对这些挑战，我们提出 AVATAR，一个自动化框架，优化智能体以实现有效的工具利用与出色的任务表现。具体而言，我们利用对比推理的关键见解，构建比较器模块（“训练器”），生成整体性的指令与提示（即计算一个稳健的 “gradient”），以优化 actor LLM。我们在知识库检索这一具有挑战的任务上演示该框架——这些任务涉及复杂的多阶段过程与大量工具使用——以及通用 QA 任务。具体而言，AVATAR 包含两个阶段：

- **优化阶段。** 优化框架（图 1）的核心是一个比较器 LLM，它自动生成整体性提示，教 actor LLM 区分有效与无效的工具使用。比较器接收正、负数据样本——当前智能体分别表现好与表现差的样本——以识别智能体表现出的总体差距与系统性错误。与容易对单个数据点过拟合的逐样本指令不同，通过把多个样本构造成一个 “batch”，比较器可以提取更稳健的 “gradient” 并 “反向传播” 给 actor。换言之，比较器可以通过按批的对比推理提供更有效、自适应的提示，帮助智能体识别求解有挑战的多阶段问题时的缺陷。遵循先前方法 [30, 41, 56, 63]，我们还维护一个存放精选历史指令的记忆库，以防止 actor LLM 重复先前的错误。
- **部署阶段。** 优化阶段之后，可以选择表现最好的提示所对应的 actor 用于测试实例。此外，在复杂检索任务中，经由 AVATAR 框架的迭代优化会更新 actor，使其动作序列更有效、更可泛化，从而在部署时能直接泛化到新的用户询问。在图 2(b) 中，优化后的 actor 形成三种新策略：1）通过抽取多方面属性来精确分解问题；2）通过精细且稳健的评分系统有效使用工具；3）由学习到的系数决定的不同分数的策略性组合，以保证准确而全面的检索。

**实验评估。** 我们在四个检索数据集和三个 QA 数据集上进行大量实验。检索任务高度复杂，涉及文本、视觉与关系信息等多模态数据。AVATAR 一致优于最先进方法，Hit@1 指标有 14% 的大幅提升。值得注意的是，仅用 25 次迭代，AVATAR 就把 FLICKR30K-ENTITIES [35] 上的 Hit@1 从初始的 5.1% 提升到 28.6%，把 STARK-PRIME [49] 上的 Recall@20 从 30.3% 提升到 39.3%。对通用 QA 数据集，AVATAR 平均优于最先进方法 13%。这些通过对提示的迭代更新获得的改进，突出了 AVATAR 优化智能体以完成复杂任务并有效使用工具的能力。我们的主要贡献是：

- 我们提出 AVATAR，一种新框架，通过自动生成整体性提示的比较器模块，优化 actor 以实现有效的工具利用。
- 我们在四项复杂检索任务与三项 QA 任务上演示 AVATAR，它在任务表现与泛化能力上显著优于现有智能体方法。
- 我们全面分析优化过程中 actor 的演化，强调比较器如何自动提供有针对性的指令，从而改进并泛化 actor。

## 2 Related Work 相关工作

**LLM 智能体。** 近期研究利用 LLM 出色的语言理解与推理能力 [1, 41, 47, 54, 55] 来完成下游任务。对需要更强能力的复杂任务，先前工作把 LLM 定位为可以与环境交互的智能体 [4, 6, 13, 18, 21, 26, 27, 40, 48, 55]、利用外部工具 [6, 28, 31, 33, 36, 38, 39, 66, 68]，并积累经验 [7, 61]。例如，ReAct [55] 以交错方式进行推理与行动，从 Wikipedia 检索信息以支持推理。

**用于检索的 LLM 智能体。** 先前研究通过预训练 [2, 9, 16, 57]、重排序 [12, 42] 与提示技术 [11, 18]，把 LLM 智能体用于信息检索（Information Retrieval, IR）系统。在 IR 系统中，检索器模块直接影响下游任务表现，例如检索增强生成 [20, 29, 30] 与知识密集型问答 [34, 52]。例如，EHRAgent [40] 面向电子健康记录问答，能够通过结构化的工具使用规划过程与交互式编码机制检索相关临床知识。然而，这些 LLM 智能体通常使用启发式（zero-shot）提示，或依赖 few-shot 示例 [18, 25, 40, 55] 完成下游任务，缺少关于如何生成有效检索策略与工具辅助动作的更有依据的指导。

**智能体优化。** 在优化 LLM 智能体这一方向，先前工作通过微调或指令调优修改 LLM 骨干的参数以增强智能体能力 [3, 15, 19, 23, 32, 33, 37, 43, 51, 58, 59]，或通过迭代提示调优生成更好的提示 [11, 18, 45, 50, 56]。最近，Zhang et al. [60] 根据执行历史迭代更新智能体的函数来训练智能体。然而，这些方法没有明确考虑针对工具使用的优化，也没有考虑对复杂多阶段任务的影响。此外，增强智能体泛化能力 [10, 31, 44] 对真实应用至关重要，但受到的关注较少。本文聚焦于通过一种新的对比推理机制自动生成整体性指令，目标是有效的工具使用与智能体的泛化能力。与微调方法相比，AvaTaR 的优势是只需要一小部分训练数据与工具描述，因而更易适应、计算开销更低。
