# ACORN: Performant and Predicate-Agnostic Search Over Vector Embeddings and Structured Data

## Abstract 摘要

应用越来越多地使用混合模态数据，必须同时搜索向量数据（例如嵌入后的图像、文本与视频）以及结构化数据（例如属性与关键词）。针对这种混合搜索设定，已有方法要么性能差，要么只支持严重受限的搜索谓词集合（例如仅小规模的等值谓词），因而对许多应用不切实际。为此，我们提出 ACORN，一种高性能且与谓词无关（predicate-agnostic）的混合搜索方法。ACORN 建立在 Hierarchical Navigable Small Worlds（HNSW）之上，这是一种先进的、基于图的近似最近邻索引，并可通过扩展现有 HNSW 库高效实现。ACORN 提出谓词子图遍历（predicate subgraph traversal），用以模拟一种理论上理想、但并不实用的混合搜索策略。ACORN 与谓词无关的构建算法旨在使这一搜索策略有效，同时支持广泛的谓词集合与查询语义。我们在已有基准数据集（谓词集合简单、基数低）以及先前方法无法支持的复杂多模态数据集上系统评估 ACORN。结果表明，ACORN 在所有数据集上达到最先进性能，在固定召回率下，吞吐量比先前方法高 2–1,000×。

## 1 Introduction 引言

由于现代深度学习模型的表示能力，向量嵌入已成为一类强大的一等数据类型，广泛用于检索增强生成 [3, 65] 或基于相似度的搜索 [18, 21, 42]。因此，向量数据库与索引在许多生产场景中被越来越多地采用。这些系统为嵌入后的非结构化数据（例如图像、文本、视频或用户画像）提供高效的近似最近邻（approximate nearest neighbor, ANN）搜索接口。然而，许多应用必须同时查询非结构化数据与结构化数据，从而需要把 ANN 搜索与谓词过滤结合起来。例如，电商网站上的顾客可以搜索与参考图像相似的 T 恤，同时按价格过滤 [64]。同样，做文献综述的研究者可以用自然语言查询，并按发表日期、关键词或主题过滤 [54]。数据科学家做异常检测时，也可以检索那些看起来像参考狗图像、但标签为 “cat” 的误分类图像 [2, 7]。

要利用多样的数据模态，应用需要能有效支持混合搜索查询的数据管理系统，即带结构化谓词的相似度搜索。这类系统需要：（1）查询性能，即在选择性、属性相关性与规模等工作负载特征变化时仍能高效、准确地搜索；（2）有表达力的查询语义，即支持事先未知的多样查询谓词（例如用户输入的关键词、范围搜索或正则匹配）。不幸的是，现有系统达不到这些目标。三种常用方法是预过滤（pre-filtering）[62, 64]、后过滤（post-filtering）[1, 5, 62, 64, 67]，以及面向低基数谓词集合的专用数据结构 [25, 49, 63, 66]。预过滤先找出数据集中通过查询谓词的全部记录，再在过滤后的向量集合上做暴力相似度搜索。该方法扩展性差，在大规模数据上对中到高选择性谓词变得低效。后过滤则先搜索 ANN 索引，再去掉不满足查询谓词的结果。由于离查询向量最近的数据库向量未必通过谓词，后过滤通常必须扩大搜索范围。这往往代价很高，尤其当搜索谓词选择性低、或与查询向量相关性低时，如图 2 所示。Milvus [62]、Weaviate [1]、AnalyticDB-V [64] 与 FAISS-IVF [5] 都基于这两种核心方法构建系统，并受其性能限制。

认识到这些限制，近期工作为低基数、且由等值谓词算子构成的混合搜索负载构造专用索引。例如，Filtered-DiskANN [25] 优于先前基线，但把谓词集合的基数限制在大约 1,000，且只支持等值谓词。HQANN [66] 与 NHQ [12] 同样把谓词集合限制为少量等值过滤器，并且每条数据只允许一个结构化属性。这些方法往往不实用，因为许多应用的谓词集合很大或无界，且事先未知。一般而言，可能的谓词集合基数随每个属性的基数指数增长，而属性基数本身可能很大。因此，我们转而提出与谓词无关的索引，以支持任意且无界的谓词集合。

本文提出 ACORN（ANN Constraint-Optimized Retrieval Network），一种面向高基数与无界谓词集合的、高性能且与谓词无关的混合搜索新方法。我们提出两种索引：ACORN-γ，面向高效率搜索；ACORN-1，面向资源受限环境下较低的构建开销。两种方法都修改分层可导航小世界（HNSW）索引——一种用于 ANN 搜索的先进图索引——并且易于在现有 HNSW 库中实现。

ACORN 同时处理预过滤与后过滤的性能限制，以及专用索引的语义限制。ACORN 提出搜索时的谓词子图遍历。顾名思义，该策略遍历由通过查询谓词的节点所诱导的 ACORN 索引子图。ACORN 把索引设计成使这些任意谓词子图近似一个 HNSW 索引。与预过滤和后过滤不同，这使得 ACORN 即使在查询向量与谓词的相关性发生变化时仍能提供次线性检索时间；我们发现这种相关性变化是现有混合搜索系统的主要挑战。ACORN 还通过与谓词无关的构建来服务广泛的谓词集合，该构建改变 HNSW 的算法以形成更稠密的图。具体而言，我们在 ACORN-γ 中引入基于目标谓词选择性阈值的、与谓词无关的邻居扩展策略；该阈值可在知道或不知道谓词集合的情况下经验估计。与此同时，我们提出与谓词无关的压缩启发式，以便在保持高效搜索的同时管理索引空间占用。我们还探索搜索性能与构建开销之间的权衡，设计 ACORN-1 以近似 ACORN-γ 的搜索性能，并进一步降低资源受限环境下的建索引时间（time-to-index, TTI）。

我们在四个数据集上系统评估 ACORN-γ 与 ACORN-1：SIFT1M [35]、Paper [63]、LAION [55] 与 TripClick [54]。评估既包括先前专用索引能够服务的、谓词集合简单且基数低的已有基准，也包括具有数百万可能谓词、现有索引无法处理的更复杂数据集。在每个数据集上，ACORN-γ 在 0.9 召回率下达到最先进的混合搜索性能，每秒查询数（queries per second, QPS）比先前方法高 2–1000×。具体而言，ACORN 在已有基准上 QPS 高 2–10×，在新基准上高 30× 以上，在 2500 万向量规模的数据上高 1,000× 以上。我们发现 ACORN-1 在经验上近似 ACORN-γ：在固定召回率下 QPS 至多低 5×，但 TTI 比 ACORN-γ 低 9–53×。详细评估表明 ACORN 的谓词子图遍历策略与谓词无关构建技术是有效的。

## 2 Background 背景

现有近似最近邻（ANN）搜索方法可大致分为基于树的 [15–17, 19, 28, 45, 50, 56]、基于哈希的 [9–11, 24, 26, 29, 30, 40, 41, 44, 46, 52, 59, 69]、基于量化的 [23, 27, 34, 35, 39] 以及基于图的 [22, 25, 32, 47, 48, 58, 68]。

图 1：在 HNSW 索引上搜索的示意图。搜索路径以蓝色箭头表示，从第 2 层开始，在第 0 层的查询点（绿色）结束。

本文以 HNSW 为基础。它是一种基于图的方法，在高维数据上经验表现最好之一，我们将其改造以支持混合搜索。

基于图的 ANN 方法因其在多种 ANN 基准上的先进表现而流行 [13, 57]。这些方法通常用贪心路由策略搜索：从预定义入口点出发遍历图索引。索引本身构成邻近图 \(G(V,E)\)，每个数据点是一个顶点，边连接邻近点。索引构建算法通常旨在近似 Delaunay 图的子图 [38]。虽然 Delaunay 图保证贪心路由算法收敛，但对任意度量空间无法高效构建 [51]。因此图方法关注更易处理的 Delaunay 子图近似，例如相对邻居图（Relative Neighbor Graph, RNG）[37, 60] 与最近邻图（Nearest-Neighbor Graph, NNG）[8, 20]。

### 2.1 Hierarchical Navigable Small Worlds 分层可导航小世界

如图 1 所示，HNSW 形成层次化、多层、度数有界的图索引。下面简要概括 HNSW 的搜索与构建算法。

HNSW 构建算法把每个点迭代插入图索引，以构造度数有界的可导航图，度数由参数 \(M\) 指定。对每个插入元素 \(v\)，首先用指数衰减的概率分布随机选择最大层索引 \(l\)，并由常数 \(m_L = 1/\ln(M)\) 归一化。层分配概率保证期望特征路径长度随层索引增加。直观上，最上层包含最长程的链接，搜索算法最先遍历；最底层包含最短程的链接，搜索算法最后遍历。插入过程分两阶段。第一阶段从顶层开始、自预定义入口点向下到第 \((l+1)\) 层，迭代执行贪心搜索。在这些层的每一层，贪心子程序选择单个节点，作为进入下一层的入口点。第二阶段，贪心搜索从第 \(l\) 层迭代到第 0 层。此时每一层的贪心搜索选择 efc 个节点作为候选边。在这些候选中，至多 \(M\) 个按基于 RNG 的剪枝算法被选为 \(v\) 的邻居 [31]。在第 0 层，度数上界提高到 \(2\times M\)，经验上可改善性能。

HNSW 搜索算法从多层图最上层的预定义入口点开始遍历，如图 1 所示。遍历随后自顶层向下采用迭代搜索策略。每一层用贪心搜索选择单个节点，作为进入下一层的入口点。到达底层后，算法不再贪心选择单个节点，而是贪心选择要返回的 \(K\) 个最近元素。我们在算法 1 中概述该过程。搜索参数 efs 通过控制底层贪心搜索期间动态候选列表的大小，在搜索质量与效率之间提供权衡。

```
Algorithm 1: HNSW-ANN-SEARCH(x_q, K, efs)
Input: 查询向量 x_q，要返回的最近邻个数 K，动态候选列表大小 efs
Output: 距 x_q 最近的 K 个元素
e ← hnsw 图的入口点
W ← ∅  // 当前最近邻集合
L ← level(e)  // hnsw 顶层
for l ← L ... 1 do
    e ← SEARCH-LAYER(x_q, e, ef = 1, l)
end
W ← SEARCH-LAYER(x_q, e, ef = efs, l = 0)
return 从 W 中取出距 x_q 最近的 K 个元素
```
