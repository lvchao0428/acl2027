# RELBENCH: A Benchmark for Deep Learning on Relational Databases

> 版权声明：本文档为同目录英文论文「摘要与正文前两节」的中文译文，仅供论文快速阅读与选题使用。译文不替代原文，不用于发表、再分发或商业用途。版权归原作者及出版方所有。原文件：`relbench-v1-arxiv-2407.20060.pdf`。

## Abstract / 摘要

我们提出 RELBENCH，一个用图神经网络解决关系数据库上预测任务的公开基准。RELBENCH 提供跨越多种领域和规模的数据库与任务，旨在成为未来研究的基础设施工具。我们用 RELBENCH 对关系深度学习（Relational Deep Learning, RDL）（Fey et al., 2024）做了第一次全面研究。RDL 把图神经网络预测模型与（深度）表格模型结合起来，后者从原始表中抽出初始的实体级表示。端到端学习的 RDL 模型充分利用编码在主键–外键链接中的预测信号，从而显著离开“手工特征工程加表格模型”这一主导范式。为了对照此前的这一金标准来彻底评估 RDL，我们做了一项深入的用户研究：由一位有经验的数据科学家为每个任务手工构造特征。在这项研究中，RDL 学到了更好的模型，同时把所需的人力减少了一个数量级以上。这表明深度学习在解决关系数据库上的预测任务时很有力量，并借由 RELBENCH 打开许多新的研究机会。

## 1 Introduction / 引言

关系数据库是使用最广的数据库管理系统，支撑着数字经济的很大一部分。它们之所以流行，是因为按表存储使维护相对容易，并且可以用 SQL 这类强大的查询语言简单地访问数据。正因为如此，许多领域的人工智能系统都建立在存放于关系数据库中的数据之上，包括电子商务、社交媒体、银行系统、医疗、制造，以及开放的科学知识库（Johnson et al., 2016; PubMed, 1996）。

尽管关系数据库很重要，其中丰富的关系信息通常被放弃了，因为没有一种模型架构能够处理各式各样的数据库结构。数据往往被“展平”成更简单的格式，例如单张表，这一步常常靠手工特征工程完成，然后再使用标准表格模型（Kaggle, 2022）。这会显著损失预测信号，并且需要数据抽取流水线，而这些流水线经常引入错误，并增加软件复杂度。

为了充分利用实体之间关系里编码的预测信号，一种新的提议是把关系数据重写成精确的图表示：数据库中的每个实体是一个节点，边表示主键–外键链接，节点特征用深度表格模型抽出。这一做法称为关系深度学习（RDL）（Fey et al., 2024）。图表示使得图神经网络（Graph Neural Networks, GNNs）（Gilmer et al., 2017; Hamilton et al., 2017）可以用作预测模型。RDL 是第一种端到端可学习的神经网络模型，能够接触关系数据库中全部可能的预测信号，并有潜力打开新的预测能力。然而，关系深度学习的发展受限于研究基础设施的完全缺乏，包括：（i）用于比较方法的标准化基准数据库和任务；（ii）RDL 的初始实现，包括把数据转成图以及训练 GNN；（iii）关于关系深度学习是否有效的初步研究。

**图 1.** RELBENCH 使人们能够在关系数据库上训练和评估深度学习模型。RELBENCH 支持与框架无关的数据加载、任务指定、标准化的数据划分、标准化的评估指标，以及用于跟踪进展的排行榜。RELBENCH 还包括 Fey et al. (2024) 关系深度学习蓝图的一个初步实现。

这里我们提出 RELBENCH，第一个面向关系深度学习的基准。RELBENCH 旨在成为未来关系深度学习研究的基础设施，提供一组覆盖多种领域的数据库，包括电子商务、问答平台、医疗和体育。RELBENCH 的数据库在规模上跨越若干数量级，从 74K 个实体到 41M 个实体，时间跨度也很不相同，训练数据从 2 周到 55 年不等。它们的关系结构差异也很大：表的总数在 3 到 15 之间，列的总数从 15 到 140。每个数据库带有多个预测任务，共计 30 个，包括实体分类、实体回归和推荐，每一项都因其现实重要性而被选入。

除数据库和任务之外，我们发布开源软件，以使关系深度学习易于获得。这包括：（i）RELBENCH Python 包，便于加载数据库和任务；（ii）关系深度学习的第一个开源实现，设计成便于研究者修改；（iii）用于跟踪进展的公开排行榜。我们在全部 RELBENCH 任务上全面评测了初始的 RDL 实现，并与多种基线比较。最重要的基线是一种强的“数据科学家”做法：我们招募了一位有经验的人，为每个任务手工构造特征，再送入表格模型。这是目前在关系数据库上建立预测模型的金标准。这项研究已开源以保证可复现。研究发现，RDL 模型在准确度上与数据科学家的模型持平或更好，同时平均把人工工时减少 96%，把代码行数减少 94%。这构成了对 RDL 核心承诺的第一次实证演示，并指向一种人们期待已久的、面向关系数据的端到端深度学习方案。

我们的网站（https://relbench.stanford.edu）是进入 RDL 的综合入口，介绍 RELBENCH 的数据库和任务，提供 GitHub 上的代码、完整的关系深度学习蓝图，以及把新数据库和新任务加入 RELBENCH 的教程，以便研究者试验自己关心的问题。

## 2 Overview and Design / 概述与设计

RELBENCH 提供一组多样的真实关系数据库，以及与每个数据库相关联的一组现实预测任务。具体而言，我们提供：

- 关系数据库：由通过主键–外键关系连接的一组表组成。每张表有若干列，存放关于每个实体的多样信息。有些表还带有时间列，表示实体被创建的时间（例如交易日期）。
- 关系数据库上的预测任务：由一张训练表（Fey et al., 2024）定义，其中有实体 ID（Entity ID）、种子时间（seed time）和目标标签等列。种子时间表示应在何时预测目标，并过滤未来数据。

下面概述 RELBENCH 的关键设计原则，重点是数据整理、数据划分、研究上的灵活性，以及开源实现。

**Data Curation / 数据整理。** 关系数据库很普遍，因此候选的预测任务很多。为了做基准测试，我们仔细整理了一组关系数据库和任务，选择标准是它们具有丰富的关系结构和列特征。我们还采用以下原则：

- 领域多样：为使在 RELBENCH 上发展出来的算法能用于广泛的应用领域，我们从多种领域选取真实的关系数据库。
- 任务类型多样：任务覆盖广泛的真实用途，包括三种有代表性的任务类型：实体分类、实体回归和推荐。

RELBENCH 的数据库汇总于表 1，覆盖电子商务、社交、医疗和体育。这些数据库在行数（即数据规模）、列数和表数以及时间范围上差异显著。任务汇总于表 2，每一项都对应一个有实际意义的预测问题，例如预测客户流失、预测临床试验中的不良事件数量，以及向用户推荐帖子。

**Data Splits / 数据划分。** 数据按时间划分：模型在直到 `VAL_TIMESTAMP` 为止的行上训练，在 `VAL_TIMESTAMP` 与 `TEST_TIMESTAMP` 之间的行上验证，在 `TEST_TIMESTAMP` 之后的行上测试。我们的实现在推断时小心地隐藏 `TEST_TIMESTAMP` 之后的数据，以系统地避免测试时的数据泄漏（Kapoor and Narayanan, 2023），并使用 Fey et al. (2024) 提出的一种简洁办法，通过时间邻居采样避免训练和验证期间的时间泄漏。一般而言，避免时间泄漏是设计者的责任。我们建议在可能时使用我们仔细测试过的实现。

**Research Flexibility / 研究灵活性。** RELBENCH 的设计是为了给未来的研究方向留出很大自由。例如，同一关系数据库内的 RELBENCH 任务共享相同的（`VAL_TIMESTAMP` 与 `TEST_TIMESTAMP`）划分。这为多任务学习和预训练打开了机会，可以同时改进同一关系数据库上的不同预测任务。我们还公开了把数据库转换成图的逻辑。这使得未来的工作可以考虑修改后的图构造，或对原始数据做有创造性的使用。

**Open-source RDL Implementation / 开源的 RDL 实现。** 除数据集和任务外，我们提供关系深度学习的第一个开源实现。高层概览见 Fey et al. (2024) 的图 2。在一张精确表示该数据库的异质时序图上学习一个神经网络，以便对节点做预测（用于实体分类和回归）以及对链接做预测（用于推荐）。我们的实现基于 PyTorch Frame（Hu et al., 2024）从原始表特征中抽出初始节点嵌入，并基于 PyTorch Geometric（Fey and Lenssen, 2019）做 GNN 建模。进一步细节见第 3 节。

本文其余部分组织如下。第 4 节描述 RELBENCH 的关系数据库。第 5 节介绍每个 RELBENCH 数据库的预测任务，三种任务类型分别在第 5.1、5.2 和 5.3 节。第 5 节还把我们的 RDL 实现与有挑战性的基线做了广泛比较。最重要的是，我们与一个强的“数据科学家”基线比较（第 6 节），发现端到端 RDL 模型优于手工特征工程这一当前金标准。最后，第 7 节讨论相关工作，第 8 节给出结论。
