# RelAgent: LLM Agents as Data Scientists for Relational Learning

## Abstract / 摘要

关系学习是一个困难问题，已经催生了多种做法，包括基于图的模型（例如图神经网络、图 Transformer）、表格方法（例如表格基础模型）以及基于序列的方法（例如大语言模型）。它们各有优点，也各有局限。我们提出 RELAGENT，一个基于大语言模型（large language model, LLM）的自主数据科学家，用于关系学习，并分两个阶段工作。在搜索阶段，LLM 智能体使用数据库、验证和评估工作区这三类工具，构造 SQL 特征程序并选择预测模型。在推断阶段，得到的程序被执行，不再调用 LLM。最终预测器由 SQL 查询和一个经典模型组成，因而预测快速、确定，并且内在可解释：特征是人可读的查询，预测只依赖于由此得到的、由查询定义的特征映射，从而可以用标准数据库系统做可扩展的部署。

## 1 Introduction / 引言

关系数据库是存储、管理和处理结构化数据的标准范式 [1]。在实践中，这类数据上的预测建模由特征构造驱动：分析人员编写 SQL 查询，沿外键路径连接表，在时间窗口上聚合信号，并构造计数、新近性统计或活动趋势等特征，供下游模型使用 [2–4]。可能的特征空间很大，要找出有用的组合，往往需要在连接、过滤和聚合上反复试错。这一过程耗时，需要大量领域知识，并且随着数据库模式变复杂而越来越难扩展。

关系数据库上的机器学习通常称为关系学习，其目标是把上述过程自动化。现有方法用不同的表示、访问模式和计算机制来应对这一挑战（见表 1）。表格方法，包括有监督的表格模型 [5–7] 和表格基础模型 [8, 9]，在扁平的特征矩阵上工作，可以非常有效；但要把它们用到关系数据库上，要么需要大量特征工程，要么使用通用聚合，而通用聚合可能捕捉不到与任务相关的关系交互。基于图的模型，如图神经网络 [10–12]、图 Transformer [12] 和关系基础模型 [13–16]，通常在由数据库导出的图上、通过以实体为中心的子图来工作。这些方法虽然强，但访问关系结构的机制是固定的：有效上下文，例如邻域大小和聚合深度，事先选定，不一定与下游任务对齐。基于序列的方法，例如把序列化的表或图交给大语言模型（LLMs）[17, 18]，提供了灵活的推理接口，但其归纳偏置并不自然地适合结构化的关系预测。这些局限指向一个互补方向：把关系结构保持在外部并且可执行，同时自动搜索与任务相关的查询。

**表 1：关系学习方法的比较。**

| 方法 | 表示 | 访问 | 机制 | 归纳偏置 | 可解释性 |
| --- | --- | --- | --- | --- | --- |
| Tabular | 表 | 内化（展平） | 树 / 注意力 | 行置换等变（row perm.-equiv.） | 特征级 |
| GNNs | 图 | 内化（局部） | 消息传递 | 置换等变（perm.-equiv.） | 事后 |
| Graph Transf. | 图（含 PE） | 内化（全局） | 注意力 | 置换等变 | 事后 |
| LLMs | 序列 | 内化（文本） | 注意力 | 顺序敏感 | 事后 |
| RELAGENT | 数据库 | 外部（查询） | SQL + 预测器 | 由查询定义 | 内在 |

**图 1：RELAGENT。** 在搜索阶段，LLM 智能体迭代地提出并改进一个特征程序（feature program），它由 SQL 特征查询 \(\{q_1, \ldots, q_n\}\) 和预测模型配置 \(\phi\) 组成，用来解决给定任务。智能体使用三种工具：（1）数据库探索，通过只读 SQL 探索查询进行；（2）程序验证，在验证集上执行候选程序并接收性能指标；（3）通过评估查询，在评估工作区（Evaluation Workspace）中检查过去的试验。一旦选定最终程序，推断时就不再需要该智能体。

**Our approach / 我们的方法。** 我们提出 RELAGENT。该框架把关系学习表述为在基于查询的特征和预测模型上的智能体搜索过程。如图 1 所示，RELAGENT 分两个阶段运行：

（1）搜索阶段：LLM 智能体通过三种查询接口与系统交互：（i）探索查询，用于查看数据库；（ii）特征查询，用于构造预测特征；（iii）评估查询，用于分析存放在评估工作区中的预测与诊断。智能体迭代地提出特征程序，选择下游预测模型（例如 XGBoost [5]、LightGBM [6]），并根据上述反馈改进程序和模型选择。

（2）推断阶段：选定的特征程序在目标实体上执行，得到的特征被送入由训练样本拟合的预测器。

更广义地说，RELAGENT 在由查询导出的特征映射上定义预测器，其假设类由可执行查询参数化，而不是由固定架构参数化。最终预测器只包含一个 SQL 特征程序和一个预测模型，因而预测快速、确定，并且内在可解释：每条预测都可以追溯到所选查询、它们物化后的特征值，以及下游模型对特征的使用方式。这也给出关系归纳偏置的另一种看法：两个目标样本若在所选 SQL 特征上的输出相同，就会得到相同的预测，因此不变性来自所选查询，而不是来自固定的图编码、序列顺序或神经网络架构。

**Contributions / 贡献。** 主要贡献如下：

- 我们提出 RELAGENT，一个智能体框架。它把关系学习表述为：由 LLM 通过工具与关系数据库交互，在基于查询的特征和预测模型上自主搜索。
- 我们提出一个以执行为依据的学习循环，带有验证反馈和评估工作区，从而可以通过对先前试验的结构化分析进行迭代改进。
- 我们把搜索与推断分开，使最终预测器在推断时不需要 LLM，并且快速、确定、可解释。
- 我们把关系学习表述为定义在由查询所定义的特征映射上的学习，其不变性由可执行查询诱导，而不是由固定的架构偏置诱导。
- 我们在关系基准上实证评估 RELAGENT，表明它在保持可解释性和可扩展性的同时，性能与强基线相当。

## 2 Related work / 相关工作

**Relational deep learning / 关系深度学习。** 关系数据库上的预测建模传统上依靠手工把与任务相关的特征表物化出来：做连接和聚合，再接上有监督的表格模型，如 XGBoost [5]、LightGBM [6] 或 AutoGluon [7]。这一工作流需要大量工程，并且不能在不同模式或不同目标之间迁移。关系深度学习（Relational Deep Learning, RDL）避免手工展平，而是把数据库当作时序异质图（行是节点，主键–外键链接是边，训练表是目标）[2]，并在此之上建立基于 GNN 和 Graph Transformer 的模型，如 RelGNN [19] 和 RelGT [12]。更近的关系基础模型，包括 Griffin [14]、Relational Transformers [13]、KumoRFM-v1 [15] 和 KumoRFM-v2 [16]，旨在跨模式、跨数据库、跨任务获得更强的迁移。另一条线索直接使用表格或语言基础模型，例子包括 GNN+TabPFN-2.5 [20]、RDBLearn [9]，以及把关系数据库序列化成上下文的基于 LLM 的预测器 [13, 17, 21]。RDL 也与构建图和知识图谱基础模型的更广泛努力相关 [22–26]，但它专门针对带有模式和时间预测目标的关系数据库。

**LLMs for structured data / 用于结构化数据的 LLM。** 可以把表和模式序列化成文本，从而把 LLM 用于结构化数据，以完成表格预测 [27] 和 text-to-SQL [28] 等任务。行级序列化可以支持少样本表格学习，但性能仍然对提示设计和表示选择敏感 [29, 30]。类似地，图结构数据也可以编码成文本，不过这类方法往往对格式和邻域选择很脆弱 [18]。后来的方法加入了结构感知的适配，包括图提示和指令微调 [31–33]，或通过图词元化注入结构 [34, 35]。更近一些，工具使用使 LLM 能够通过显式操作而不是纯粹的提示来与结构化数据交互。ReAct [36] 把推理与工具调用交错进行，Toolformer [37] 学习使用 API，Plan-and-Execute [38] 和 Reflexion [39] 等扩展加入了规划与自我修正。面向图的变体进一步通过工具调用 [40] 或可执行程序 [41] 来做结构化推理。与那些把表或图邻域序列化进 LLM 上下文、从而把关系结构内化的做法不同，RELAGENT 把数据库留在外部，并通过 SQL 访问它。

**LLMs as feature engineers / 把 LLM 用作特征工程师。** 除了把 LLM 直接当作预测器，近来的工作把它们当作特征工程师，为下游模型生成与任务相关的变换。早期方法主要关注单表设定：CAAFE [42] 和 FeatLLM [43] 表明，LLM 可以为表格数据合成有语义的特征或基于规则的变换，提高少样本性能，同时避免在推断时使用 LLM。更新的系统把特征工程表述为迭代搜索：LLM-FE [44] 把特征构造表述为由验证反馈引导的程序搜索，OCTree [45] 进一步纳入决策树推理，以迭代地改进单条规则。对于多关系型数据库，ReFuGe [46] 通过一条固定的顺序流水线扩展了基于 LLM 的特征生成，并带有聚合的验证反馈和固定的下游模型。RELAGENT 则暴露三种查询接口：针对数据库的探索查询、用作可执行程序的特征查询，以及针对一个持久工作区的评估查询，该工作区保存行级预测和试验历史。这使得有针对性的自我修正成为可能，也可以在 SQL 特征与下游模型上联合搜索，同时让部署后的预测器保持内在可解释。
